## 為什麼 line62 作廢 —— 這是本次最重要的一筆

協調者把原 ADR 的過度宣稱「收窄」成「這在讀取側成立,在寫入側不成立」。
**收窄後的版本仍然是假的**:有三個型別(`RID`/`Callable`/`Signal`)**兩側都不擋**。

- `security-engineer` 抓到
- `godot-specialist` **背書了這個錯誤框架**,說「逐句核對全部成立」
- 而否證它的證據,就在 `godot-specialist` **自己寫的**
  `docs/engine-reference/godot/modules/core-serialization.md` 第 4 節

**這是「收窄宣稱到實測範圍、收窄後仍被否證」的第二次。**
也是平行雙軌覆核的直接價值:單靠引擎專家一軌,錯誤會原樣進入待核准的文件。

正確框架是二維的:

| 型別 | 寫入側 | 讀取側 |
|---|---|---|
| `Object`(24,含所有 Resource/RefCounted/Node) | ❌ 靜默編碼,資料消失 | ✅ 整包失敗 |
| `RID`(23)/`Callable`(25)/`Signal`(26) | ❌ 不擋 | ❌ **也不擋** |
