## 二、登記表提案(`docs/registry/architecture.yaml`,現 81 項)

⚠️ **提案而已。** 依 `/architecture-decision` 流程,登記是寫入 ADR **之後**的步驟 6。
且本專案有明文要求:**登記表是權威來源,散文不得複述** —— 所以下表只列「要登記什麼」,
完整 `why:` 欄要在登記時寫足,不在此處寫半套。

| 類型 | 建議名稱 | 內容要旨 |
|---|---|---|
| api | `save_type_gate_reject_set` | 拒絕集合恰為 {23 `RID`, 24 `Object`, 25 `Callable`, 26 `Signal`};白名單制(判準恆為允許集合 `.has()`,**絕不寫成拒絕集合的 or 鏈** —— 後者是黑名單,新型別會預設通過) |
| api | `save_type_gate_shared_both_sides` | 寫入側與讀取側**共用同一份實作**;寫入側失敗**不併入** `ReadRejection`(語意不同,另立 `GateRejection`) |
| api | `hash_input_fixed_order_array` | 雜湊輸入一律正規化為固定順序 `Array` tuple,**不得**直接對 `Dictionary` 呼叫 `var_to_bytes()`(鍵插入順序會改變輸出 → 健康存檔被判損毀) |
| api | `manifest_entry_fields_single_source` | 形狀檢查與雜湊正規化**共用同一份** `MANIFEST_ENTRY_FIELDS`;誠實劃界:欄位存在性自動同步,**逐欄位型別檢查分支仍手動** |
| forbidden | `depth_check_not_first_statement` | `SaveTypeGate._walk()` 的深度檢查必須是函式內**第一個可執行敘述**。移到型別判斷或遞迴之後,會讓 `GateResult`(帶欄位物件而非 bool)的空值展開從「安全」變成「呼叫端在 `null` 上取屬性而中止」 |
| forbidden | `hash_compare_without_length_check` | 雜湊比對必須先驗長度再比內容 —— 兩邊都失敗時空陣列 `==` 會**假通過** |
| forbidden | `null_check_instead_of_is_dictionary` | 解碼結果判定不得用 `!= null`。全零 16 bytes 是合法 NIL 編碼,回傳 `null` 且零錯誤訊息,`!= null` 會把損毀誤判為成功 |
| forbidden | `fileaccess_store_var_on_save_path` | 存檔讀寫路徑禁用 `FileAccess.store_var()`/`get_var()`(它們**真的**接受第二個布林參數,是一條外觀完全正常的等效繞道)。位元組一律走 `store_buffer()`/`get_buffer()` |

**就地修訂**(非新增):`api save_serialization_format` 的**刻意分歧標記可以撤除** ——
該標記寫著「ADR-0003 全文 18 處仍為舊形狀,禁止把本條目對齊回 ADR」。本次修訂完成後
ADR 已改正,分歧消失,標記必須撤掉,否則它會變成另一個停在舊狀態的欄位。

⚠️ **這一條特別容易漏,因為它是「把警告拿掉」而不是「加東西」。**

## 四、四個無人擁有的跨文件缺口 —— 複驗者判定其中兩個是同一件事

| 缺口 | 範圍 | 性質 |
|---|---|---|
| **組裝層(`SaveWriter`)無人認領** | **全部**寫入路徑:逐一呼叫 `serialize_block()`、算雙層雜湊、組 `block_manifest`、呼叫 `serialize_manifest()` | **完整性** —— 沒有任何文件說一份存檔是怎麼組出來的 |
| 遷移回寫的無名序列化步驟 | **一條**路徑:ADR-0004 機制七 Phase B 的 `Dictionary` → `write_temp()` 要的 `PackedByteArray` | **安全** —— 決定遷移函數注入的危險型別會不會落到磁碟 |

**複驗者裁定:後者是前者在遷移路徑上的實例,不是第四個缺口。**

- 若組裝層被認領並定案、**且明文要求遷移回寫也必須走它** → 安全缺口**作為結果自動關閉**
- **反過來不成立**:只補遷移路徑,一般寫入路徑的組裝層仍然無人擁有

⚠️ **實務結論:不要分兩筆修。** 當**一個**裁決處理 ——「誰擁有組裝層」—— 並在裁決裡
明文要求兩條路徑(一般寫入、遷移回寫)都走同一個入口。同時得到安全性與完整性,
而且**只有一個擁有者,不會產生新的銜接縫**。

**另兩個仍獨立**:
- ADR-0004 路徑四承諾「不反序列化 payload 就做型別檢查」→ **新設計下結構性做不到**
- ADR-0004 第 328 行殘留舊詞「型別白名單**解碼**」→ 會讓實作者以為解碼完就等於檢查完,**於是跳過步驟 5b**

## 五、複驗新增的一項殘留(不阻擋,屬 devops 而非本 ADR)

`self_check()` 這道斷言的價值取決於 **CI 跑的引擎版本等於出貨建置的引擎版本**。
**找不到任何地方釘住 CI runner 的 Godot 版本** —— `VERSION.md` 釘的是**文件**版本,
不是 CI 執行檔。若日後升級引擎而 CI 仍跑舊版,`TYPE_MAX` 由 39 變 40 這件事會
**CI 通過、出貨建置漏接**。依核准門檻第四節第 2 項不阻擋。
