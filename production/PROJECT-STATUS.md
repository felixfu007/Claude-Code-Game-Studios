## 🔴 要注意的一件事:兩個「檢查」都通過了,而它們都比看起來的鬆

今天兩條互不相干的工作線,**在同一天撞上同一個形狀**:

**第一個** —— 那張大工作單事先分析過「有 89 個地方會受影響」。**那個數字算的是另一種東西。**
真正會被新保護機制擋下的地方不在那 89 個裡面。發現的方式是跑測試 ——
但它**不是**跳出一堆紅字,而是**測試總數從 1014 掉到 984**。
因為一條測試壞掉會讓它同一組後面的測試全部不執行,**30 條就這樣沒跑,而畫面上看起來只有幾條紅的**。
**只有把數字拿來相減的人看得見。**

**第二個** —— 翻譯那張工作單的驗收方式,是跑一道指令確認「沒有漏網的文字」。
專家照做,結果確實是乾淨的。**但那道指令只看得見某一種寫法的文字**,
看不見直接寫在程式中間的 —— 而那裡還有 **10 句玩家看得到的中文**。
我用更寬的條件重掃才發現,你當場裁決補完。

**共同點**:兩次都是「檢查通過了,但它在回答的不是我們以為的那個問題」。
兩次都不是靠規則擋下來的,是靠有人去算、去重掃。

## 關於你給我的那個倉庫

**結論:它是對的東西,但它只是一半。**

那個服務只做「把一句描述變成一張圖」,而且刻意不碰網路、不負責收工單也不負責送圖回來 ——
這正好符合我們的架構(你主管不希望公司筆電連家裡的機器)。

**缺的那一半是:誰去拿工單、誰把圖送回來。它原本一行程式碼都沒有。**
我今天補上了,已經推上去。現在的流程是:我在公司寫一張工單推上 GitHub → 家裡那台定時去拿 →
跑完把圖推回來 → 我拉下來。**兩邊都只跟 GitHub 說話,誰都不用連誰。**

🔴 **三件你該知道的事:**

1. **那個服務的程式碼是 GitHub 的 AI 代理人寫的**(我從提交紀錄查到的)。
   好消息是沒有不明的外部廠商、只依賴一個套件;**壞消息是那 1700 多行沒有任何人類讀過,
   包括寫它的那一方。**
2. **我寫的兩支工具,可信度差很多。** 公司端那支我**真的跑過**(測了引號、換行、中文會不會
   讓資料格式壞掉,以及五種打錯參數的情況)。家裡那支**一行都沒執行過,連語法檢查都沒有**
   —— 因為這台公司筆電沒有可用的 Python。這個差別我寫在倉庫裡了,免得日後有人誤以為都驗過。
3. **整條路還是沒有跑通過一次。** 家裡那台還沒裝 ComfyUI,所以這一切目前都只是設計。
   **第一次真的跑通,仍然只有你本人做得到。**
