## 怎麼玩

| 動作 | 鍵盤 | 手把 | 滑鼠 |
|---|---|---|---|
| 移動游標 | 方向鍵 | 十字鍵 / 左蘿蔔 | 移動滑鼠 |
| 確認（選人 / 走 / 打） | Enter 或空白鍵 | **A 鍵**（PS 是 ✕） | 左鍵 |
| 結束我方回合 | Esc | **B 鍵**（PS 是 ○） | — |

點一個角色 → 他能走的格子會亮起來 → 點一個亮格他就走過去 → 敵人在射程內會亮成另一種顏色 → 點下去就打。

## 🔴 這次最重要的三件事

### 一、我抓到一個會讓手把玩家卡死的缺口

專家在註解裡順口提了一句「結束回合那個鍵沒有手把綁定」。

**我沒有採信也沒有否定，我自己寫程式去問引擎。** 結果證實了，而且比他說的更嚴重——
**確認鍵也沒有手把綁定**，而現在能用的那個是綁在 **Y 鍵**上的，那不是任何人預期的確認鍵。

**後果有多實際**：拿手把的玩家選完人、走完路、打完架之後，**沒有任何辦法把回合交給敵方，
就卡在自己的回合裡出不去。** 而主機根本沒有 Esc 鍵——那條路上這個問題無解。

已修好，重新定義了兩個遊戲專用按鍵，兩種裝置都能按。**我逐鍵複驗過設定檔沒有被改壞**
（那個檔案曾經被自動程序悄悄刪掉過一行畫面設定）。

### 二、專家沒照我的指示做，而他是對的——我寫錯了

我在派工單裡明文要求座標換算「**必須**」用某個特定方法。他沒照做，並附上實測數字推翻我：
**引擎在把滑鼠位置交給程式之前，早就已經套用過縮放了**，照我說的做會套第二次。

🔴 **而且這個錯誤在原生視窗下完全看不出來，只有玩家把視窗放大才會壞。**

**我要記下的教訓是對我自己的**：派工單寫得愈具體，愈可能把錯的具體要求傳下去。
我那條要求的來源是上一次的試驗結論，但那個結論適用的是**另一條路徑**。
**把「參考資料上這樣寫」當成「已經實測過」，就是這樣傳下去的。**

### 三、前四張截圖全是滑鼠操作的——按鍵那條路沒人證明過

專家交了四張截圖，內容都對（我還把移動範圍的每一格都驗算過一遍，數學正確）。

**但我發現四張裡的選取與移動全部是用滑鼠做的。「按確認鍵」這條路，一張圖都沒有。**

我自己寫程式補拍了三張：

- **用方向鍵**把游標移到另一個角色身上 → **按確認鍵** → 他被選中了
  （我特意挑了一個移動力不同的角色，**高亮形狀必然不一樣**，所以不可能是舊畫面蒙混）
- **按結束回合鍵一次** → 敵方五個人自己動了起來、回合數變成 2、控制權交還給我

## 🟢 順帶回答了一個懸了兩次的問題：狙擊手不是太脆

之前自動對打時，狙擊手在第 1 回合就被兩隻遠程敵人集火打死。我當時登記過一句話：
**「這不算他太脆的證據，那個笨 AI 把他推到開闊地了，真人不會這樣走。」**

**這次第一次證明了那句話是對的。** 我自己操作，**一個人都不動**，敵方推進一整回合——
**沒有任何人受到一點傷害。**

**所以：不要因為自動對打的數字去調他的血量或防禦。** 那次陣亡是站錯位置，不是數值有問題。

   **請留意這件事有多煩** —— 它決定這是「佔位美術的小瑕疵」還是「必須先解決的阻礙」。

## 這次要跟你講的一件事

**四種驗法，三種抓到東西，而且抓到的完全不重疊。**

- 自己**重跑測試** → 數字對上，沒有新發現
- 自己**啟動遊戲** → 沒有新發現（但這是「能不能玩」唯一的直接答案）
- 自己**讀程式碼** → 找到手把缺口的線索
- 自己**另外做實測** → 證實缺口比專家說的更嚴重、補拍三張沒人拍的證據、
  並證明了狙擊手的陣亡是站位問題

**最後那一種最花時間，也最容易被省略。這次它一個人抓到的，比前三種加起來還多。**

順帶一提，這次也第一次出現**專家不照我的指示做，而他是對的**。我把那件事記進了教訓，
對象是我自己不是他。
