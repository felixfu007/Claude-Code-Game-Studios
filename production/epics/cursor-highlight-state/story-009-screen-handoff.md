## Implementation Notes

*出自 ADR-0005 機制十一:*

| 分支 | 情境 | 入口 |
|---|---|---|
| **甲** | 舊表面卸載前交接 | `handoff_before_unload()` |
| **乙** | 新表面掛載後設定 | `handoff_after_mount(target)`(走 `_write_target_internal(target, UNCONDITIONAL)`) |
| **丙** | 暫停/取消後返回 | 由呼叫方主動重新設定 |

1. 🔴 **乙分支必須有專屬入口,不能重用 `set_target()`** —— 後者走「目標確實改變才 `TARGET_CHANGED`」,**乙分支目標恰等於當下目標時會靜默不重置**。
2. **甲/乙兩分支皆須把滑鼠奪權累積位移量重置為 0**、起點更新為當下滑鼠座標 —— 這是第五個 `ResetTrigger` 值 `SURFACE_HANDOFF`,呈現層待遇同觸發點 (a)(b)(c)(收斂,非瞬間歸零)。
3. 🔴 **丙分支不是無條件「重新計算」**:AC-63b 原文為「若原目標在取消後仍然有效,**得直接以原目標值重新設定,不需要重新計算**;僅當原目標已失效時才依 Core Rules #6 計算」。
   **ADR 曾把它寫成無條件重算 —— 那是對 GDD 義務的收窄,已更正。有效性判定歸呼叫方**(本系統不理解遊戲實體語意)。
4. **丙分支也不是「還原暫停前的目標」** —— 呼叫方必須**主動**重新設定,不得讓游標停留在「待重新解析」狀態返回一個可互動的畫面。
