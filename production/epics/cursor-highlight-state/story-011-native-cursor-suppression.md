## Implementation Notes

*出自 ADR-0005 機制十三、機制十三之二:*

1. **原生游標二元隱藏,連續 alpha 由自繪載體承擔。** 引擎的原生指標是否支援連續 alpha 動畫**未查證**,但**本設計刻意不依賴這個答案** —— 自繪載體是上位方案,答案是什麼都成立。
2. 🔴 **呈現層平滑器只對下降方向限速,上升方向立即同步。**
   **理由是純數學**:`reclaim_visual_convergence_max_frames` 的實際下限為 2(配置為 1 即等於單影格瞬間歸零,自我矛盾)→ `max_step ≤ 0.5` → 常見滑鼠速度下 2–3 影格即跨過門檻 → 若上升也限速,`_presented_alpha` **結構上不可能**在跨門檻當下達到 1.0,**必然違反 GDD「達到門檻的當下透明度達 100%」**。
3. **兩個值的模型,不要混為一談**:`reclaim_progress()` 本身**必須立即**反映全部四個重置觸發點;**呈現層透明度**對觸發點 (a)(b)(c) **不得**單影格瞬間歸零,須於 `reclaim_visual_convergence_max_frames` 內收斂。**只有觸發點 (d) 瞬間歸零。**
4. **機制十三之二:未登記表面 hover 時暫時恢復原生指標** —— 判定採白名單(見 Story 003)。
   ⚠️ **`gui_get_hovered_control()` 對 `MOUSE_FILTER_IGNORE` 的行為未實測**,但白名單反轉後失敗方向已翻轉至安全側:後果僅是該表面的 AC-60 便利性失效,不會錯誤顯示指標。

## 🔴 隨 Story 010 結案而落到本張的一條硬性義務(2026-09-04 管理者裁決)

**本張必須包含一次真的開著視窗、用眼睛看畫面的檢查。不得只有 headless 自動測試。**

**裁決背景**:ADR-0005 Validation Criteria #20 的敘述寫的是「有視窗的整合測試」,
而 Story 010 實際交付的是 headless 自動測試。管理者於 2026-09-04 裁決**接受**該做法,
理由是 headless 每次推送都會自動跑、有視窗的版本要人工執行因而會逐漸沒人跑;
且該張的探針實測 headless 量到的數字與 2026-09-01 真實 GPU spike 完全一致
(`prototypes/story-010-headless-resolution-probe-2026-09-04/`)。

🔴 **但那是接受一個帶條件的做法,不是取消要求。** headless 抓不到的那一類問題是
**「要真的畫出來才看得見」** —— Story 010 不畫任何東西,所以在那張沒有損失;
**本張是開始畫東西的第一張,損失從這裡開始計算。**

⚠️ **本張 Story Type 已經是 Visual/Feel,依 `coding-standards.md` 本來就要求
截圖 + 主管簽核。** 本節不是新增一種證據,是明文指出:**那份截圖必須來自真的開著視窗的
執行,而且必須有人打開圖檔確認它畫的是它宣稱的東西。**

📌 **截圖證據的四項機械檢查與那條「人要打開圖看」的規則,見 `.claude/docs/coding-standards.md`
的 Screenshot Evidence Rules。** 該節是 2026-08-31 一張 Godot 開機畫面被當成實際遊戲畫面
寫進證據目錄之後訂的 —— **那張圖的相異色彩數比真實遊戲畫面還多**,所以「顏色夠多所以不是空白」
這種檢查方向是錯的。**寫截圖工具前先讀該節。**

**紀錄位置**:本裁決記於 `production/session-state/active.md` 的 2026-09-04 批次,
以及 `production/qa/evidence/cursor-canvas-layer-evidence.md` 的「兩項判斷與管理者裁決」節。
**本節是義務的執行點,那兩處是紀錄** —— 義務寫在已結案的 Story 010 裡等於沒寫,
本專案有明確前例(技術債登記表建立的起因就是這個)。
