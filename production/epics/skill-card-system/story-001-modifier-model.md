# Story 001:甲類修正的資料模型與有效值計算

> **Epic**:技能卡牌系統 —— 邏輯層
> **型別**:Logic(**BLOCKING** 級測試證據)
> **狀態**:📋 Ready
> **估時**:M
> **依賴**:無

## 目標

讓一個單位身上可以掛著多個「暫時性戰鬥數值修正」,並讓既有的
`Unit.effective_atk()` / `effective_def()` 回傳把它們算進去之後的值。

🔴 **這條接縫已經存在且已在跑** —— `src/gameplay/units/unit.gd` 的兩個方法目前
`return atk` / `return def`,而 `BattleState._compute_attack_damage()`(結算與預覽**共用**
的唯一入口)已經在呼叫它們。**本 story 是把那兩個方法填上內容,不是新增接縫。**

## 規則(來源:GDD `## Formulas` 公式一 + Edge Cases)

```
ATK_eff(u) = max(0, ATK_base(u) + clamp(Σⱼ Δatkⱼ, −4, +6))
DEF_eff(u) = max(0, DEF_base(u) + clamp(Σⱼ Δdefⱼ, −3, +4))
```

| 規則 | 值 / 要求 |
|---|---|
| 疊加方式 | **逐條加總**,不取最大、不互斥、不覆寫 |
| 累計夾限 | `ΣΔatk ∈ [−4, +6]`、`ΣΔdef ∈ [−3, +4]`(來源:`design/quick-specs/unit-stats-provisional.md` 7-4) |
| 有效值下限 | `max(0, …)` |
| 單卡 `\|Δ\|` | 1 ~ 3。**逐卡定義,本 story 不寫死任何卡** |
| 合法作用對象 | **僅我方單位**(GDD 公式一:敵人不是那 5 名具名角色) |

🔴 **`max(0, …)` 是硬性要求,不是保守寫法。** 戰棋公式一宣告 `ATK`/`DEF` 型別為 `int, ≥0`;
若允許 `DEF` 為負,`ATK − DEF` 會**大於** `ATK` —— 一張減益牌造成的傷害會超過「把防禦完全歸零」。
**那是公式定義域外的行為,而公式本身不會報錯。**

🔴 **不得改用「打牌時就地 `+=`、到期時 `-=`」。** 那會摧毀基準/有效分離,
且未來若出現任何永久成長來源,到期時減去修正量會算錯。**基準欄位 `atk`/`def` 全程不變。**

## 逐條可讀的查詢(GDD OQ-12,2026-09-09 管理者裁決)

**必須提供一個回傳「生效中修正逐條清單」的查詢**,每條含:**來源、帶號量值、剩餘回合數**。
判準比照上游對 `Φ` 的硬性約束:**正負與量值須單獨可讀。**

🔴 **只給加總值在結構上就做不到逐條列出** —— 而逐條列出是介面規格
`design/ux/skill-card-play.md` 的 Z5 明細與 AC-U6 的前提。**本 story 不做這個查詢,那份規格就做不出來。**

⚠️ **清單是唯讀的。** 回傳值不得讓呼叫端改到內部狀態(GDScript 的 `Array` 是參照型別)。

## 建議實作形狀(接縫是硬性的,類別切分可由實作者調整)

| 硬性 | 建議 |
|---|---|
| ✅ `Unit.effective_atk()` / `effective_def()` 維持現有簽章、成為唯一讀取路徑 | `CardModifier`(`RefCounted`):`source_name` / `atk_delta` / `def_delta` / `remaining_turns` |
| ✅ 夾限與 `max(0,…)` 的算術只有**一份**實作 | 純函式放 `CardModifierRules`(靜態,無狀態),`Unit` 只持有清單並委派 |
| ✅ 修正隨宿主單位消失(不轉移、不延續) | 清單掛在 `Unit` 上即自動成立 |

⚠️ **`src/gameplay/units/unit.gd` 檔頭自述是「Pure data holder — no combat math lives here」。**
把夾限算術寫進 `Unit` 會讓那句話變成假的。**要嘛math 外移,要嘛同批更正該檔頭** —— 不得留著矛盾。

## 驗收條件

| # | GIVEN / WHEN / THEN |
|---|---|
| **AC-1** | 單位身上有兩個甲類修正 `+2`、`+3` → 查 `effective_atk()` → 等於基準 `+5`(**逐條加總,不取最大**) |
| **AC-2** | 攻擊方 `ATK_base=6` 無修正;防禦方 `DEF_base=3` 受 `−5` 減益;**`Φ` 固定為 0** → `effective_def() == 0` **且本次傷害恰為 6,不多不少** |

**AC-2 的 `Φ=0` 與攻擊方 ATK 必須在測試裡鎖死**(以測試替身或無關係線的單位隔離)——
GDD 明文:原版未鎖定時「不同人會寫出彼此不一致的測試,且若選到 `Φ≠0` 連正常情況都可能矛盾」。

## 補測(GDD 登記為零 AC 覆蓋、實作期必補)

- **甲類修正隨宿主單位陣亡消失** —— 單位 `hp=0` 後,不得有任何路徑仍讀得到它的修正
- **累計夾限真的會夾**:掛四張 `+3`(Σ=+12)→ `effective_atk()` 只加 `+6`;
  掛三張 `−3`(Σ=−9)→ 只減 `−4`
- **基準欄位不變**:上述任一情境後 `unit.atk` / `unit.def` 與初始值逐字相同
