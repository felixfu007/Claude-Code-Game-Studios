## 為什麼

回合換手是戰棋最重要的狀態轉換之一,現在只靠左上一行字與手牌變灰,不夠醒目。

## 派工前須先決定(2026-11-17 已全部決定;實作者不得自行改)

顏色須取自色票 `design/art/color-palette.csv` 既有色(art-director 已指定,見下「配色」;實作者不自創)。
🔴 **兩組橫幅**:敵方回合一組、我方回合一組(管理者 2026-11-17 裁決兩者一起做),兩組須彼此可分,且不單靠顏色(橫幅文字本身已區分)。
橫幅**不得蓋到棋盤任何一格**(畫面架構硬性約束:介面疊在棋盤上方;1080p/4K 世界層無邊區,但棋盤在世界層內縮進,上緣有空帶可用)。
位置/時長/文字/動態偏好由 UX 決定(`docs/reviews/story-049-enemy-phase-banner-ux-2026-11-17.md`):

- **位置**:棋盤上緣空帶、水平置中、與回合標題同一列;矩形取自 `HudLayout.phase_banner_rect(window_size)`(單一出處,敵我共用;高 = `font_size × LABEL_HEIGHT_MULTIPLIER`,寬 = `font_size × 8`,N 一律經 `font_size`/`compute_scale`,不自算)。
- **時長**:淡入 0.15s、停 0.9s、淡出 0.25s(具名常數);只做透明度變化,不位移、不縮放;淡化以純函式 `banner_alpha(elapsed)` 表達,日後「減少動態」設定可將淡化秒數歸零。
- **文字**:重用 `battle.hud.faction_enemy`(「敵方行動」)與 `battle.hud.faction_player`(「我方行動」),不新增字串列。
- **不做**「減少動態」設定(專案目前沒有;另案)。
- 橫幅 `mouse_filter = IGNORE`,不吞輸入、不延後任何敵方步驟。

### 配色(art-director 2026-11-17,全文與手算對比度見美術檔;**所有色值皆為色票既有列**)

美術檔位置說明:第 1~2 節敵方、第 7 節我方;**其第 4、5 節關於「1080p/4K 沒有棋盤外可放橫幅」的敘述,已被 UX 決定取代**(棋盤在世界層內縮進,上緣有空帶),位置以本單上段為準。

| 項目 | 敵方回合 | 我方回合 |
|---|---|---|
| 標題色(StatusLabel) | `ui_state_negative_01` `#FF5252` | `ui_text_primary_01` `#FFFFFF`(明確設為具名常數,不再靠引擎預設) |
| 橫幅底色 | `cloth_warm_shadow_01` `#5C1F22`,α 0.78 | `cloth_cool_base_01` `#3A6B9C`,α 0.78 |
| 橫幅文字色 | `#FFFFFF` | `#FFFFFF` |
| 上下線 | `#FF5252`,各一條,粗 = N 螢幕像素(`compute_scale()`) | `#FFFFFF`,各一條,粗 = N 螢幕像素 |
| 字型/字級 | `HUD_FONT`;`HudLayout.font_size()`(不新發明字級) | 同左 |

- 動畫僅透明度(α 乘數);文字描邊預設不加。
- 標題在地形上的可讀性:美術偏好標題加 `#0E0F14` 描邊(同 `PIECE_LABEL_OUTLINE_COLOR` 慣例),實作者擇一(描邊或同底襯)並於回報說明。
- 我方橫幅最壞情況白字對比僅約 4.61:1(手算,未實測):AC6 開圖後若讀不清,備案①文字加 `#0E0F14` 描邊 ②底色 α 升至 0.85(須重算);預設先不改。
- 退路(若覺得敵方暗紅底太搶):`#0E0F14` α0.72 + 同樣上下線。

## Acceptance Criteria

- [ ] **AC1 標題色**:進入 `Phase.ENEMY_ACTING` 時回合標題色改為規格色 `#FF5252`,回到 `PLAYER_INPUT` 還原為具名常數 `#FFFFFF`。測試:真實 `BattleScreen`(注入合成資料)驅動兩次階段切換,斷言標題節點顏色常數兩態不同且等於規格常數。
- [ ] **AC2 敵方回合橫幅**:進入 `Phase.ENEMY_ACTING` 時顯示「敵方行動」橫幅;**時間到(約 1.3s)或離開 `ENEMY_ACTING`(含 `FINISHED`)即消失**,離開階段的同一幀「應顯示」旗標為假(不淡出殘留)。
      橫幅矩形取自 `HudLayout.phase_banner_rect`,**與整個棋盤矩形(13×6 格,逐格取 `HudLayout.cell_window_rect` 的聯集)不相交**
      (此判準涵蓋所有敵兵位置與敵兵移動中的所有時間點;至少於 960×540、1920×1080,建議另加 2560×1440、3440×1440)。
      同時斷言橫幅 `mouse_filter = IGNORE`,且不延後第一個敵方步驟。
      敵方回合中輸入本就被凍結,故敵方橫幅不實作輸入關閉。
      防空洞:斷言橫幅確實出現過(「應顯示」旗標在切換後某幀為真)。
      另斷言:橫幅可見的每一幀 `InfoLabel.text == ""`,或其文字矩形不與橫幅相交;不成立則**停下回報,不得自行改位置**。
- [ ] **AC2b 我方回合橫幅**(管理者 2026-11-17 裁決一起做):**僅在 `ENEMY_ACTING → PLAYER_INPUT` 轉換時**顯示「我方行動」橫幅(戰鬥開場的第一個玩家回合不出;`FINISHED` 不出)。
      矩形同 AC2,同樣與棋盤矩形不相交;時長同 AC2。
      **第一個玩家輸入(按鍵/手把按鈕/滑鼠按鍵「按下」,不含滑鼠移動與搖桿漂移)即消失,且不消耗該輸入**(沿用 `_input()` 對 ObjectivePanel 的既有「不消耗事件」模式);離開 `PLAYER_INPUT` 亦硬關,不與敵方橫幅同框。
      z 序在 `InfoLabel` 之下;橫幅可見的每一幀,若 `InfoLabel` 非空,斷言其文字矩形不與橫幅相交。
      實作者須實測並回報:換手那一幀 `selected_unit()` 是否為 -1、開場是否會發 `phase_changed`(若會須排除首次);與預期不符則停下回報。
      防空洞:斷言橫幅確實出現過。測試:真實 `BattleScreen`(注入合成資料)驅動「敵方→我方」換手。
- [ ] **AC3 與提示列同步**:同一幀內提示列已為 story-045 的 `ENEMY_PHASE` 內容(測試斷言標題色、橫幅、提示列三者在同一次 `_refresh_view` 後一致)。
      橫幅一律斷言離散的「應顯示」旗標,不斷言透明度(透明度由計時連續變化,同幀不穩定)。我方回合換手時,同樣斷言標題色已還原、提示列為 story-045 的 `NO_SELECTION` 內容。
- [ ] **AC4 可跳過/不阻擋**:兩種橫幅皆不吞輸入:敵方橫幅期間既有行為不變(敵方回合本就不接受操作);我方橫幅期間,第一個玩家輸入(例如確認)同時關閉橫幅並照常執行其原本功能(斷言該輸入的原效果仍發生)。
