## 二、第二部分:若 Q1~Q3 答案為可行 — 2 首音樂需求規格

> 🔴 **本部分僅在管理者看過第一部分回報、並裁決模型與授權之後才啟動。** 家用端**不要**在回報第一部分的同時自行開始產音樂。

### 2.1 遊戲調性(取材出處)

- 《盲目於微光》是戰術戰棋 + 敘事策略,**克蘇魯(Cthulhu Mythos)調性**;五名彼此陌生的人在**迷霧森林**中醒來(`design/gdd/game-concept.md` 「電梯簡報」與「核心身份」)。
- **戰鬥層 100% 資訊透明、零隨機,恐怖不在戰鬥之內**(同上「核心身份」類型欄;支柱一)。→ **戰鬥曲不要做成驚嚇、不要有隨機突發的恐怖音效式編曲**,應是冷靜、專注、有壓迫但可預期。
- 調性對標《暗黑地牢》:「資源永遠不夠、一群人在其中不斷磨損」(`game-concept.md`「對標作品(調性與結構)」)。
- 美術為像素風、480×270 套裝(`design/art/art-direction.md`)。⚠️ 該檔第 218 行附近明寫「不規劃音訊」,**音訊的調性目前沒有任何美術文件規定,以上只取自 game-concept**;本單的情緒描述是我方的詮釋,**不是既有裁決**。

### 2.2 兩首規格

| 項目 | `mus_title_main_loop` 標題曲 | `mus_battle_main_loop` 戰鬥曲 |
|---|---|---|
| 情緒 | 迷霧中的孤寂與不安的靜,帶一絲「他們終究要互相依靠」的微光 | 冷靜、專注、持續的壓迫感;像在算一盤輸不起的棋;不歡快、不英雄化 |
| 編制方向(建議,可議) | 稀疏、空間感、慢速;弦/鋼琴/氛圍墊底,**避免明確人聲歌詞** | 較緊湊的節奏型,低音脈衝或打擊樂但**避免突發重音/驚嚇**;可預期的律動 |
| BPM 建議 | 60~80 | 90~110 |
| 長度 | 60~120 秒一圈 | 90~180 秒一圈(玩家一場 30~120 分鐘,會聽很多遍,**越不惹人煩越重要**) |
| 循環 | **必須無縫循環**(頭尾接起來無爆音、無明顯節拍斷裂、無音量跳動) | 同左,**硬性** |
| 人聲 | 不要歌詞/可辨識語言 | 同左 |
| 格式 | `.ogg`(Vorbis) | `.ogg`(Vorbis) |
| 取樣率/聲道 | 44.1 kHz(或 48 kHz,回報原生值即可)/ 立體聲 | 同左 |
| 響度目標 | 約 -16 LUFS integrated(**建議值,未經試聽驗證**;以管理者家中實聽為準)。真峰值不超過 -1 dBTP | 同左 |
| 命名 | `mus_title_main_loop.ogg` | `mus_battle_main_loop.ogg` |

### 2.3 候選數量與交付

- 每首**至少給 3 個候選**(不同 seed/不同提示),因為 AI 音樂品質不穩,**挑選本身是工作量**。命名在規定檔名後加候選序號,例如 `mus_battle_main_loop_c01.ogg`;最終入選者才改為規定檔名。
- 每個候選附:提示詞全文、seed、模型名稱與版本、參數、輸出檔 SHA256、長度、是否做過循環後製(做了什麼)。
- 🔴 **不要自行判斷「好不好聽」或「是否通過」。** 管理者**只能在家試聽**(公司不能出聲);公司端沒有人能驗收聲音。家用端只列數據,試聽由管理者在家執行。
- 循環是否無縫,**家用端須附客觀證據**(例如頭尾 N 毫秒的波形/樣本差值),但最終仍以人耳為準。

## 三、第三部分:勝 / 敗 stinger

- 範圍裁決見草稿 Q3:**最小版 = 2 首循環曲 + 2 個 stinger**(`minimal-audio-scope-draft` 第二節 2.3)。**管理者尚未對 stinger 是否一併產生做裁決**,因此本單只詢問:
  - Q9 已問能否產 3~6 秒短旋律。
  - 若可以,**請在第一部分回報中另列:勝利 stinger、失敗 stinger 兩者能否在同一模型/同一環境產出**。
- 規格預設(待管理者確認才做):`mus_stinger_victory_01.ogg` / `mus_stinger_defeat_01.ogg`,3~6 秒,**非循環**,尾端自然收束(不可突然截斷),勝利與失敗在調性上要一聽就能分辨(**失敗不要做成嘲弄感**;`game-concept` 對陣亡採哀悼語域,見該檔「修正二」)。
- 命名依專案慣例 `[category]_[context]_[name]_[variant].[ext]`。

## 四、限制(請逐條遵守)

1. 🔴 **不得下載任何未經協調者同意的新模型、元件或 LoRA。** 家用端**只先回報候選**(第一部分 Q2),**由管理者裁決**後才可下載(同 32 號第 3.2、第三節慣例)。
2. **不要為了回答 Q1 而去「試裝看看」。** 要查現況就讀已安裝內容;要測試就等裁決。
3. **管理者只能在家試聽**。交付物要能讓他在家用耳機聽,**不需要任何公司端的人聽過**。
4. **授權原文必須附取得日期。** 授權條款會變;沒有原文與日期的「可商用」一律當作未查證。
5. 做不到就回報「做不到 + 原因」,**不要變通硬做**(同 32 號第四節 3.)。

## 五、AI 產音訊的揭露政策(待決)

- 美術側的 `docs/ai-art-pipeline/SPEC.md` 我查過:**未找到對外揭露(遊戲內/商店頁)的明文規定**。唯一相關是第 53 行:該 SPEC「不處理 AI 產出能不能商業販售的授權問題 —— 已有另一份報告處理」,以及附錄 C-4 登記的一項「規則衝突」(那是寫檔規則,與揭露無關)。
- 因此**音訊的揭露政策標為「待決」**:是否比照產圖、在遊戲或商店頁揭露,對應草稿 Q6,**管理者尚未裁決**。Steam 對 AI 內容的揭露規定**未查證**,上架前需讀當時版本。
- 在裁決之前,**家用端須完整保留每個候選的模型/版本/提示詞/seed 紀錄**,以便日後無論揭露與否都有追溯依據。
