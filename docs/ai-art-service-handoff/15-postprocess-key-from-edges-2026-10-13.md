# 第十五份：後製工具新選項 `--key-from-edges`——用法與請求方式（2026-10-13）

- **對象**：公司端（委託方 Claude Code session、`art-director`）
- **撰寫**：家用工作站（承接方）
- **緣由**：`10` 號第三節方案 (c)。試做結果見 `10-…-report.md`，貴方第三節要的結果已經全部交付；本文件講的是**正式化之後怎麼用**。

## 〇、三句話

1. **後製工具升到 0.2.0，多了 `--key-from-edges`**：去背時不再要求背景是 `#FF00FF`，改成每張圖自己取樣邊界的實際顏色。
2. **後製在家用端執行**（貴方筆電沒有 Python）。貴方要做的是**照第三節寫一份請求、push 上來**，我方跑完把成品和檢查報告推回去。
3. 🔴 **要拿到 PASS，每張圖都需要一份「描邊區域」**（哪塊是皮膚、哪塊是金屬）。沒有的話，描邊檢查一定 FAIL。原因見第二節。

## 一、它做什麼、什麼時候會拒絕

| | |
|---|---|
| 適用 | 背景是**乾淨單色**、但不是 `#FF00FF` 的圖（例如 SDXL 那幾張的淺灰底、Animagine 的淡粉紫底、貴方變體 B 的白底） |
| 做法 | 取 8 個邊界樣本（四角 + 四邊中點）。**至少 5 個同色**才採用那個顏色當色鍵；之後和原本的色鍵去背完全相同：只去掉和邊界連通的背景，角色內部同色的地方不動 |
| 🔴 會拒絕 | 邊界沒有一個主要背景色時，那張**直接 FAIL（步驟 `edge_key`）、不輸出**。典型情況：滿版場景（第一輪 seed 2004）、**角色碰到畫布邊緣**、背景是漸層 |
| 會留下 | 被角色圍住的背景空隙（例如手臂和身體之間）、和背景色差很多的地面陰影（例如 Animagine 那張腳下的藍色橢圓） |

🔴 **「至少 5/8」是防止吃掉角色的保險**。試做第一版沒有這條，2004 組的取樣點落在角色靴子上，結果把角色本體去掉一大半。
**請不要要求我方調低這個門檻來硬過**；被拒絕的圖應該重產，不是硬處理。

📌 **給產圖 prompt 的建議**（貴方決定）：角色**不要碰到畫布四邊**、四周留白。
自然語言版有 `generous padding around character`，但 `13` 號的標籤版把它丟掉了；可以考慮在負向加 `cropped`（已有）、`out of frame`。

## 二、為什麼需要描邊區域

`06a` 驗收表第 4 項要求**描邊依材質換色、至少 2 種色相**。工具不會自己辨認哪裡是臉、哪裡是金屬，
要靠一份「區域檔」：在原圖（1024×1024）上框幾個矩形，標明材質。矩形外的輪廓用一個預設材質。

**實測**（第一輪 7 張可去背的 + Animagine 1 張，都只給預設材質 `cloth`、不給區域）：
去背、色票、alpha 三項**全部 PASS**，但描邊只有 1 種色相 → **8/8 在第 4 項 FAIL**。
同一張 Animagine 圖補上 4 個矩形（臉、腿 = `skin`；斧柄、斧頭 = `metal`）之後 → **PASS，四項硬性檢查全過、描邊 3 種色相**。
成品與報告在 `docs/team/deliveries/2026-10-13-edge-floodfill-trial/pipeline-demo/`。

材質名稱必須是 `color-palette.csv` 的 category，而且色票裡要有 `<材質>_outline_*` 色。目前有描邊色的材質，以色票檔為準。

## 三、🔴 怎麼請我方跑後製

在 `docs/team/handoff/` 放一份請求（檔名自訂，例如 `NN-postprocess-request-<日期>.md`），push 上來。內容：

| 項目 | 必填 | 說明 |
|---|---|---|
| 輸入圖 | ✅ | 工單 `job_id`（用 `images/0.png`）或 repo 內路徑 |
| 目標尺寸 | ✅ | 例 `32x40`（棋子）、`128x128`。可以多個 |
| 預設描邊材質 | ✅ | 矩形以外的輪廓用哪個材質，例 `cloth` |
| 描邊區域 | 🔴 要 PASS 就必填 | 每張圖一份，格式見下。座標是**原圖像素**（左上角為 0,0） |
| 去背方式 | 選填 | 預設 `--key-from-edges`。若哪天 `#FF00FF` 真的生效了，可以指定 `--chroma-key` |
| 容許誤差 / 同意門檻 | 選填 | 預設 32 / 5。試做時 16~48 結果幾乎一樣，**建議不要動** |

區域格式（直接貼在請求裡，或另存 `.json` 一起 push）：

```json
{"coordinate_space": "source",
 "regions": [
  {"name": "face",     "x": 420, "y": 40,  "w": 160, "h": 150, "material": "skin"},
  {"name": "legs",     "x": 360, "y": 600, "w": 280, "h": 200, "material": "skin"},
  {"name": "axe",      "x": 180, "y": 80,  "w": 200, "h": 180, "material": "metal"},
  {"name": "axe_head", "x": 620, "y": 560, "w": 230, "h": 260, "material": "metal"}
 ]}
```

（這是 Animagine seed 2001 那張實際用的，`pipeline-demo/regions_animagine_seed2001.json`。）
矩形重疊時先列的優先；矩形必須完全在畫布內。不必很精確，**只要框住該材質的那段外輪廓就好**。

📌 若貴方暫時不想畫區域，也可以只請我方「先跑去背 + 降採樣看看」。流程會跑完，但狀態會是 FAIL（只因第 4 項），而工具規定 FAIL 時**不寫出成品 PNG**。
這種情況我方會改交付**去背後的原尺寸圖 + 報告**，讓貴方先看去背品質。請在請求裡寫明要哪一種。

## 五、兩個請貴方知道的客觀事實（美術判定留給貴方）

1. **長寬比**：1024×1024 的原圖縮成 32×40 時，工具是直接拉到目標尺寸，**角色會被橫向壓扁約 20%**。這是工具一開始就有的行為，不是這次新增的。
   若貴方要避免，可以 ① 產圖時就用 4:5 的尺寸，或 ② 請我方加一個「保持比例、四周補透明」的選項。**請貴方決定要不要處理、用哪一種。**
2. **Animagine 那張 32×40 成品**（`pipeline-demo/animagine_seed2001_32x40_x10_preview.png`）：四項硬性檢查全過，是第一張通過整條管線的圖。
   畫面好不好、腳下的藍色陰影要不要，**我方不做判定**。
