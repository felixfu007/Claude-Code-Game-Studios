## 零、這份文件誠實的起手式

## 一、威脅模型——這個情境真正的風險是什麼

這套系統有三個與一般企業伺服器不同的特徵,風險評估要針對這三點,不是抄一般資安清單:

1. **運行環境是家用網路,不是企業網路。** 家用網路通常是一個「扁平」網路——路由器、
   智慧家電、手機、電腦全部在同一個網段,彼此沒有區隔。家用網路上其他裝置若遭入侵
   (例如一台不常更新韌體的智慧家電),理論上就有機會在同一網段內嘗試碰觸這台生圖伺服器。
2. **程式碼是外部團隊建置的,委託方不一定會逐行審查。** 這不是對外包團隊的不信任,
   而是一個結構事實:委託方的風險承受,不能建立在「我會自己讀過每一行程式碼」這個假設上,
   因為實務上大機率不會發生。安全措施必須假設「交付的程式碼委託方不會逐行讀」也仍然安全。
3. **這台機器對外只開一個本機 HTTP API,其餘都是委託方自己的事。** 工單怎麼送進來、
   成品圖怎麼送出去,不屬於這次外包範圍,由委託方另行處理。**本章只談這台機器本身、
   這個 API 介面本身的安全,不涵蓋前面那段傳輸流程**——那段的風險評估委託方已自行處理過。

把這三點合起來,這個情境**真正**需要擔心的,不是「有沒有人想攻擊這台機器」(一台家用電腦
通常不是針對性攻擊目標),而是:**一旦這個 API 意外地變得可以從家用網路以外的地方連到,
它會立刻變成自動化掃描工具的目標**(網路上持續存在大範圍掃描公開 IP 開放連接埠的自動化
工具,不需要有人「盯上」這台機器,被掃到純粹是機率問題)。其次是**交付的程式碼或模型檔
本身就夾帶風險**,而委託方沒有管道逐一驗證。本章以下各節針對的就是這兩類風險。

## 二、網路暴露面——硬性要求

### 2.1 綁定位址的三個層級與各自代價

| 綁定方式 | 誰連得到 | 代價/風險 |
|---|---|---|
| **僅本機**(`127.0.0.1`/`localhost`) | 只有這台機器自己的程式能呼叫 | 最安全,但委託方若想從家裡其他裝置(手機、另一台電腦)呼叫,**必須**先登入這台機器,不能直接跨裝置呼叫 |
| **區域網路**(綁定到家用網路的內部位址) | 家用網路內的所有裝置都連得到 | 方便跨裝置呼叫,但代價是**家用網路上任何一台被入侵的裝置,理論上都能呼叫這個 API**——家用網路通常沒有裝置隔離 |
| **公開網際網路**(對外開連接埠、連接埠轉發、動態網域) | 全世界任何一台連網裝置都連得到 | 🔴 **明確禁止,見下方** |

**綁定位址的具體建議值與設定方式,見本交付包第二章(部署手冊)——此處不重複,僅給安全層級的取捨判斷。**

### 2.2 明確禁止事項

🔴 **委託方要求:伺服器不得對公開網際網路開放連接埠,也不得為了方便而做連接埠轉發(port forwarding)
或使用動態網域(Dynamic DNS)把這台機器的服務公開曝露在網際網路上。** 這是交付驗收的硬性條件,
不是建議。任何「只是暫時方便測試」的對外開放,都不能出現在交付的最終設定裡。

**理由(不涉及委託方個人情況,純技術事實)**:對公開網際網路開放的服務埠,會被網路上持續
運作的自動化掃描工具發現,通常在數小時到數天內。發現之後,這個端點就會持續受到自動化的
弱點嘗試、憑證暴力破解等攻擊,不需要有人刻意針對這台機器。

### 2.3 若真的需要跨裝置或遠端存取,安全的做法有哪些(給選項,不給單一結論)

| 方案 | 做法 | 代價 |
|---|---|---|
| **A. 私有疊加網路(建議預設)** | 使用點對點的私有疊加網路工具(例如 WireGuard 類或同性質的商用網狀網路產品),只讓委託方自己的裝置彼此可見,不對外開放任何監聽埠 | 設定一次即可,日常使用幾乎無感;需要委託方自己的每台裝置都安裝對應的用戶端軟體 |
| **B. 僅出站的反向通道** | 家用機器主動對一台委託方自己信任的中介伺服器建立出站連線,不在家用路由器開任何對內監聽埠 | 需要委託方自己維運或信任那台中介伺服器;多一個環節要顧 |
| **C. 商用穿透/代理服務** | 使用市面上的穿透服務把本機服務包裝成可遠端存取的網址 | 設定最簡單,但多了一個第三方中介,流量是否端對端加密、該服務本身是否可信,**必須先查證該服務的加密與信任模型再採用**——不是裝了就等於安全 |

**無論選哪一種,API 本身都必須有身分驗證機制(金鑰或憑證),不能只靠「位址沒人知道」當作
唯一防線**——意外曝露的情況下,「沒人知道這個位址」這件事本身撐不住自動化掃描。

## 三、「程式碼不是委託方自己寫的」——怎麼降低風險

### 3.1 外包方交付時應附上的東西

- **完整相依套件清單,版本鎖定(不是「最新版」)。** 每個套件應能說明來源(官方套件庫、
  官方原始碼倉庫),而不是來路不明的鏡像站或個人分享連結。版本鎖定的意義是:
  日後重新安裝時,裝到的是同一個版本,而不是被動地裝到一個事後才被植入問題的更新版本。
- **伺服器端自訂程式碼應以可閱讀的原始碼交付**,不是僅交付編譯後或打包過的執行檔。
  即使委託方現在不會逐行審查,這讓日後任何人需要審查時有東西可看,而不是一個黑盒子。
- **要求外包方揭露軟體是否有任何對外連線行為**(例如自動更新檢查、使用情況回報/遙測)。
  這類行為本身不一定是惡意的,但委託方有權利知道這個系統除了生圖之外,還會主動連到哪裡。

### 3.2 模型權重檔案的來源與格式——格式本身就是風險面

🔴 **已查證**:AI 模型權重檔案常見兩種儲存格式,安全性差異很大:

- **舊格式(`.ckpt`、`.pt`、`.pth` 等,底層是 Python 的 `pickle` 序列化)**:這類格式的設計
  目的不只是存資料,而是「連程式邏輯一起存」——載入檔案這個動作本身就可能觸發檔案裡夾帶的
  任意程式碼執行,不需要使用者額外按下任何「執行」。這不是理論風險:已有獨立資安研究團隊
  在 Hugging Face 這類模型分享平台上實際找到過夾帶反向連線(reverse shell)程式碼的模型檔案
  案例(JFrog, 2024-02-27,
  https://jfrog.com/blog/data-scientists-targeted-by-malicious-hugging-face-ml-models-with-silent-backdoor/ ,
  查證於 2026-10-05;ReversingLabs, 2025-02-06,
  https://www.reversinglabs.com/blog/rl-identifies-malware-ml-model-hosted-on-hugging-face ,
  查證於 2026-10-05,該案例甚至用特殊手法繞過了平台自動掃描)。
- **`.safetensors` 格式**:由 Hugging Face 與 EleutherAI、Stability AI 共同設計,檔案內**只有
  張量數值資料與描述資料的 JSON 表頭,沒有任何可執行程式碼的路徑**——載入這個格式的檔案,
  結構上就不可能在載入時執行程式碼。這點已經過獨立資安稽核公司 Trail of Bits 的稽核確認
  (稽核於 2023-05-12,Hugging Face 公告於 2023-05-23 的部落格文章:
  https://huggingface.co/blog/safetensors-security-audit ,查證於 2026-10-05)。

**建議**:**模型檔一律只收 `.safetensors` 格式**,不下載、不使用 `.ckpt`/`.pt` 格式的模型。

⚠️ **格式安全不等於內容可信。** `.safetensors` 格式本身保證的只是「載入時不會執行程式碼」,
**不保證檔案裡的權重數值本身沒有被動過手腳**(例如被刻意訓練成會在特定條件下輸出異常結果)。
格式安全是最低防線,不是全部防線——仍然只應從有信譽的來源(官方帳號、來源可追溯)下載模型檔,
並記錄每個模型檔的 SHA256 雜湊值(此項本交付包第二章已列為交付必附項,此處不重複)。

另外要誠實說明:Hugging Face、Civitai 等平台雖然都有自動掃描機制(掃毒 + 檢查 pickle 檔案
內夾帶的程式呼叫),但**這些掃描是輔助性質,不是保證**——平台本身的文件也明白寫著「這不是
百分之百可靠的防護」,且已有被繞過的實際案例(見上方 ReversingLabs 案例)。「平台沒標示為
不安全」不等於「保證安全」。

### 3.3 第三方套件供應鏈風險——白話講後果

任何軟體都會依賴一堆別人寫的套件。風險在於:**委託方今天安裝的版本是乾淨的,不代表這個
套件名稱背後的程式碼永遠乾淨**——套件的維護者帳號可能被盜用,或套件本身在某個更新版本中
被植入問題,而使用者在不知情的狀況下升級就一併裝進來。**鎖定版本號**(而不是永遠裝「最新版」)
正是為了避免這種「我什麼都沒改,但下次重裝時裝到了一個不一樣的東西」的情況。

## 四、這台機器會接觸到什麼資料

這台機器在運作過程中會經手:**文字提示詞、生成出來的圖片、模型權重檔案、以及呼叫紀錄
(日誌)**。以下幾項原則與傳輸層怎麼設計無關,是這台機器本身該遵守的:

- **日誌不應該透過這個 API 本身被讀取或匯出。** 呼叫紀錄(誰在何時用了什麼提示詞)應該留在
  機器本地,供事後人工查閱,而不是成為 API 的一個可呼叫功能——否則等於多開一個資料外洩的
  管道。
- **提示詞若包含尚未公開的遊戲設計內容**(例如角色設定、劇情用詞),應視為需要保護的內容,
  日誌保留原則上從簡,不做超出除錯需要的長期保存。
- **錯誤訊息不應該洩漏系統細節。** API 回傳的錯誤訊息不應包含完整檔案路徑、內部堆疊追蹤、
  或任何可能幫助攻擊者了解系統內部結構的資訊。
- **這個 API 的功能範圍應該僅限於生圖本身**,不應該附帶任何形式的指令執行、任意檔案讀寫、
  或讓呼叫端臨時從網路上抓取新模型/新程式碼的能力。功能範圍越窄,萬一這個端點意外曝露,
  能造成的損害範圍也越小。
- **模型權重檔案本身不應該被這個 API 回傳或下載**——它只應該被用來生圖,不該有一條路徑讓
  呼叫端把整個模型檔案載走。這部分也跟下一節的授權問題有關:模型檔案的散布本身可能受授權
  條款規範。

## 五、授權——這一節對委託方最實際(非法律意見,僅供確認方向用)

🔴 **再次強調:本節不是法律意見,只整理公開可查的授權條款內容與業界常見法律評論,
供委託方判斷是否需要進一步諮詢律師。所有結論性的法律判斷,應由委託方自行確認。**

### 5.1 模型授權條款本身——不同模型條款差異很大,必須逐一確認

常見的開源影像生成模型授權條款,至少有兩種明顯不同的模式(查證於 2026-10-05):

| 模型 | 授權條款 | 商業使用條件 |
|---|---|---|
| **Stable Diffusion XL(SDXL)基礎版/精修版** | CreativeML Open RAIL++-M | 允許商業使用,**沒有營收門檻**;但附帶「禁止用途」條款(不得用於產生非法、有害、仇恨、兒童性剝削等內容)。來源:Hugging Face 官方模型頁 `stabilityai/stable-diffusion-xl-base-1.0` 的授權欄位,https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0 |
| **Stable Diffusion 3 / 3.5** | Stability AI Community License(2024 年中改版) | **僅限企業/個人「總年營收」低於 100 萬美元者可免費商用**;超過門檻須另購企業授權。即使在免費門檻內,若散布模型或以此模型為基礎的衍生產品,**仍須附上指定的授權聲明檔案,並在相關網站/文件上標示「Powered by Stability AI」**。來源:Hugging Face 模型頁 `stabilityai/stable-diffusion-3.5-large` 的 LICENSE.md,https://huggingface.co/stabilityai/stable-diffusion-3.5-large ,以及 Stability AI 官方條款頁 https://stability.ai/community-license-agreement |

🔴 **重點提醒**:
1. 這個 100 萬美元門檻算的是**公司的總年營收**,不是「用這套生圖系統賺的錢」——即使生圖
   只是內部工具,只要公司整體年營收超過門檻,一樣要換成企業授權。
2. **不同模型、不同版本的授權條款不能互相套用**——換一個模型檔案之前,必須重新確認該檔案
   實際附帶的授權條款版本,不能假設「反正都是 Stable Diffusion 系列就一樣」。
3. 以上門檻與條款內容為 2026-10-05 查證結果,**授權條款本身會隨時間修改**(SD3 剛發布時的
   版本就曾因社群反彈而在發布約一個月後修改過一次條款),驗收與日後每次升級模型版本時都
   應該重新查核目前生效的條款原文,不要依賴本文件的既有記錄。

### 5.2 AI 生成圖像本身的著作權歸屬——可能不受保護

美國著作權局於 2025-01-29 發布的報告(著作權局官方頁面:https://www.copyright.gov/ai/ ,
查證於 2026-10-05)採取的立場是:**純粹由 AI 生成、僅靠文字提示詞產生的圖像,不構成可受著作權
保護的著作**——著作權法要求「人類創作」,而下提示詞被認為對最終圖像的表現形式控制不足以構成
創作行為。**可以**受保護的是:人類在 AI 輸出之上做的「創意編排/選擇」(例如把多張 AI 圖組合成
一張角色立繪、做後製調色調整)、或是以人類原創素材(手繪草稿、參考構圖)為輸入時殘留在輸出中
的部分。

**對商業遊戲的實際後果**:如果一張素材從頭到尾只靠打提示詞產生、沒有任何人工編修,**這張素材
本身可能不受著作權保護**——理論上其他人複製這張圖,委託方可能沒有著作權基礎去主張侵權。
**建議**:每一張要進遊戲的 AI 生成素材,都保留一道人工編修/合成的手續(調色、合成、局部
重繪皆可),這同時提升品質,也讓最終成品多一層可主張著作權保護的人類創作成分。

### 5.3 「用別人的風格」——風格本身與具體重製是兩回事

業界法律評論(以電子前哨基金會 EFF 的立場為代表,2023 年文章:
https://www.eff.org/deeplinks/2023/04/how-we-think-about-copyright-and-ai-art-0 ,
查證於 2026-10-05)普遍認為:**「風格」本身不受著作權保護**——模型從既有作品中學到一種
畫風,原則上與人類畫師觀摩他人作品學畫風是類似的性質。

**但有一條明確的分界線**:如果提示詞的設計意圖是刻意要求模型「重製出某一張具體存在的、
可辨識的原作品」,而不只是「某種風格」,這種情況下**責任可能落在下指令的人身上,而不是
模型本身**——這在技術上稱為「記憶化」(memorization)問題:生成模型在少數情況下,對於
訓練資料中被大量重複出現的特定圖像,有機會生成高度相似的重製結果,而不只是風格相似。

**實務建議**:
- 提示詞避免指名在世的特定畫師、工作室、角色或作品名稱(例如「像某某知名畫師的風格」),
  改用中性的描述(媒材、年代、光影、構圖等客觀描述詞)。
- 若生成結果與某張具體存在的既有作品構圖高度相似(不只是風格相似),不應採用該張輸出。

### 5.4 這個領域的法律環境目前並不穩定——僅作背景說明,不代表具體建議

目前有多起與 AI 生圖模型相關的訴訟仍在進行中,例如 Getty Images 對 Stability AI 的訴訟
(英國案於 2025-11-04 已有一審判決,著作權部分 Getty 敗訴但已獲准上訴,商標部分 Getty
部分勝訴;美國案仍在進行,尚未結案)、以及一群藝術家對 Stability AI 等公司提起的集體訴訟
(Andersen v. Stability AI,陪審團審理於 2026-09-08 左右展開,**截至本文查證日 2026-10-05
尚未查到最終判決結果**)。**這些訴訟目前主要針對模型訓練方的責任,尚未有明確判例直接處理
「單純使用這些模型商業產圖的公司」要負什麼責任**——這代表這個領域的規則還在變動中,
**建議委託方每隔一段時間(例如每次重大模型升級時)重新查核一次目前的法律環境與所用模型的
最新授權條款**,不要假設今天查到的結論長期有效。

### 5.5 這一節沒有涵蓋、需要委託方自行確認的事項

- 委託方公司/專案目前與預期的年營收是否落在前述 100 萬美元門檻之內(本文無法代為判斷)。
- 若最終選用的模型不是 SDXL 或 SD3/3.5,而是其他社群微調模型,其授權條款可能來自上游基礎
  模型、也可能疊加微調者自訂的額外條款,**需要逐一查核該特定檔案附帶的授權文字**,本文的
  比較表不能直接套用。
- 任何涉及「用特定既有作品或特定畫師作品去訓練/微調模型」的計畫,其授權與倫理風險超出本文
  查證範圍,若有此類計畫應另行諮詢。
- 以上法律環境描述屬於背景參考,**具體到委託方這個專案是否構成法律風險,應諮詢熟悉當地法規
  的律師**,本文作者不具備提供法律意見的資格。

## 六、交付驗收安全檢查清單

外包方交付時,委託方應逐項確認下列各點(每項皆為可直接執行的動作):

- [ ] **實際連線測試**:從這台機器以外的裝置嘗試呼叫這個 API,確認在未設定任何遠端存取方案
  (第二章 2.3 節)的情況下無法連通;確認路由器沒有對這個服務做任何連接埠轉發設定。
- [ ] **索取完整相依套件清單**,確認每個套件都標明版本號與來源,沒有「安裝時自動抓最新版」
  的指令。
- [ ] **索取模型權重檔案清單**,包含檔名、下載來源連結、SHA256 雜湊值;實際對照收到的檔案
  重新計算雜湊值,確認一致。
- [ ] **確認每個模型檔案格式**,若非 `.safetensors`,要求外包方書面說明原因與採取的替代防護
  措施。
- [ ] **索取每個使用中模型的授權條款連結與條款版本日期**,並自行開啟連結確認條款內容與交付
  文件所述一致。
- [ ] **要求提供伺服器端自訂程式碼的可閱讀原始碼**(非僅執行檔/打包檔)。
- [ ] **要求外包方書面揭露**這套系統是否有任何對外連線行為(自動更新檢查、使用狀況回報等),
  並說明如何關閉。
- [ ] **實際觸發一次驗證失敗情境**(例如用錯誤的金鑰呼叫),確認回應是拒絕並記錄,而不是
  放行或洩漏內部錯誤細節。
- [ ] **確認 API 功能範圍**:除了生圖本身,逐一確認沒有任何路徑可以執行系統指令、讀寫任意
  檔案、或下載模型檔案本身。
- [ ] **確認日誌與呼叫紀錄的存放方式**:日誌只留在本機,沒有透過 API 本身對外可讀取或下載。
