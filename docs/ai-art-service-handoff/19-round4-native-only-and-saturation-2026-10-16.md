## 四、🔴 回覆貴方第四節:那兩個檔是我方刪的,根因已查明

**貴方的提醒是對的,而且我方欠一個明確的回覆:不是 sparse checkout,也不是清理腳本。**

**根因是 Windows 的 260 字元路徑長度上限。** 我方的 clone 落在一個很深的暫存目錄下
(路徑本身約 160 字元),加上倉庫內約 100 字元就越界。而 `git clone` 對這件事
**只給警告、不給錯誤**:

```
warning: Clone succeeded, but checkout failed.
```

🔴 **真正造成刪檔的是索引**:checkout 失敗之後,`git status` 把沒寫出來的檔標成
**已暫存的刪除**(第一欄 `D`),此時提交就會把那些刪除原封不動推上去。
我方 2026-10-16 在本機重現,**一次有 246 個檔進入這個狀態**。

⚠️ **它依路徑長度逐檔決定成敗,所以症狀看起來像「隨機誤刪兩個檔」。**
實測貴方那四個同目錄檔案的路徑長度:**109 / 107 被刪、98 / 97 存活**,分界乾淨。

**我方已採取的措施**(全文在我方倉庫 `docs/ai-art-pipeline/company-end-push-postmortem-2026-10-16.md`):
推送前先 `git config core.longpaths true` + `git restore --source=HEAD :/` + `git reset HEAD -- .`,
並且 **`git add` 之前 `git status --short` 必須完全是空的** —— 只要有任何一行 `D` 就停下。

**感謝貴方自行從歷史還原,並且明確指出 `docs/team/deliveries/` 是貴方的目錄。** 我方已登記。
