## 1. 問題一：風格 A vs 風格 B —— 選哪一個？或這批答不了這個問題？

**一句話結論：這批答得了，但答案不是「選 A 或選 B」，而是「B 沒有產生任何可觀察效果，建議放棄
這個修改方向，回頭用 A（並拿掉那組關鍵字省字元）」。**

目視核對 2002、2003 兩組成對圖（styleA vs styleB），加上 2001 兩張都是裝備設定圖的縮圖比對：
**同 seed 的 A/B 在構圖、姿勢、打光、描邊風格、陰影處理上幾乎一模一樣**，唯一看得出的差異是
配件道具本身的選擇（例如 2002 組 A 拿斧頭+披風、B 拿斧頭+盾牌；2003 組 A 拿長槍+彎刀、B 拿
滅火器+斧頭）——這些是生成過程本身的隨機變化（換 prompt 片段前就會因 seed 不同而出現的那種
差異量級），**不是「加了 `pixel art style, pixelated` 這幾個字之後產生的風格轉變」**。
1024 畫布上**沒有任何一張出現看得出來的像素塊化**，與交付報告自己的量測方向一致（同 seed
A/B 距離小於跨 seed 距離）——我的目視判斷與對方的客觀量測在這一點上互相印證。

**為什麼這代表「答得了」而不是「樣本太少、答不了」**：這不是在問「哪個 seed 比較好看」這種
需要大量樣本才能看出趨勢的問題，而是在問「這一個具體的 prompt 修改（加兩個字詞）有沒有
造成任何方向性的效果」——4 組樣本裡 4 組都是「沒有效果」，而且目視與量測兩種獨立方法得到
同一個結論，這已經是一致、可重複的否定結果，不需要更多 seed 去「確認也許第 5 組會不一樣」。

**延伸判斷（放在這裡提前講，避免誤導）**：`pixel art` 這類關鍵字在 SDXL base 1.0、1024 原生
解析度、無 LoRA 的設定下本來就不容易穩定觸發真正的像素網格——真正的像素化預期是靠**後製的
降採樣 + 量化**完成（06a 第二節的既定設計），不是靠生圖端的文字提示。所以 B 這個實驗方向
從一開始的機制上就不太可能成功，這批圖只是把這個預期用實測證實了。**建議**：往後的 prompt
不再加這組關鍵字，省下的字元數（約 28 字元）用在第四、六節建議的其他修正上。

## 2. 問題二：離像素風有多遠？現有後製流程走得通嗎？

**一句話結論：很遠，而且現有流程走不通——不只是因為去背斷掉，是源頭的繪製風格本身就跟
目標（flat 3-tone cel-shade、外輪廓單線）不相容，去背就算修好，量化這一步照樣會出問題。**

目視確認的風格落差（對照 `06a` 第一節硬參數與 `art-direction.md` 的 flat cel-shade 要求）：

1. **大量內部描邊，違反「internal seams 最小化到無」**：2002 組兩張的背帶、口袋、扣具、
   披風/盾牌邊緣全部各自描了黑色輪廓線；2003 組同樣在肩帶、口袋、護具接縫處有明確描邊。
   這與規格「外輪廓才描邊、內部靠色塊對比分色」正好相反。
2. **陰影是柔和漸層，不是三階平塗**：2002 組的披風、2003 組的制服皺褶、2004 組的全身
   打光都看得出連續的明暗過渡（接近傳統厚塗/渲染風格），不是「shadow/base/highlight
   三個離散色階」的平塗 cel-shade。`06a` 要求的 flat color-block 在這 8 張裡沒有一張
   做到。
3. **唯一比較接近規格精神的是 2003 組（A、B 皆然）**：它有一圈相對一致寬度、乾淨的**外輪廓
   描邊**（白色或淺色線，整圈包住剪影），這是 8 張裡唯一看得出「外輪廓單線」意圖的構圖。
   即便如此，2003 內部一樣有肩帶/護膝的黑色描邊，陰影也一樣是漸層，**不是完全合格，只是
   相對最接近**。
4. **2004 組風格明顯跳脫其他三組**：改用更寫實的渲染（臉部打光細緻、場景有空氣透視），
   完全不是扁平插畫路線。同一個角色、同一份 prompt，不同 seed 之間的畫風穩定度本身就
   是個問題——這點下一節（問題四）會再談。

**若硬著頭皮照現有流程跑（1024 → 裁切 → 降到 32×40 → 量化到色票）會發生什麼**：
交付報告 3.3 節用粗略做法（不去背、整張圖含背景一起量）量到的數字很能說明問題——
**8 張的「距最近色票平均距離」介於 19.1～46.5，有一張（2002A）高達 68%（870/1280）的
像素離最近色票超過門檻值 32**。這不是「量化演算法不夠好」能解決的，而是**來源圖本身
色彩是連續漸層/柔和過渡，不是離散平塗色塊**——把連續漸層硬塞進一個 64 色（單一角色
更只分配到建議 ≤24 色）的離散調色盤,必然產生大量色階斷層/雜訊,不會自動收斂成乾淨的
像素藝術外觀。**這是來源風格的問題,不是後製工具寫得好不好的問題。**

**另一層：裁切會吃掉武器道具。** 2002、2003 組的武器（斧頭、長槍、彎刀）往兩側或往上
伸出的幅度相當大，常常逼近或貼齊 1024 畫布邊緣。目標 32×40 是**窄長比例**（寬:高 ≈
4:5），若沿用報告 3.3 節「取中央 4:5 裁切」的做法，**武器很可能被裁掉一截**，這還沒算
進去背與量化的問題,是構圖比例本身跟最終尺寸不匹配的額外風險。

**結論與建議方向**：去背是「連第一步都跑不完」的阻擋項（問題三），但**就算去背修好了，
量化這一步現在看起來也會輸出很糟的結果**，因為源頭畫風是柔和厚塗、不是扁平三階 cel-shade。
這批圖佐證了一件事：**光靠 prompt 文字描述（哪怕寫得再精確、字數再多），SDXL base 1.0
不太能穩定產出我方要的扁平 cel-shade 外輪廓單線風格**。若 LoRA 角色模型訓練（另一份
technical-director 文件的範疇）已經在規劃中，這是支持「需要它」的新證據，不是我這份文件
的裁決範圍，但值得明確點出來讓負責那份文件的人知道。

## 3. 問題三：洋紅去背失效 —— 原因判斷與替代方案

**一句話結論：8 張全部沒有洋紅背景不是單一巧合，而是這個底模/參數組合對「背景要怎麼畫」
整體遵循度偏弱的其中一個症狀（連帶也沒遵守「no scenery」「no shadow cast on background」
「no gradient background」這些負向指令）；建議短期用「取樣各圖實際背景色再做邊界泛洪」
頂上，中期測試換一個與訓練資料連結更強的色鍵色，兩者互不排斥、可以並行驗證。**

### 3.1 為什麼 SDXL 不照做（我的判斷，非量測結論）

1. **多重背景相關指令互相稀釋**：positive prompt 裡光是背景就有 4 處描述（純色洋紅背景、
   無場景、無背景陰影、無漸層背景），加上前面還有一長串風格/打光/構圖描述，**背景這幾個
   詞在整句 40 多個逗號片段裡占比很小**；negative prompt 雖然也明確列了
   `complex background, scenery, ... gradient background, patterned background,
   drop shadow on background`，但 8 張裡仍然出現灰色漸層背景（2002/2003 組）甚至完整
   城市/山岩場景（2004 組）——**連負向提示都沒被確實遵守**，不只是正向指令沒被選中,
   這指向的是整體背景可控性偏弱,不是單一措辭問題。
2. **十六進位色碼對擴散模型是弱指令**：文字描述的 `(#FF00FF)` 這種精確色碼,一般認知上
   擴散模型只會把它當語意暗示（「偏洋紅/粉紫調」），不會當成要精確命中的數值目標——
   這是業界對這類模型的一般認知，**我沒有針對本機做過交叉驗證，僅供參考，不是實測結論**。
3. **角色/裝備描述的語意拉力可能大於背景指令**：大量戰術裝備、消防員設定等敘事性描述,
   可能讓模型傾向生成「完整場景插畫」而非「人物設定圖」,2004 組直接生出城市天際線背景
   是最明顯的例子——模型選擇了「敘事連貫的環境」而不是字面指令。

### 3.2 替代方案（列出優缺點，不代為決定）

| 方案 | 做法 | 優點 | 缺點 / 風險 |
|---|---|---|---|
| **(a) 調整 prompt 寫法** | 把背景描述移到片段更前面、縮短成更直接的短句，並在句尾再重複一次加強 | 零成本、零架構變更，可立即在下一批測試 | 文字對背景的控制力本來就偏弱（見 3.1），不保證有效，仍需再跑一批驗證 |
| **(b) 改用其他色鍵色（例：純綠 `#00FF00`，「green screen」是訓練資料裡更常見的攝影概念）** | 改提示詞背景描述為綠幕相關用詞 | 「綠幕」在真實攝影/影片訓練資料中的共現頻率遠高於「洋紅背景」，理論上遵循度可能更好 | 🔴 **不是可以直接套用的安全變更**：我已查過 `color-palette.csv`，`nature` 類（`#6B7A4E`、`#9FAF7A`、`#628A45` 等）與 `ui` 類的 `#4DE659` 都是帶綠相的顏色，與純綠 `#00FF00` 的色相距離明顯比洋紅當初被驗證時的任何既有色都近。**必須先比照 `06a` 3.4.2 對洋紅做過的那種逐色核對,才能判定純綠是否安全**，我在本次任務裡沒有做這個核對，不應該被當成「可以直接拿去用」的結論 |
| **(c) 後製改用「取樣實際背景色 + 邊界泛洪填充」，不預設固定色鍵值** | 每張圖先取樣四個邊角/邊界中點的實際顏色，以該顏色為基準、帶容許誤差做邊界連通泛洪去背 | 不需要跟模型對抗、不需要等重跑，**現有這 8 張裡 2002/2003 這種「背景相對乾淨」的構圖可能馬上就能用** | 對 2004 這種「背景本身是有城市天際線的完整場景、沒有單一邊界色」的構圖**完全沒用**——沒有乾淨的種子色可以泛洪；也有誤吃到角色自身淺色區域（例如 2002 的白色面罩塗料）的風險，容許誤差要調得很保守 |
| **(d) 後製改用 AI 去背模型（rembg 類分割模型）** | 在生圖後、量化前加一個語意分割去背節點 | 對 2004 這類複雜場景背景也能處理，是唯一一個對全部 4 種構圖都可能有效的選項 | 🔴 **這正是 `06a` 3.2/3.3 已經裁決排除的路線乙**，裁決理由（二元 alpha 量化紀律不相容、失敗模式難驗證、VRAM/相容性風險預算已緊）在這次沒有新的推翻證據——**但本次「甲路線 0/8 全軍覆沒」是裁決那三條理由之後才出現的新事實**，我認為這點值得讓管理者知道、評估要不要重開 3.2 的裁決，但**這是我的建議而不是我可以單方面定案的事** |
| **(e) 放棄自動去背，改人工遮罩** | 由非美術背景的人用一般影像編輯軟體（魔術棒/手動選取）對相對乾淨背景的圖做半自動去背 | 不需要等任何技術修正；對 2002/2003 這類相對乾淨背景的構圖技術門檻低（去背不等於繪畫） | 治標不治本——每張都要人工介入，無法規模化到第二輪 80 張；對 2004 類複雜場景一樣吃力；且本專案目前「美術產出無人擁有」，誰來做這件事是另一個缺口 |

**我的建議排序（僅供參考，最終由管理者/協調者決定）**：先做 (a)+(c) 作為零成本/低成本的
立即動作（(a) 已經會跟著第六節的 prompt 縮短一起做；(c) 可以馬上拿現有 8 張試跑，不必等
新一批生成），再視結果決定要不要投入 (b) 的色票核對工作。(d) 列為「若 (a)(b)(c) 都不夠，
需要重新攤開給管理者的選項」，(e) 列為最後手段。

## 4. 問題四：prompt 遵循度問題（seed 2001 多人構圖、seed 2004 跪姿）

**一句話結論：兩點都屬實（已開全解析度圖確認 2001，2004 的跪姿與城市背景也已確認）；
判斷是 SDXL base 1.0 純文字條件控制的結構性限制，不是單純的措辭問題——但負向提示詞目前
完全沒有針對這兩種失敗畫面類型設防，這是一個便宜、值得先做的局部修正。**

- **seed 2001（A、B 皆然，A 已開全解析度確認）**：確認不是單一角色——是一整張裝備設定圖，
  中央一個穿著全套護具的角色，四周散布約 10 個零件圖示（護目鏡、手套、腰帶、背面/側面
  小人像等），典型的「裝備 turnaround/reference sheet」構圖。這與「single character,
  isolated single character, centered composition」要求直接衝突。
- **seed 2004（A 已開全解析度確認，B 僅縮圖確認）**：確認是單膝跪姿，不是 `standing idle
  pose`；背景是完整的城市天際線場景（B 縮圖看起來是山岩場景），與「no scenery」直接衝突；
  地面/環境上有清楚的陰影與光影過渡，與「no shadow cast on background」「no gradient
  background」也衝突。

**判斷：這是模型的結構性隨機性，不是純粹的措辭問題。** SDXL base 1.0 在這個設定下（無
LoRA、無 ControlNet 姿態導引、無參考圖）對構圖與姿勢沒有硬性保證機制——prompt 寫了
「standing idle pose」只是提高機率，不是鎖定結果。裝備描述越詳細，模型就越可能把它
識別成「裝備設定圖」這個常見的訓練資料類型（與問題三的背景失效是同一種機制：敘事/
類型傾向蓋過字面指令）。**這代表換個說法不能保證完全不再出現這兩種失敗畫面，但可以
降低出現頻率**——降低頻率是現實可以做到的,保證零出現不是純文字條件能做到的。

**具體可做的修正（便宜、不影響正向 prompt 字數預算）**：目前負向提示詞完全沒有排除
「設定圖/多視角/跪姿」這類競爭類型。建議在 `[SPRITE-NEG]` 或 `[COMMON-NEG]` 加入：

```
reference sheet, turnaround sheet, model sheet, multiple views, item icons, equipment grid, inventory grid, orientation chart, kneeling, crouching, sitting, action pose, dynamic lunge, one knee down
```

人工估算約 **198 字元**（含逗號分隔，不含前後連接的 `, `）——**此數字為人工估算，未用
程式精算，正式採用前請務必用程式重新計算一次,不要信任這個手算數字**。原負向 prompt
606 字元，加上這段與一個連接逗號空格，粗估約 806 字元，距離 1000 上限估計還有餘裕，
但同樣需要精算確認。這段文字是**交回協調者/技術總監套用的建議稿**，我沒有直接修改
任何規格檔或 prompt 組裝檔案。

## 5. 問題五：下一步建議（含排序與理由）

**排序（由先到後）**：
