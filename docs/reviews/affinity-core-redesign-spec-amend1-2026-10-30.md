## 1. 戊獨行改為條件式(取代原規格 2.2 的觸發條件)

**規則**:敵方階段戊受擊時,若戊在**剛結束的我方階段**「出過手」,則獨行的**正向部分**關閉;否則照原規格。
```
lone_guard_eff = attacked_last_player_phase ? min(lone_guard, 0) : lone_guard
```
- `lone_guard`(原規格:d_min≥3 → +2;=2 → 0;=1 → −1)**數值不變**。
- **「出手」的精確定義**:戊在該我方階段內,**作為傷害結算的攻擊方**完成過至少一次攻擊結算(`resolve_attack` 路徑;**含**由卡牌觸發、以戊為攻擊方的傷害結算——若此類路徑存在,**未查證**)。
  **不算出手**:只移動、只待機、結束回合、被使用增益/關係類卡牌、戊自己使用不造成傷害的卡牌。取消的攻擊(預覽後取消)不算。
- **貼隊友的 −1 不條件化**:`min(lone_guard, 0)` 保留 −1。理由:這是原有的空間代價,與出手無關;條件化會削弱它。因此出手後 d≥3 → 0、d=2 → 0、d=1 → −1。
- **旗標生命週期**:`attacked_last_player_phase` 在每個我方階段**開始時清為 false**,戊完成一次攻擊結算即設 true,整個敵方階段保持,下個我方階段開始再清。
- **第 1 回合/敵方先手**:正常為我方先手,第 1 回合敵方階段看第 1 回合我方階段。若某關設為**敵方先手**,首個敵方階段**之前沒有我方階段** → 視為 false(未出手,獨行生效)。
- **戊陣亡**:戰鬥已判敗,不需定義。**戊未行動**(跳過):視為未出手,獨行生效。
- **歸屬(跨系統)**:該旗標屬**戰棋戰鬥狀態**,不是好感度系統狀態(好感度系統 R10 無狀態,不得持有)。公式五只接收一個布林參數。旗標寫入須走戰棋的提交入口(`commit_authoritative_change`,ADR-0001),具體時機由實作期確認——**未查證**。
- **預覽**:我方階段戊出手前,預覽須同時列出「若出手:受擊 X / 若不出手:受擊 Y」(creative-director 指出的介面代價)。UI 規格交 `/ux-design`。

## 2. 負向 Φ 改為進位(取代原規格 1.2、1.3)

```
guard(Φ_def) = sign(Φ_def) × ceil(|Φ_def| / 2)      # 正負對稱
```
- Φ=−1 → −1(額外受傷 1,舊為 0);−2 → −1;−3 → −2;−4 → −2。正向不變。
- `GUARD_MIN = −2`、`GUARD_MAX = +3` **不調整**;Φ=−4 本來就 −2,不受影響。
- 新算例:丁(DEF 6)貼近丙、Φ_def=−1,被 ATK 13 打 = 13−6+1 = **8**(舊 7);被 ATK 14 = **9**(舊 8)。
- R6 影響:負向的懲罰在挨打通道首次對 vs01 生效;合作/對立的差距不變(對立遠離仍 Φ=+2 → 減傷 1)。

## 4. 運用臂 score 的設計意見(交 qa-lead 登記)

H2 現行:score = Φ_att(t) + guard_total(t);步驟 1 先保留「能攻擊」的格。對戊,建議用**與遊戲規則同一判準的決策時估法**:
- **步驟 2(候選全為可攻擊格)**:戊必定出手 → 獨行正向視為 **0**;score(戊,t) = (d_min(t)=1 ? −1 : 0)。結果:運用臂在可攻擊時只會避免貼隊友,不再追求獨行 +2。
- **步驟 3(無可攻擊格,戊本回合不出手)**:`lone_guard` 照完整值 +2/0/−1 計入 score。
- 這與管理者「不為好感度放棄攻擊」一致;**運用臂不應為了保住 +2 而主動不出手**(那是新策略,須另行登記,現在不加)。
- 後果須揭露:此估法下運用臂**幾乎用不到**獨行減傷的收益,因此本次重測主要測「甲乙丙丁的減傷」,戊的條件式主要作為對照臂與運用臂共同承受的規則。**無決策期預測誤差**(估法只用當回合已知資訊,不預測敵人)。
- 忽視臂:不計分,但條件式規則自動作用(規則屬遊戲,不屬策略)。
