  🔴 **2026-10-30 已被部分取代**:「完全不提供」不再成立 —— 戊的 `Φ` 仍恆為 0,但他**有承傷側的獨行減傷**(公式五)。上一行的 ⚠️ 現改讀為「**輸出通道**對該角色完全不提供」。

### B2:錨點 B2 之後插入新 bullet(與上下 bullet 同層)
```
- **【2026-10-30 新增】`Φ_def` 的取值時機**:`guard` 用**防守方被攻擊當下所在格**的 `Φ`。預覽(「假如站這裡」)與實際結算走**同一個查詢函式**(承接 UI Requirements 第二條);**不得**以攻擊方回合開始時的快照計算。
- **【新增】防守方是敵方**:`guard = 0`(敵方無關係線、無 Φ);我方攻擊敵方時完全走舊式(只有 `Φ_att`)。
- **【新增】`guard_total` 為負**(`Φ_def<0` 或戊相鄰 `lone_guard=−1`):傷害增加,仍受 `GUARD_MIN` 夾限,且總傷害不超出 `max(0, ...)` 的語意(只可能多,不會出現負傷害)。
- **【新增】`ATK − DEF + Φ_att − guard_total < 0`**:傷害為 0(`max(0,…)`),不回補生命。
- **【新增】`Φ_def` 夾限後極大**(例 +12):`ceil(12/2)=6`,被 `GUARD_MAX` 壓回 +3。與公式三夾限**各自獨立**,先夾 Φ,再算 guard,再夾 `guard_total`,**各只夾一次**。
- **【新增】戊獨行:無存活隊友**:`d_min` 視為「≥3」,`lone_guard=+2`。這是**資料不是錯誤**(其餘四人全倒時戰鬥已判敗,實務上不會發生,但函式須有定義)。
- **【新增】戊獨行:隊友陣亡**:`d_min` **只計存活隊友**;最近隊友陣亡後即時重算,不保留舊值(承接 R5 的「陣亡即失效」精神)。
- **【新增】戊獨行:多位隊友**:取**最近一位**,不逐位加總(避免全隊擠在身邊時重罰);距離為曼哈頓距離(R2)。
- **【新增】非戊單位**:`lone_guard` 恆 0,不論距離。**戊的辨識方式**(單位資料旗標或 id)為實作期決定,**不得以「沒有關係線」推斷**,否則日後無關係線的新角色會意外獲得獨行減傷。
- **【新增】戊被日後加入關係線**:`guard(Φ_def)` 與 `lone_guard` 可同時非零,以 `GUARD_MAX` 夾限;是否仍保留獨行減傷須**重新裁決**,本文件不預設。
```

## C. Tuning Knobs:錨點 C 之後插入

```
### 【2026-10-30 新增】減傷與獨行減傷的旋鈕(公式定義見「公式四」「公式五」,**此處不複述**)

| 旋鈕 | 目前值 | 安全範圍 | 類別 | 調太高 / 太低 |
|---|---|---|---|---|
| `GUARD_MAX`(guard_total 上限) | **+3** | 2 ～ 5 | 曲線 | 太高:Φ 夾限 +12 時敵方傷害趨近 0(`ATK−DEF` 約 5~8,上限 5 已可吃掉七成以上)。太低(<2):`ceil(Φ/2)` 在合作 Φ=+3 的減傷 2 被截斷,減傷通道失效 |
| `GUARD_MIN`(guard_total 下限,額外受傷上限) | **−2** | −3 ～ 0 | 曲線 | 設 0 = 完全不懲罰負 Φ 與戊相鄰(支柱四代價通道關閉,**改動須 creative-director 裁決**)。過低(<−3):單下傷害暴增,配合「一人倒即敗」過於懲罰 |
| `lone_guard`(戊 d_min ≥ 閾值時) | **+2** | 1 ～ 3 | 曲線 | 太高:戊近乎不死,獨行永遠最佳,貼隊無意義。太低(1):診斷中戊被集火致死的現象改善不足(**未驗證**) |
| 獨行距離閾值 | **3**(與 R3「≥3」同形) | 2 ～ 4 | 曲線 | 設 2 = 與隊友隔一格即算獨行(太易觸發);設 4 以上 = 在 13×6 棋盤上難以達成 |
| 相鄰懲罰(戊 d_min=1) | **−1** | −2 ～ 0 | 曲線 | 設 0 = 戊貼隊友無代價(**支柱四審查期間不得自行調整**);過低:戊被排擠在隊外 |
| 減傷係數(`ceil(Φ/2)` 的 1/2) | **1/2,進位** | 固定;改動視為新裁決 | 曲線 | 改 1/1 則 Φ=+3 減傷 3,逼近上限;屬公式結構,不是單純旋鈕 |

- **這些值存放處**:應與 R3 常數同為外部資料(`assets/data/`),不得寫死(專案規則:gameplay 數值資料驅動)。
- **類別**:全部是曲線旋鈕(影響成長/強度形狀);無 feel、gate 旋鈕。
- 🔴 **跨系統校準義務擴大**:原義務(輸出通道 Φ ≥ 敵方 DEF 差距)之外,**承傷通道**須驗 `guard_total` 與敵方 ATK 虛高差距的關係。`docs/registry/architecture.yaml` 的 `phi_curve_enemy_advantage_cross_calibration` 條目已同步登記。**⚠️ 本次未重驗;列為實作期義務。**
- 🔴 **與上方「校準目標」的關係**:該目標(無加成 4 下、有加成 3 下)針對**我方輸出**;`guard` 影響的是「我方被打幾下倒」,**不改變**該目標的語意,但 `AC-FEEL` 的人工試玩須同時記錄承傷體感(見下方 AC-G5)。
- 🔴 **「優先調基礎數值而非加大 Φ」的建議**(上方校準段)仍然有效:`guard` 是 Φ 的第二通道,不是替代基礎數值調整的理由。
```

## D. Acceptance Criteria:錨點 D 之後插入

```
### 【2026-10-30 新增】減傷與獨行減傷(BLOCKING,自動單元測試;敵 ATK / 我方 DEF 為測試內常數,不讀 `assets/data/`)

- **AC-G1(guard 取值表)**:GIVEN `Φ_def` 分別為 +12、+3、+2、+1、0、−1、−2、−4,且無獨行,WHEN 計算 `guard_total`,THEN 依序為 **+3(夾限自 6)、+2、+1、+1(ceil 0.5)、0、0、−1、−2**。
- **AC-G2(傷害算例)**:GIVEN `ATK=14, DEF=8, Φ_att=0`,防守方為我方且 `Φ_def=+3`,WHEN 結算,THEN 傷害 **4**;`Φ_def=0` 時為 **6**;`Φ_def=−2` 時為 **7**。(`Φ_def=+12` 時為 **3**,證明 `GUARD_MAX` 作用。)
- **AC-G3(敵方防守不適用)**:GIVEN 防守方為敵方、我方攻擊 `ATK=16, DEF=6, Φ_att=+3`,WHEN 結算,THEN 傷害 **13**(= 16−6+3,與改動前一致)。若回傳小於 13 代表 guard 誤套到敵方,測試須失敗。
- **AC-G4(敵方攻擊的 Φ_att 仍為 0)**:GIVEN 敵方攻擊我方、`Φ_def=+3`、`ATK=14, DEF=8`,WHEN 結算,THEN 傷害 **4**,**且**傳入的 Φ_att 在破解欄位中為 0(既有「敵方 Φ 歸零」行為不變)。
- **AC-G5(傷害下限)**:GIVEN `ATK=5, DEF=8, Φ_def=+3`,WHEN 結算,THEN 傷害 **0**,不為負。
- **AC-G6(預覽 = 結算)**:GIVEN 任一組上述輸入,WHEN 分別呼叫預覽與實際結算,THEN 兩者傷害**全等**,且預覽的細項回報含 `guard` 欄位。(承接 UI Requirements「預覽與實際結算必須走同一個查詢函式」。)
- **AC-G7(無 RNG)**:GIVEN 相同輸入連續結算 100 次,THEN 輸出恆相同。
- **AC-L1(獨行三檔)**:GIVEN 戊 `DEF=8`、敵 `ATK=14`,戊與最近隊友的曼哈頓距離 `d_min` 分別為 **3、2、1**,WHEN 結算,THEN 傷害依序 **4、6、7**(`lone_guard = +2、0、−1`)。
- **AC-L2(只取最近)**:GIVEN 戊身旁 1 格有 1 位隊友、2 格有 2 位、3 格有 1 位,WHEN 計算 `lone_guard`,THEN 為 **−1**(只看最近一位),且與「僅 1 位隊友相鄰」時**相同**。
- **AC-L3(只計存活)**:GIVEN 戊最近的隊友(距 1)陣亡,WHEN 再次結算,THEN `d_min` 改取次近存活隊友,`lone_guard` 即時隨之改變。
- **AC-L4(無隊友)**:GIVEN 無其他存活我方單位,WHEN 計算,THEN `lone_guard = +2`,不報錯。
- **AC-L5(非戊不適用)**:GIVEN 甲(非戊)與所有隊友距離 ≥3,WHEN 計算,THEN `lone_guard = 0`。
- **AC-L6(不影響攻擊)**:GIVEN 戊攻擊敵人、`d_min≥3`,WHEN 結算,THEN `Φ_att = 0`(戊獨行**不**加攻擊),傷害與改動前相同。
- **AC-L7(曼哈頓距離一致)**:GIVEN 至少 20 組座標,WHEN 以 `d_min` 的距離函式與 `AffinityRules.manhattan_distance` 逐組比對,THEN 全數一致(沿用 AC-R2 的「兩份實作測到一致」精神)。
- **AC-L8(夾限單次)**:GIVEN 假設某單位 `guard(Φ_def)=+3` 且 `lone_guard=+2`,WHEN 計算 `guard_total`,THEN 為 **+3**,不是 +5(`GUARD_MAX` 只夾一次)。
- **AC-G8(資料驅動)**:GIVEN 以注入資料改變 `GUARD_MAX`、`lone_guard`,WHEN 重算 AC-G2/AC-L1,THEN 輸出隨資料改變,程式碼不變(承接 AC-R1)。

### 【2026-10-30 新增】減傷與獨行減傷(ADVISORY,人工試玩;**不阻擋**)

- **AC-GFEEL**:GIVEN 開窗試玩,WHEN 玩家把甲乙貼近,THEN 傷害預覽畫面能指出「減傷 N」的來源(不得只顯示合併後的傷害);戊落單時預覽顯示獨行來源(非空白的 0)。判準:試玩者能口述「為什麼這下比較不痛」。
- **AC-GFEEL-2**:GIVEN 同批試玩紀錄,THEN 附上我方「被打幾下倒」的實測次數,與 `design/quick-specs/unit-stats-provisional.md` 加註表的推估值對照(推估為 **算術未驗證**)。headless 取不到像素,UI 項須開窗驗證。
```
