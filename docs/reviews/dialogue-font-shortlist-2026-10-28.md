## 二、向量字型字級規則提案(非最終)

### 與 HUD 點陣規則的根本差異

| | HUD(Cubic 11) | 對話正文(向量) |
|---|---|---|
| 公式 | `11 × N`,N 來自 `compute_scale()` | 不需要整數倍;可任意 px |
| 為什麼 | 11×11 點陣,非整數倍會糊 | 向量字型可連續縮放 |
| 風險方向 | 掉檔(1366×768 只有 N=2) | **太小讀不到**,與太大擠爆對話框 |

### 提案公式

> **正文字級 px = max(24, round(螢幕高 ÷ 30))**,取偶數(round 後向下取偶,避免奇數 px 對齊半像素)。

要與 HUD 規則一致的一點:**螢幕高取當下實際解析度**(同基準畫布決策),且仍不得在對話畫面自行複製 `compute_scale()`;
本提案**不用 N**,所以不新增第二份倍率公式 —— 只用螢幕高。(實作由 godot-specialist 決定放哪。)

| 螢幕 | 算式 | 字級 | 佔螢幕高 | 對照 HUD |
|---|---|---|---|---|
| 1366×768 | 768÷30 = 25.6 → 26(偶數) | 26px | 3.39% | HUD 22px(2.86%),正文略大於 HUD |
| 1920×1080 | 1080÷30 = 36 | 36px | 3.33% | HUD 44px |
| 2560×1440 | 1440÷30 = 48 | 48px | 3.33% | HUD 55px |
| 3840×2160 | 2160÷30 = 72 | 72px | 3.33% | HUD 88px |
| 960×540(最小視窗) | 540÷30 = 18 → 受下限 24 | 24px | 4.44% | HUD 22px |

- **為什麼比例約 3.3%**:HUD 規則在主流螢幕是 3.67%~4.07%;正文是大段文字,通常比短標籤小一檔,但不可低於 HUD 的 ~80%(3.3% ÷ 4.07% ≈ 82%)。此為**設計推理(C 級),非實測**。
- **最小可讀字級 24px 的依據**:一般經驗是 CJK 內文在 1080p 約 ≥ 28px 才舒適、24px 是勉強底線,筆畫多字(體/識/籲)在 24px 以下易糊(**未驗證**,為業界經驗法則)。**最終數字必須由探針在 1366×768 實看後決定**,尤其候選 A(楷體)可能需要更高下限(如 28px)。
- **對話框容納量**是這條規則的另一半:字級放大則每行字數變少。需另算「每行字數 × 行數」是否塞得進疊在棋盤上的半透明對話框(螢幕架構硬性約束:不可佔用側邊固定欄位)。**這一半尚未估算**,交 ux-designer/godot-specialist。
- **不得做的事**:字級不取整數倍的好處不要用壞 —— 向量字型須開啟抗鋸齒、**不得**在像素描邊的世界層 SubViewport 內渲染(世界層是 nearest 放大,文字會變硬邊;介面層 CanvasLayer 才對)。

## 三、管理者回家怎麼比較(一次看完)

建議做一支**探針畫面**(由 godot-specialist 做;**這裡只規定顯示什麼**,不是實作規格):

1. **同一段對話文字**,三種字型各渲染一次,並排(或上下三塊):
   - 內含必測字:「體 識 籲 鬱 龜 驟 灣 戀」,加標點「,。!?「」…——」,加一行半形數字與英文(如 `HP 12 / 30`)。
   - 一段約 40~60 字、兩行的敘事對話(含一句短感嘆句),貼近真實戰棋劇情語氣。
2. **疊在實際戰鬥棋盤畫面上方**(半透明對話框),不是純白底 —— 因為真實閱讀環境是在像素世界上方。
3. **四個解析度**各一張畫面或可切換:1366×768、1920×1080、2560×1440、3840×2160;字級依本檔第二節公式。
4. 同畫面再放一個 HUD(Cubic 11)標籤,讓他看「像素 HUD 字 + 向量正文」的搭配。
5. 提供鍵盤切換字型與兩檔字級(公式值、公式值 +4px),讓他自己選最舒服的字級。
6. 輸出方式:**家中機器開窗跑**(他在公司看不了),並存四個解析度的截圖到 `production/qa/evidence/`,
   截圖須人眼確認(專案 Check 5);他回家只需看截圖或直接執行。
7. 記錄每個字型缺字數(跑完必測字清單 + 常用字清單,缺字應為 0)與載入耗時,附原始 log。

## 四、推薦與理由

**推薦 A 為主候選預期、B 為保底、C 當中性基準;但在看過探針畫面前不鎖定。**

排序理由:
1. **氣氛**:本作是敘事重的戰棋(好感度對話、permadeath 情感重量),楷體對「人聲」的表現力最高,
   與像素世界形成最鮮明、且有意圖的對比。
2. **A 的唯一硬風險是小字級易讀性**,而它**可以用探針直接驗證**(1366×768 的 26px 是最壞情況);
   驗不過就退到 B(圓體,易讀性好)或 C。
3. 若管理者重視功能文字清晰度勝過氣氛,則 C 最穩;B 是兩者折衷,但圓角風格若與戰鬥肅殺感違和就該排除。

**需要管理者決定的事(依序)**:
1. 三套中選哪一套(或要求補 Noto Sans TC 比較)—— 看過探針截圖後。
2. 是否接受向量正文字級以「螢幕高 ÷ 30、下限 24px」為起點(最終數字看探針)。
3. 在意不在意 HK 字形與台灣標準字形的差異(只影響是否排除 C)。
4. 授權與檔案大小在**納入前**由專家驗證(本檔未驗證項),通過才下載進版控。

**未驗證清單(納入前必查)**:三套的檔案大小、字元涵蓋(必測字)、授權全文與 RFN 宣告、是否為可變字型、Godot 4.7.1 載入與渲染表現。
