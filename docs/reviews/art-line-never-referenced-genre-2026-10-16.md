## 二、🔴 根因比「忘了寫」更具體:調性方向從來不存在

`design/art/art-direction.md` 第 1 行標題是「**美術方向:像素風硬參數**」,
而它自述的權威範圍是「**畫布尺寸、色盤、描邊、字型**」。

**它是一份技術規格,不是調性方向。而調性方向從來沒有任何文件寫過。**

**所以美術線不是違反了規格 —— 是它要遵守的那份規格不存在。**
整條線在優化「32×40 的剪影辨識度」,而沒有任何人檢查過調性。

### 連帶:選了一個動漫底模,而且那是刻意的

2026-10-13 為了解決「源頭畫風(連續漸層厚塗)與目標(扁平 cel-shade)不相容」,
管理者裁決換底模為 `cagliostrolab/animagine-xl-3.1`。

🔴 **`animagine` 是動漫模型。** 而實際送出的 prompt 開頭是:
```
masterpiece, best quality, very aesthetic, absurdres, safe, 1girl, solo, ...
```
`1girl` / `very aesthetic` / `masterpiece` **是 danbooru 動漫標籤。**

**「太動漫」不是偏差,是那個模型與那組標籤的設計目的。**
而換底模那次的裁決**只處理了「扁不扁平」,沒有處理「像不像動漫」** ——
因為當時沒有任何文件說它該像什麼。

## 三、管理者 2026-10-16 裁決:**只改立繪,棋子維持像素**

**選項逐字**:「**只改立繪,棋子維持像素**」。
**被跳過的三個**:先補調性文件不動像素規格 / 推翻像素風改做寫實 / 先別動只登記。

**內容**:角色立繪(支援對話用)改為寫實風、**不受 128×128 限制**;
棋盤上的棋子(32×40)**維持像素**。

### 🔴 這個裁決解決了【媒材】,但沒有解決【調性】—— 協調者當場向管理者指出

**「維持像素」不等於「維持動漫」。**

今天產的 3 張(`20261016-001/002/003`)的 `asset_category` 是 **`sprite`**(棋子),
而**動漫的頭身比與臉型會原封不動活過降採樣** —— 32×40 照樣讀得出是動漫臉。

而管理者的原話是「希望**都**寫實一點」。

📌 **所以合理的讀法是**:**媒材上棋子維持像素,但調性上兩者都要離開動漫。**
🔴 **這個讀法是協調者的,尚未經管理者確認。** 下一個人請先確認再據以行動。
