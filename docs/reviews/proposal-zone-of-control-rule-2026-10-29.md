## 一、白話摘要

管理者 10/28 試玩後要求「敵人不能穿過我方角色走」。程式的做法是:**敵方單位只要走進我方任何一名
存活角色「正上、正下、正左、正右」的緊鄰格,就必須在那一格停下,不能從那格繼續往外走。**
這等於每個我方角色周圍有一圈「減速帶」,敵人可以踏上去、但踏上去就不能再走。我方單位完全不受
這條規則影響。

**設計文件現在完全沒寫這條。** 更嚴重的是:設計文件現有的兩處條文
(移動規則、驗收條件 AC-2)寫的是「只有『被佔位的格子』擋路」,**讀文件的人會得出與程式不同的
可達範圍**,日後若有人依文件改程式或寫測試,會把這條規則改掉而不知道。

## 三、可貼進 GDD 的條文草稿

> 以下為草稿,措辭沿用該 GDD 的格式。**括號內「(來源)」只是給審閱者看,貼入時依專案規則改成指向正式出處,不要複製行號。**

### 3.1 Core Rules 新增一條(建議編號:接在 #2「移動規則」之後,或作為 #2 的子項)

> **阻擋規則(2026-10-28 管理者試玩裁決)**:**敵方**單位的移動,在「佔位格不可穿越」之外,另受下列限制:
> 1. **阻擋區**:任一**存活**我方單位的**正上、正下、正左、正右**四格(僅限棋盤範圍內;斜角格不算)構成阻擋區。
> 2. **可進入、不可穿越**:敵方單位可以移動**進入**阻擋區內的格子並停在該格,但**不得從阻擋區內的格子繼續移動到其他格子**。進入阻擋格仍照常消耗該格地形成本。
> 3. **起點例外**:敵方單位若在本回合開始時已位於阻擋區內,**可以**自該起點正常離開(起點不受第 2 條限制);限制只套用於移動途中新進入的格子。
> 4. **我方單位不受此規則限制**(單向規則)。
> 5. 陣亡的我方單位不產生阻擋區(沿用「陣亡單位不再參與任何後續計算」)。
> 6. 阻擋區**不取代**既有的佔位規則:佔位格仍不可穿越(不分敵我)。

### 3.2 Formulas:公式三(可達格範圍)補一個參數

沿用本 GDD 公式三的格式(下列變數表補進該節既有的變數表):

- 擴充表達式:`accumulated_cost(origin, t)` 的合法路徑額外要求——**路徑上除終點與起點外的每一個中繼格 `m`,皆滿足 `m ∉ stop_set`**。(即阻擋格只能當終點,不能當中繼。)
- 注意:程式實作是「到達阻擋格後不再從它展開」,與上式等價(阻擋格可作為終點、不可作為中繼)。**此等價性是依程式結構推導,未用窮盡測試驗證**(見第五節)。

| Symbol | Type | Range | Description |
|--------|------|-------|-------------|
| `stop_set` | 格座標集合 | 0 ~ 4×(我方存活單位數) 格,去重後更少 | 阻擋區:我方存活單位四向緊鄰且在棋盤內的格子;查詢單位為我方時恆為空集合 |
| `origin` | 格座標 | 棋盤內 | 起點;即使 `origin ∈ stop_set` 也可離開 |
| `t` | 格座標 | 棋盤內 | 目標格;`t ∈ stop_set` 時可達(只要成本與其他條件滿足) |

- **輸出範圍**:`reachable_set` 的子集合關係不變(只會比無阻擋區時小或相等),`origin` 仍不在回傳集合內(程式回傳不含起點;此點與 GDD 公式三「至少含 `{origin}`」的措辭是否一致,見 3.4 衝突 C)。
- **範例**(取自測試):開放地形,`origin=(0,0)`,`MP=3`,`stop_set={(1,0)}` → `(1,0)` 可達;`(2,0)` 不可達(只能經 `(1,0)` 兩步到達,繞路需 4 步 > 3)。無 `stop_set` 時 `(2,0)` 可達。

### 3.3 Edge Cases 新增

| 情況 | 結果 | 理由 |
|---|---|---|
| 敵人開場就在我方單位緊鄰格 | 可離開,不會動彈不得 | 起點例外(程式註解明講的理由) |
| 兩名我方單位的阻擋區重疊 | 重疊格視為同一個阻擋格,效果不疊加 | 字典去重(程式以 Dictionary 儲存) |
| 敵人要通過的唯一走廊兩側都有我方單位 | 走廊上緊鄰我方的格子都是阻擋格;敵人最遠只能走到第一個阻擋格 | 由規則 2 直接推得;**未有測試涵蓋此情境** |
| 我方單位在途中陣亡 | 下一次查詢起,其阻擋區消失 | `units_of()` 只含存活單位;**敵方回合中途陣亡是否即時反映,未查證** |
| 阻擋格上有其他單位佔位 | 照既有佔位規則,不可進入 | 規則 6 |

### 3.4 與既有條文的衝突(要一併改,否則文件自相矛盾)

| 衝突 | 既有條文 | 問題 | 建議 |
|---|---|---|---|
| **A** | Core Rules #2「移動規則」整段:「可達格集合…路徑不得穿越…已被單位佔據的格子」 | 沒提阻擋區;字面上敵人的可達集合比程式大 | 在該條末尾加一句指向新規則 |
| **B** | 公式三的 `accumulated_cost` 定義與 Edge Cases 表、AC-2(可達格驗收條件)的「路徑不穿越任何佔位格」 | 同 A;AC-2 照字面測敵方單位會**與程式不符** | AC-2 條件加「查詢單位為敵方時另受阻擋規則」,並見 3.5 |
| **C** | 公式三寫「origin 恆在集合中(至少含 `{origin}`)」,程式 `reachable_tiles` 回傳**不含**起點(`if pos != origin`) | **這是既有的文字/程式差異,與阻擋規則無關**,但本提案的起點例外會讓人更需要弄清楚 | 另案;本提案只標記,**未查證 GDD 是否已在別處說明此差異**(BattleController 註解顯示呼叫端自己補起點) |
| **D** | 威脅範圍(公式四)與其「佔位軸偏樂觀」的揭露義務 | 阻擋規則讓敵方威脅範圍**變小**(敵人少走幾格),且與佔位那條同方向:玩家看到的威脅圈是「依當下盤面」的估計。理論上同樣屬「不得宣稱絕對安全」的範圍 | 在公式四揭露段補一句,不新增義務 |
