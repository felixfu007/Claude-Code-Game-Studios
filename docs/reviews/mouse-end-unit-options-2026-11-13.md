## 二、方案

共同前提:右鍵 = 取消選取(2026-10-28 試玩回饋)不可動;介面不得依賴棋盤旁空位,只能疊在棋盤上。

### 方案 A:HUD 常駐「結束行動」按鈕(與「手牌」「選單」並排)
- 步數:選單位後 1 次點擊(單位已選 → 點按鈕)。
- 與右鍵衝突:無。
- 裝置一致:鍵盤 Q / 手把 Back 保留;按鈕本身可被游標/手把焦點到(現有兩顆按鈕已是此模式),三裝置皆同一入口。
- 畫面空間:多一顆按鈕,需與既有兩顆在 480x270 基準與 1366x768 等「掉檔」解析度下並排不遮棋盤;疊放在棋盤上要確認不擋單位。
- 規模:小到中(粗估 1 個按鈕 + 狀態可用/灰化 + 文字進在地化 + 版面測試;**未驗證**)。
- 優:最好發現(affordance 明確,符合 no hover-only);步數最少。缺:無單位選取時按鈕常駐但無用,需灰化並說明原因(不能只靠顏色);誤觸成本低(只結束單一單位,可接受)。

### 方案 B:選取單位後出現「單位動作選單」,內含「結束行動」
- 步數:選單位後 2 次(開選單、點項目);若選單隨選取自動彈出則 1 次,但會擋棋盤。
- 與右鍵衝突:需定義右鍵先關選單、再取消選取(兩層取消),增加心智負擔。
- 裝置一致:良好(選單原生列表,手把天然適用),但鍵盤 Q 一鍵直達與選單路徑步數不對等。
- 畫面空間:浮動選單要跟單位走、避開邊緣,為三案中版面最複雜。
- 規模:大(新元件 + 定位 + 兩層取消 + 測試;**未驗證**),且與現有「選單」(整個陣營結束在選單內,見 battle-menu 設計)語意容易混淆。
- 優:可日後擴充其他單位動作;缺:現階段只有一項,過度設計。

### 方案 C:點已選單位自身 = 結束行動
- 步數:1 次,無新 UI。
- 與右鍵衝突:無,但**與現有左鍵點已選單位的行為衝突**(推測目前是取消選取,未驗證),改掉等於改既有行為。
- 裝置一致:手把/鍵盤無對應手勢,只對滑鼠存在,違反對等原則的精神(雖然別的裝置有 Q)。
- 畫面空間:零。
- 規模:小,但風險在行為改動。
- 優:零 UI 成本;缺:無任何提示(不可發現),誤觸風險最高(想取消選取卻結束了單位,不可逆),新手看不到。**不建議。**

## 三、推薦

**推薦方案 A**。理由:可發現性最高、步數最少、不動右鍵與左鍵既有語意,且沿用現有 HUD 按鈕模式與三裝置焦點機制;成本最低的是 C,但它用隱藏手勢換掉可逆性,與「誤觸不白白浪費」的專案立場(battle-menu 設計裁示)相反。建議附帶要求:無選取單位時按鈕灰化並以文字/形狀(非僅顏色)表明不可用;提示列(story-045)在滑鼠狀態補上按鈕說明。決定權在管理者。

## 四、結束畫面(勝敗 3 秒)空白底條

事實:`_fail_load`(3576 行)會隱藏 `_controls_hint_bg`,但結束畫面路徑沒有同樣處理(已 grep `_controls_hint_bg.` 全檔只有此一處賦值);提示列文字由 `_refresh_controls_hint` 以狀態產生,結束狀態為空字串。

建議:**隱藏**。理由:空底條無資訊、像是壞掉的 UI;結束 3 秒內玩家不需操作提示;隱藏還能讓勝敗橫幅/畫面更乾淨。實作上跟 `_fail_load` 同樣用 `visible = false`,離開結束狀態(重開局)要記得恢復,否則下一場提示列消失(**此處為最易漏的邊緣情況**)。若管理者想保留底條作為畫面一致的「版面邊界」,那是視覺風格判斷,**交 art-director**;從 UX 觀點隱藏較好,無無障礙影響。

## 六、管理者四問:現況事實與建議(2026-11-13 追加)

標記:【確定】= 讀碼所得;【推測】= 未實測。全部為讀碼,未開遊戲驗證畫面。

### 問 1:選了角色後按右鍵會怎樣
事實:
- 【確定】右鍵 → `battle_cancel`(`battle_screen.gd:3627-3628`);已選單位時走 2658-2661 行 `_controller.deselect()`,只清掉「目前選取」,**不改任何行動旗標**(`battle_controller.gd:766-769`、`_clear_selection_internal` 1223 行)。
- 【確定】取消後單位「還能不能再選」只看一件事:是否已全部做完(`_select_unit_internal`,1213 行 `if _order.is_done(id): return false`)。**只移動過或只攻擊過的單位可以再選;移動+攻擊都做完(或被結束)的單位不能再選。**
- 【確定】注意:右鍵取消**不會**把已用掉的移動還原,也沒有「復原移動」。
建議:現況合理;但「已移動未攻擊單位按右鍵會取消選取、而不是復原」對新手可能出乎意料,提示列(story-045)可在已選單位狀態補一句「右鍵=取消選取(動作不會復原)」。

### 問 2、3:已移動 / 已攻擊 / 兩者皆完成,玩家現在看到什麼
事實:
- 【確定】棋子右上角有兩個小方塊(`board_view.gd:1422-1453`):左=移動、右=攻擊;**實心=已用掉、空心框=還沒用**。
  - 皆未用:兩個空心;只移動過:左實心右空心;只攻擊過:左空心右實心;全做完:兩個都實心(1433-1436 行註解)。
- 【確定】點到該格看資訊卡,會有一行「狀態:…」,四種字樣:`皆未用` / `只剩攻擊` / `只剩移動` / `已行動`(`strings.csv:80-85`,對應 `battle_screen.gd:3141-3152`)。攻擊被拒時另有原因行(行動已用、射程外、太近、視線被擋,3078-3087 行)。
- 【確定】方塊顏色統一為近白(`ACTION_FLAG_PIP_COLOR`,416 行),**以實心/空心而非顏色區分**,通過「不只靠顏色」。方塊只有 5 像素(`ACTION_FLAG_PIP_SIZE`,407 行,基準 480x270)。
- 【推測/未見證據】全做完的單位在棋盤上**有沒有變暗/灰化**:我在 `board_view.gd` 的 modulate 搜尋只看到移動框與威脅條紋染色,沒看到「已完成變暗」,故推測沒有。
建議(簡短):(1) 5 像素實心/空心對遠視或快速掃視不易辨識,且玩家不一定知道「左移右攻」,建議全做完的棋子加一個更明顯的整體提示(例如變暗或加小勾,形狀非顏色,樣式交 art-director);(2) 第一次出現時用提示列說明兩個方塊含意;(3) 這也直接影響「結束行動」的需求:只要「只移動過」單位的右上看得出還能攻擊,玩家才知道該不該按結束。

### 問 4:選了角色後再點同一角色
事實(讀到底,`battle_controller.gd:790-814`):
- 【確定】**不會取消選取**。我先前推測「點自身=取消」是錯的,以此更正。
- 【確定】若該單位**還能移動**:點自己 = **原地移動**(用掉移動旗標、位置不變,800-801 行,2026-10-28 試玩回饋加的)。
- 【確定】若該單位**已移動過、還能攻擊**:800 行條件不成立,往下 802 行變成「重新選取」同一單位,**結果是什麼都沒變**(沒有任何回饋,也不會結束行動)。
- 【確定】只有點到「不是自己、也不是可移動/可攻擊目標」的空處,才會 `&"deselected"`(806-812 行)。
建議:(1) 這使方案 C(點自己=結束)直接不可行:點自己已被「原地移動」佔用,**撤回方案 C**;(2) 「已移動過再點自己毫無反應」是無回饋的死點擊,建議至少給提示列/音效說明「已移動,可攻擊或結束行動」;(3) 原地移動一點就用掉移動,新手易誤觸,可考慮需明確預覽(現已有移動預覽標示自己的格子,見 `_is_move_preview_cell`),此項屬玩法層,交 game-designer 判斷。

### 對原推薦的影響
方案 A(結束行動按鈕)不受影響,反而更有理由:「只剩攻擊 / 只剩移動」是常態,玩家必須有明確的「我不做了」出口。方案 C 撤回,只剩 A、B。
