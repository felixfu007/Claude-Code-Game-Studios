## 1. Overview

好感度—位置連鎖系統把「角色之間的關係」變成「棋盤上的空間戰術」。

**玩家面**:每位主角與特定同伴之間存在正向或負向關係,以綠線/紅線畫在棋盤上。把互相信任的兩人排在一起,雙方變強;把彼此對立的兩人擠在一起,雙方變弱。玩家移動游標時就看得到這個變化,**不必先下手才知道結果**。

**系統面**:本系統對「某個單位站在某一格」這個提問,回覆一個**帶號整數 `Φ`**,進入戰棋移動與交戰系統的傷害公式(攻擊方 `Φ_att` 為輸出通道;防守方 `Φ_def` 經公式四換成承傷減傷 `guard`)。另有戊的騎牆規則(公式五)。本系統無狀態、無隨機、不寫入任何資料 —— 只把「誰站在哪裡、誰與誰有什麼關係」翻譯成數字。

**為什麼必須存在**:戰鬥結算沒有任何隨機性,敵方數值又固定高於我方(`enemy_advantage_pct`,目前 0.20)。**好感度佈局是玩家抵銷數值劣勢的主要手段**,少了它戰鬥退化成純比數值而我方必敗。

> 「`Φ` 是傷害公式唯一與站位有關的項」這句不成立(2026-08-31 移除「唯一」):站位另經 `guard`(承傷)與戊的騎牆項進入傷害。上游 `tactical-combat-system.md` 須同步限定(原 OQ-5,已執行)。

**範圍涵蓋陣亡處理**:單位陣亡或離場後,連到它的關係線如何失效、其餘單位的 `Φ` 如何隨之改變,屬本系統職責。

## 2. Player Fantasy

**目標感受:「我不是靠運氣贏的,是靠我把人擺對位置。」**

服務的是**理解帶來的力量感**。玩家一開始只看到幾條彩色的線,像裝飾;某場戰鬥中他發現把甲挪到乙旁邊,傷害預覽從 4 跳到 7,那一擊剛好夠殺掉原本殺不掉的敵人。**那個瞬間,關係線從裝飾變成資源。**

**關鍵時刻**:游標移到某一格,畫面同時告訴他「走到這裡,你會多打 3 點,但丙會因為靠近丁而少 1 點」。他在**下手之前**就知道全部後果 —— 這是零隨機承諾在好感度層的兌現。**玩家的失敗永遠是判斷失誤,不是運氣不好。**

**反面感受(必須避免)**:

- **「我不知道為什麼變強了」** —— 數字變了卻看不出是哪條關係造成的,本系統退化成隱形難度調節器,支柱二在回饋層失效。
- 🔴 **「線是假的」** —— 畫面顯示的關係狀態與實際生效的不一致。**一次都不能發生**:玩家一旦發現畫面會騙人,零隨機承諾建立的信任一起失效。(舊實作的抑制邏輯確實會讓同一條線在甲、丙帳上不一致;R4 取消抑制後已根除,R8 將該性質明文化為契約。)

**與敘事的連結**:這些關係是角色之間真實的信任與嫌隙。玩家為了戰術把兩人排在一起,同時也是在**選擇讓誰陪著誰**。戰術最佳解與情感偏好可以衝突 —— 那個衝突正是本作想讓玩家感覺到的重量。

## 3. Detailed Rules

### 3.1 Core Rules

**R1. 關係表是資料,不是規則。**【既有行為】誰與誰有關係、正向或負向、強度多少,**不由本節定義**,本節只定義曲線與疊加。權威資料來源是上游即時查詢(3.3 ①);靜態檔 `vs01_affinity_links.txt` 僅為垂直切片暫代品,與 ① 衝突時一律以 ① 為準。

**R2. 距離一律用曼哈頓距離**,與戰鬥射程判定採用相同定義。【既有行為】實測(2026-08-31)是**兩份獨立實作**(`affinity_rules.gd` 的 `manhattan_distance` 與 `combat_rules.gd` 的 `_manhattan_distance`),只是今天答案一致;黑箱比對**無法區分「共用同一函式」與「兩份碰巧一致」**。【裁決 2026-08-31】允許兩份實作,但必須測到一致(合併會讓 Gameplay 橫向耦合戰鬥模組,收益低於成本)。見 AC-R2。

**R3. 距離—數值曲線**【既有行為,2026-08-31 確認採用】

| 距離 | 正向關係 | 負向關係 |
|---|---|---|
| 1(相鄰) | **+3** | **−1** |
| 2 | 0 | 0 |
| ≥3 | **−1** | **+2** |

距離 2 是**刻意的死區**:靠近與遠離都必須是明確的選擇,不存在「稍微靠一點」的漸進收益。距離 0 不會發生(棋盤禁止同格,有落地機制)。`≥3` 是一整段,不是遞增門檻。

**R4. 疊加:所有關係線全部生效,逐條加總,不存在任何抑制機制。**【裁決 2026-08-31,推翻既有行為】一個單位身上每條關係線,無論正負、幾條,各自依 R3 算出數值後全部相加。*理由*:本作結局結構建立在「大家聚在一起」與「疏離一個人」兩極之上(`endings.md` 第 3 節,2026-08-26 裁決 D22);唯有逐條加總,走向某一極的程度才轉化為戰力差異。若只取最近一條,走一步與走到底同樣強,選擇就是假的。

**R5. 「犧牲一人」是 R4 的直接後果,不需另外設計。**【裁決 2026-08-31】被多人負向連著的角色留在隊伍中,讓每個關係人各自承擔 −1;排除他則團隊解除負擔,而他自己失去所有正向鄰接、每條正向線承擔 −1。這個取捨是機制自動長出來的,不是腳本事件。

**R6. 兩條路線的戰力不對等,且是刻意的。**【裁決 2026-08-31】合作(相鄰正向)每條 **+3**;對立(遠離負向)每條 **+2**,合作上限比對立高約 50%。加上承傷通道(公式四)後,合作單條 Φ=+3 對應減傷 2、對立單條 Φ=+2 對應減傷 1,**兩路線差距擴大為約 100%**(【裁決 2026-10-30】;輸出通道的 +3/+2 與 50% 設計意圖仍有效,R3 四個常數未動)。
- *理由*:「拒絕互相掩護」換得不必背負他人,**戰術上付出代價是這個選擇的重量本身**。⚠️ 差距是明文設計,非抄襲原型的巧合;**調整 R3 任一數值前必須連同本條重新裁決。**
- ✅ **實機量測(2026-08-31,OQ-7 結案):對立路線在輸出通道的代價「只有」帳面 50%,沒有隱藏的第二層。** 以 vs01 真實棋盤(13×6,**全部 78 格皆可通行** —— `board.gd` 的 `MOVE_COST` 沒有「不可通行」概念,`#` 是倒木、成本 3、可走、只擋視線)窮舉:最嚴苛情況(近戰須貼敵)下,全部 **15** 個可攻擊站位中,最少仍有 **61 格**可供夥伴站在距離 ≥3 處(最多只需 4 格);最壞情況下仍有 **9 格**可讓近戰夥伴、**28 格**可讓遠程夥伴同時攻擊。標 (A) 級,自述以 headless spike 直接呼叫 `Board.from_ascii()`、`Board.blocks_sight()`、`AffinityRules.manhattan_distance()`、`CombatRules.is_attack_legal()`、未重新實作規則(完整數字見 `design/gdd/reviews/affinity-position-chain-review-log.md`)。⚠️ **未計入移動力(MP)**,只會讓可行性變差、不會讓結論反向。
- 🔴 調數值時要知道:輸出通道兩路線差距就是帳面那 50%,不多也不少;若誤信「還有隱藏代價」會過度補償 +2。

**R7. `Φ` 的上下界完全由硬性夾限決定,沒有第二道機制。**【裁決 2026-08-31】單一角色的關係線數量**不設上限**(管理者裁決:不限制敘事),故**線數不約束 `Φ`,夾限是唯一的邊界,且會在正常遊玩中真的作用**(第 5 條線起合法佈局就可能觸發)。推導與反例見公式二。**修改夾限值即修改戰力上下限本身。** (舊「結構層+保險絲層兩道」是錯的:棋盤只約束最多幾人能**相鄰**,不約束一角色有**幾條線**,後者是資料基數不是拓樸。)

**R8. 每條關係線對其兩端同時生效,且雙方看到的狀態必然一致。**【裁決 2026-08-31】不存在「這條線對甲生效、對乙不生效」。R4 取消抑制後視角不對稱在數學上已不可能發生;本條把該性質明文化為契約,防止日後以任何形式重新引入單邊抑制而破壞「線不會騙人」。

**R9. 陣亡或離場的單位,連同其所有關係線一併失效。**【既有行為,已驗證】實作為「從位置表整條移除」而非設旗標;任何一條線只要有一端不在場,該線不計。**位置快照必須每次重新讀取,不得快取** —— 陳舊快照會讓屍體以生前位置繼續提供加成。

**R10. 本系統無狀態、無隨機、不寫入任何資料。**【既有行為】純查詢:給定「誰在哪裡」(與當下關係狀態),回覆帶號整數。符合專案級禁令 `rng_in_combat_settlement`。

**R11. 戊的規則不在本節。** 戊(麥子健)與其餘四人各有一組配對,與其他九組用**同一套** `S ∈ {NONE, POS, NEG}` 判定、不看名字,因此他**可以有關係線、有 Φ**。他專屬的騎牆(獨行減傷與留一手)的**唯一定義處是公式五**。【裁決 2026-11-12 / 2026-11-17】

> R4/R7/R8 對實作的變更已於 2026-08-31 落地(提交 `f8d1241`):`SUPPRESSED` 狀態已刪除;`bonus_for()` 結尾 `clampi(total, PHI_MIN, PHI_MAX)`;`affinity_link.gd` 對超出值域的 `amp` 有 `push_warning()`;4 條舊測試是**刪除重寫**(測試名即被推翻的行為),替代品為 AC-R4a/R4b/R7/R7b/MIX。逐檔清單見該審查紀錄第一輪條目。

### 3.2 States and Transitions

**本系統本身沒有狀態**(R10)。可觀察狀態屬於**每一條關係線**,完全由當下位置推導,不儲存、不記憶:**正向/負向 × 緊鄰/死區/疏遠**六種,外加「失效」(任一端不在場,整條不計,R9)。各狀態數值**一律以 R3 為準**,此處不複製(曾有一張與 R3 逐格重複的表,是純粹的漂移面)。

**轉換沒有事件,只有重新求值。** 任何移動、陣亡或極性變化後,下一次查詢自然反映新狀態;不存在「轉換中」,也沒有延遲生效。極性本身可在戰役中改變(來源見 3.3),本系統不記憶歷史,永遠只反映查詢當下。

## 4. Formulas

### 公式一:`Φ` 的計算

`Φ(u, o) = clamp( Σᵢ ampᵢ × B(polarityᵢ, dᵢ) , Φ_min, Φ_max )`,其中 `dᵢ = manhattan(o, pos(partnerᵢ))`,`B` 為 R3 曲線。

| 符號 | 型別 | 值域 | 說明 |
|---|---|---|---|
| `u` | int | 名冊 id | 受查詢單位;可為假設站位的預判查詢 |
| `o` | Vector2i | 棋盤合法格 | 「假如站在這裡」 |
| `k(u)` | int | **0 ～ 無上限** | **雙端皆在場**的生效線數;任一端離場即不計(R9) |
| `ampᵢ` | int | **恆為 1** | 權威來源見 3.3 ①,不是本表 |
| `dᵢ` | int | 1 ～ 棋盤最大值 | 每次查詢即時算,**不快取** |
| `B` | int | `{−1, 0, +2, +3}` | R3 曲線 |
| `Φ` | int | **−4 ～ +12** | 夾限後輸出;夾限前原始和**兩個方向皆無界**(公式二) |

算例(vs01 起始佈陣):甲(0,2)、乙(0,3) 正向相鄰,距離 1 → `Φ(甲) = +3`;甲攻擊 E1(`ATK=16`、`DEF=10`):`max(0, 16−10+3) = 9`,未相鄰(`Φ=0`)則為 `6`,**站位差 3 點、佔基礎傷害 50%**。丙(1,3)、丁(0,4) 負向、距離 2 → 死區 → `Φ=0`;丙移至距丁 ≥3 → `Φ=+2`。

### 公式二:關係線數量不設上限,`Φ` 因此無界 —— 夾限存在的理由

【裁決 2026-08-31】每角色關係線數量不設限(不讓數值設計限制敘事)。**幾何只約束「相鄰」**:距離恰為 1 的格子恰有 4 個(`|dx|+|dy|=1` 只有 4 組整數解),故正向緊鄰貢獻飽和於 4×(+3) = +12。但**距離 ≥3 的格子不稀缺** —— 負向疏遠每條 +2(向上無界)、正向疏遠每條 −1(向下無界)。**反例(已複算)**:四條正向緊鄰(+12)+ 一條**負向**距 ≥3(+2)= 原始和 **+14**,超出 `Φ_max`;這是合法佈局,不是資料錯誤。

> ⚠️ 舊推導「`N=4`,第 5 條線起只能停在死區」只在第 5 條與前 4 條**同極性**時成立,而 R4 禁止該假設;且其引用 `board.gd` 的 `_get_orthogonal_neighbors()` 為證是錯的 ——「距離 1 恰有四格」是 L1 度量本身的性質,`affinity_rules.gd` 對 `Board` 零引用。**想重新驗證線數上限而去看 `board.gd`,是在查錯的東西。**

### 公式三:夾限值 `Φ_min = −4`、`Φ_max = +12`

線數不設限後,夾限是**唯一擋住數值的東西**,合法佈局下會真的觸發。兩數取自相鄰四格的飽和點(`+12 = 4×(+3)`;`−4 = 4×(−1)`),意義為「純靠緊鄰站位所能達到的最好與最壞」。依管理者既有裁決「先補資訊再談數值」,不調整。🔴 **調整 = 直接調整戰力上下限。** ⚠️ 夾限假設 `amp = 1`;對話卡牌加乘若日後改變 `amp`,必須在同一次變更重算:`Φ_max = 4 × amp_max × (+3)`、`Φ_min = 4 × amp_max × (−1)`(`4` 是幾何事實,不是「每角色線上限」)。此處刻意不預留猜測性寬鬆值。

### 公式四:好感度減傷 `guard`【裁決 2026-10-30 新增,2026-10-30 amend1 負向改對稱進位;本節為唯一定義處】

```
guard(Φ_def) =  ceil(Φ_def / 2)         當 Φ_def > 0
             =  0                         當 Φ_def = 0
             = −ceil(|Φ_def| / 2)        當 Φ_def < 0   (負值 = 額外受傷)
guard_total  = clamp(guard(Φ_def) + lone_guard_eff, GUARD_MIN, GUARD_MAX)
damage       = max(0, ATK − DEF + Φ_att − guard_total − hold_back_eff)
```

| 符號 | 型別 | 值域 | 說明 |
|---|---|---|---|
| `Φ_def` | int | −4 ～ +12 | **防守方被攻擊當下所在格**的 Φ(沿用公式三夾限);預覽與結算走同一查詢函式,不得用回合開始快照 |
| `Φ_att` | int | −4 ～ +12 | 攻擊方 Φ;規則不變 |
| `lone_guard_eff`、`hold_back_eff` | int | −1~+2 / {0,1} | 戊的騎牆項,定義在公式五,**非騎牆者恆 0** |
| `GUARD_MIN` / `GUARD_MAX` | int | −2 / +3 | 旋鈕(見 Tuning Knobs);避免 Φ=+12 時傷害歸零 |
| `ATK`、`DEF` | int | ≥0 | 單位數值 |
| `damage` | int | ≥0 | `max(0,…)` 後輸出,不回補生命 |

- **只對我方(PLAYER)防守方生效**。敵方無關係線、無 Φ,敵方防守 `guard = 0`;敵方攻擊時 `Φ_att` 仍為 0。
- **負向對稱進位**:Φ=−1 → −1(額外受傷 1)、−2 → −1、−3 → −2、−4 → −2。負 Φ 在 vs01 的負向配對貼近時於承傷通道付代價。
- 無 RNG;玩家預覽必須顯示「減傷 N」(Player Fantasy 反面感受)。預覽(`preview_damage_breakdown`)與結算走同一函式,細項含 `guard` 與 `hold_back` 鍵(恆存在)。
- 算例(推估,敵 ATK / 我方 DEF 取自 `assets/data/units/vs01_roster.txt`):甲(DEF 8,Φ_def=+3)被 ATK 14 打 = 14−8−2 = **4**;丙(DEF 7,Φ_def=+2)被 ATK 13 打 = **5**;丁(DEF 6,Φ_def=−1)被 ATK 13 打 = 13−6+1 = **8**、被 ATK 14 打 = **9**。

### 公式五:戊的騎牆 —— 獨行減傷 `lone_guard`、留一手 `hold_back`、騎牆有效判定【裁決 2026-10-30 新增,2026-11-03 amend2 改為騎牆,2026-11-17 新增有效判定;本節為唯一定義處】

人設(`design/narrative/characters.md` 戊 條「絕不把籌碼押在同一邊」「算計過的自我保護」)落實為玩法:**身上沒有任何關係時,騎牆生效;一有關係,騎牆失效、並肩加成(公式一、四)取而代之。** 戊可以有關係線,他與其餘四人的 4 組配對和其他九組用同一個 `S` 判定。辨識戊靠**名冊第 12 欄 `lone_guard=1`(語意讀為「騎牆者」,不新增欄位)**,**不得以「沒有關係線」推斷**。

#### 騎牆有效判定(【裁決 2026-11-17】唯一定義處)

```
straddle_active = ALL over m in alive_allies(戊) : state_of(pair(戊, m)) == NONE
lone_guard_eff  = straddle_active ? lone_guard(d_min) : 0
hold_back_eff   = straddle_active ? hold_back(is_straddler, d_min) : 0
```

| 符號 | 型別 | 值域 | 說明 |
|---|---|---|---|
| `alive_allies(戊)` | set | 0~4 個單位 | 戊以外、場上**目前存活**的我方單位。**只看存活者**(2026-11-12 裁決);陣亡者的配對不參與 |
| `state_of(pair)` | enum | {NONE, POS, NEG} | 配對關係狀態,**每次查詢即時讀池、不快取**。定義在規格 v1.0 第 3 節 / story-012,本文件不複述:`n==0` 或 `\|v\|≤k` → NONE;`v>k` → POS;`v<−k` → NEG;與名字無關 |
| `straddle_active` | bool | {true,false} | **同一個布林同時驅動下面兩項,不得各算一次** |
| `lone_guard(d_min)` | int | −1 / 0 / +2 | 距離表(下) |
| `hold_back(…)` | int | {0,1} | 留一手(下) |
| `lone_guard_eff`、`hold_back_eff` | int | −1~+2 / {0,1} | 實際進入公式四 |

- **輸出範圍**:布林,與既有值或 0;不新增夾限(`guard_total` 只在公式四夾一次)。
- **只對騎牆者計算**:非騎牆者 `lone_guard_eff = hold_back_eff = 0`。
- **三項同開同關**【裁決 2026-11-17,Q3「三項一起歸零」】:`straddle_active = false` 時,`lone_guard`(含 `d_min=1` 的相鄰懲罰 −1)與 `hold_back` **全歸零**;不得只關一項(否則騎牆半開)。
- **`CombatRules` 不認識好感度池**:`straddle_active` 由戰棋狀態端(`BattleState`)向好感度側查完,以布林傳入;不得在 `CombatRules` 內另寫第二套門檻。
- **無存活隊友**:`alive_allies` 為空 → `straddle_active = true`,但 `d_min` 無值,下表已規定 `lone_guard = 0`、`hold_back = 0`,結果不變。
- **構造互斥**:`lone_guard_eff ≠ 0` 或 `hold_back_eff ≠ 0` ⇒ 戊 4 組皆 NONE ⇒ 戊無關係線 ⇒ `Φ_def(戊)` 與 `Φ_att(戊)` 皆為 0。故 `guard(Φ_def)` 與 `lone_guard_eff` **結構上不會同時非零**;公式四 `GUARD_MAX` 夾限對此是不可達的保險。(`guard_total` 夾限函式本身仍須單獨測,AC-L8。)

#### 獨行減傷距離表(僅 `straddle_active = true` 時適用)

`d_min` = 戊與**所有存活隊友**(戊以外的我方存活單位)之**最短曼哈頓距離**(R2,實作 `AffinityRules.manhattan_distance()`),**取最近一位,不逐位加總**。

| `d_min` | `lone_guard` | 常數 |
|---|---|---|
| 1 | **−1** | `LONE_NEAR_GUARD` |
| 2 | **+2** | `LONE_MID_DISTANCE=2`、`LONE_MID_GUARD=+2` |
| ≥3 或無存活隊友 | **0** | `LONE_FAR_GUARD` |

「騎牆」= 離隊友剛好 2 格才有減傷;貼身多受 1 點;落單沒有減傷。**只作用於承傷**(進入 `guard_total`)。出手條件(「戊出手後獨行減傷關閉」及其旗標、敵方先手特例、預覽雙值)已取消:`lone_guard_effective()` 一律回傳 `lone`,`lone_guard_if_at(unit_id, tile, will_attack)` 的 `will_attack` 參數**保留但忽略**(已棄用,三處 `##` 註解已標,有測試釘住 true/false 結果相同;後續工作單移除前它是「看似有用、實際無作用」的陷阱)。

#### 留一手 `hold_back`

`hold_back = 1` 當且僅當「攻擊方為騎牆者(旗標單位)**且 `straddle_active = true`** 且攻擊當下其所在格 `d_min = 2`」,否則 0;`d_min` 只計存活隊友,無存活隊友不適用;敵方、我方他人皆不適用。純函式 `CombatRules.hold_back(is_straddler, d_min)`,無 RNG,`hold_back ∈ {0,1}`,在 `max(0,…)` 之前。留一手**不經 `Φ_att`**,是傷害式中獨立的一項(騎牆有效時戊無關係線、`Φ_att` 為 0,該性質不變)。算例:戊 ATK 16 打 DEF 6 的敵人,從 `d_min=2` 格出手 = 16−6−1 = **9**;從 `d_min=1`、`≥3` 或無隊友出手 = **10**。

#### 騎牆有效判定算例(戊 DEF 8,敵 ATK 14,`d_min=2`;配對狀態為假設值,算術推出、未跑程式)

| 情境 | `straddle_active` | `lone_guard_eff` | `Φ_def` | `guard` | 傷害 = 14−8+0−guard_total |
|---|---|---|---|---|---|
| 4 組全 NONE | true | +2 | 0 | 0 | **4** |
| 戊×甲 POS,甲距戊 2 格(死區,貢獻 0) | false | 0 | 0 | 0 | **6** |
| 戊×甲 POS,甲在戊旁 1 格(`d_min=1`) | false | 0(連 −1 一併關) | +3 | ceil(3/2)=2 | **4** |
| 戊×甲 POS,甲**已陣亡** | true(只看存活者) | +2 | 0 | 0 | **4** |

最後一列在實戰中不可達(任一我方陣亡即戰敗,`battle_state.gd` `outcome()`,取自規格第 3 節協調者核實註記,本稿未重驗);列出是為釘住函式語意,不得依賴該巧合。

#### 騎牆的設計脈絡(推估,未驗證,不是校準結論)

- 代價結構:拿到 +2 減傷須待在距隊友**剛好 2 格**,待在那裡出手要付 −1 傷害;想全力打就得貼上去(多受 1 點)或脫隊(失去減傷);**有了關係則整組失效**。(creative-director 裁決見 `docs/reviews/straddle-pillar4-review-2026-10-30.md`,選項來源 `docs/reviews/lone-wolf-redesign-options-2026-10-30.md` 候選 1;戊原「出手二選一」候選甲已被取代。)

- 騎牆「留一手 −1」之於「`d=2` 才有 +2」若兩常數分叉須重新裁決(見 Tuning Knobs)。

## 5. Edge Cases

**距離與關係線**
- **兩單位距離為 0**:不會發生(棋盤禁止同格)。曲線仍定義為 `0` 作防禦性預設。
- **關係線任一端不在場**(陣亡/離場,含兩端同時陣亡):該線**整條不計**,不是計為 0,是不參與加總。
- **角色沒有任何關係線(所有配對 `S` 皆 NONE)**:`Φ` 為 0,不論站哪。**任何單位皆然**,戊與其他單位無差別;差別只在戊另有騎牆(公式五)。對輸出通道,該角色得不到本系統抵銷敵方數值優勢的能力。
- **極性在戰役中翻轉**:不記憶歷史,下次查詢即反映新極性。
- **某角色關係線達 5 條以上**:🔴 **合法,不是資料錯誤**(2026-08-31 不設上限)。依 R4 逐條加總,超出夾限即壓回,**不觸發診斷記錄**。
- **原始和超出夾限**:壓回 `−4` / `+12`。⚠️ 畫面逐條數字加起來不等於總和,而 Player Fantasy 明令「線不會騙人」,**UI 必須明示「已達上限/下限」,不得靜默截斷**(UI Requirements)。
- **`amp` 超出合法值域**(關係表寫錯,如 `amp=10`):**這才是資料錯誤**。夾限仍壓回邊界,**且必須留下可觀測的診斷記錄**。⚠️ 現行 `affinity_link.gd` 對超出值域 `amp` 有 `push_warning()`(2026-08-31 落地)。`amp ≠ 1` 時公式成立但公式三夾限失效、必須重算。
- **同一對角色有多條重複線**:視為資料錯誤,**逐條加總不去重**(不猜意圖),診斷記錄同上。
- **查詢的單位本身不在棋盤上**(預覽用途):允許,回傳依 `o` 計算的假設值。⚠️ 本系統**不檢查該單位是否存活**,存活檢查是呼叫端義務;目前僅單一呼叫路徑保證,**此邊界尚無測試守著**(OQ-4)。
- **單次結算中好感度被寫入而改變極性**:本系統照實回報當下值;**維持快照是上游戰棋系統的義務**,本系統只保證回傳純量。

**減傷(公式四)**
- **`Φ_def` 取值時機**:防守方被攻擊當下所在格;預覽與結算走同一函式,不得用回合開始快照。
- **防守方是敵方**:`guard = 0`;我方攻擊敵方只有 `Φ_att`。
- **`guard_total` 為負**(負 Φ 或戊相鄰):傷害增加,仍受 `GUARD_MIN` 夾限。**`ATK − DEF + Φ_att − guard_total − hold_back_eff < 0`**:傷害 0,不回補生命。
- **夾限各只夾一次**:先夾 Φ(公式三),再算 guard,再夾 `guard_total`。

**騎牆(公式五)**
- **無存活隊友**:`d_min` 視為「≥3」,`lone_guard = 0`、`hold_back = 0`;不報錯。**隊友陣亡**:`d_min` 只計存活隊友,即時重算。**多位隊友**:取最近一位,不加總。
- **非騎牆者**:`lone_guard_eff = hold_back_eff = 0`。**不得以「沒有關係線」推斷誰是騎牆者**,辨識是名冊旗標。
- **戊的關係線由 `S` 決定,不是「被加入」**【裁決 2026-11-17】:任一組 `S ≠ NONE` → 騎牆失效 → 兩項歸零(含相鄰懲罰),`guard(Φ_def)` 照常;兩者不會同時非零(公式五構造互斥)。若有人另對戊加線,與 `S` 判定一致處理,不另設特例。
- **戰鬥中 `S` 翻轉**(例:丙類寫池,`skill-card-system.md` 卡 07/08):`straddle_active` **每次查詢即時重算、不快取**,翻轉後的下一次查詢(預覽、結算)立即反映;寫回 NONE 即恢復(冷淡區可逆)。⚠️ 與 3.3 ②「Φ 在結算中為快照」並存:單次結算內 `straddle_active` 與 `Φ` 應取同一快照(結算步驟①),**快照範圍是否涵蓋 `straddle_active` 屬戰棋系統契約,未驗證**(OQ-9)。
- **預覽與結算同一函式**:`straddle_active` 的取得路徑,預覽(`lone_guard_if_at`)與結算(`_lone_guard_of`、`_hold_back_of`)必須是**同一個**。
- **`k = 0` 的實際後果**【裁決 2026-11-17:量測前先設 0】:任何 `n>0` 且 `v≠0` 的配對即為非 NONE;戊只要與任何人有過一次未被抵銷的互動(如營火「關心」「質問」或丙類寫池),騎牆即失效,直到值回到 0。`k` 的正式值待 story-025 量測;**不得以占位值 50 上線**(story-012)。`k` 是**全域旋鈕,10 組配對共用**。
- **留一手 `d_min` 取值時點**:取**攻擊當下戊所在格**;預覽時用游標格(= 假設攻擊格)。傷害下限:`hold_back` 在 `max(0,…)` 之前,ATK 不足時維持 0(ATK 16 對 DEF 16 → 0)。
- **留一手與卡牌**:不經 `Φ_att`,不吃卡牌修正;被使用增益卡不影響 `hold_back`(只由位置與騎牆有效決定)。**以戊為攻擊方的卡牌觸發傷害是否也走同一函式扣留一手:未查證**,由實作與 `skill-card-system.md` 確認,不得默認。

## 8. Acceptance Criteria

### 8.1 BLOCKING(自動單元測試)

**位置曲線與疊加**
- **AC-R1**:GIVEN 注入兩組強度不同的假資料(程式碼不變),WHEN 查詢 `Φ`,THEN 輸出隨資料改變 —— 證明極性/強度來自外部而非硬編碼。
- **AC-R2**:GIVEN **至少 20 組**涵蓋邊界距離(0、1、2、3、棋盤最大值)的座標對,WHEN 逐組比對 `AffinityRules.manhattan_distance` 與 `CombatRules` 射程判定所隱含的距離,THEN **全數一致**。⚠️ 這是「兩份實作測到一致」,不是「同一個函式」。
- **AC-R3**:GIVEN 四種(極性×距離)組合各自單獨存在,WHEN 查詢單線 `Φ`,THEN 依序回傳 +3/−1(正向距1/距≥3)與 −1/+2(負向距1/距≥3),距離 2 恆為 0。
- 🔴 **AC-R4a**:GIVEN 單位有兩條正向線(一條距1、一條距≥3),WHEN 查詢 `Φ`,THEN 回傳 **+2**(=3−1)。**若回傳 +3 代表仍在跑舊「只取最近正向」邏輯,測試須失敗。**
- **AC-R4b**:GIVEN 同一單位再加一條負向距1線,WHEN 查詢,THEN 回傳 +1(=3−1−1)。
- **AC-R5**:GIVEN X 與 Y、Z 各有負向距1線,WHEN X 從名冊移除,THEN Y、Z 的 `Φ` 各自 +1,且不經任何額外腳本事件。
- **AC-R6**:GIVEN 單條正向距1與單條負向距≥3各自單獨存在,WHEN 查詢,THEN 前者 +3、後者 +2,兩者不相等。
