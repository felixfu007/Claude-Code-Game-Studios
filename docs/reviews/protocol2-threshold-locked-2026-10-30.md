## 2. B 案電腦版完整規則(全部數字寫死)

### 2.1 設定

- 兩臂:**忽視臂**、**運用臂**;各 **8 個變體**,一一配對(第 3 節),共 16 局。每局只跑**一次**。
- 回合上限:**12 回合**。於第 12 回合結束時尚未 VICTORY(含 `aborted`)= **未通關**。腳本 `MAX_ROUNDS` 現為 30,須改 12;`BattleLoop.run(max_rounds)` 在第 12 回合內通關算通關、第 13 回合才發生的算未通關 —— **此邊界行為未查證**,ai-programmer 須用夾具關卡實測並在 README 記下。

- 戰敗(任一我方單位死亡,`battle_state.gd` 的 `outcome()`)與 12 回合未通關,一律稱「未通關」。

### 2.2 指標定義
- **通關**:`outcome == VICTORY` 且 rounds ≤ 12。**通關率** = 通關變體數 / 8。
- **回合數**:`BattleLoop.run()` 回傳的 `"rounds"`,只取通關局。
- **瀕死單位**:我方單位,在整局任一次受傷結算後 `3 * hp <= hp_max` 且 `hp > 0`(「未死」);整數式,不用浮點。腳本須於**每次攻擊結算後**掃描全體我方單位並記錄各自最低 HP(只看結束血量會漏)。
- **每局瀕死數**:該局符合上式的我方單位數。**戰敗/未通關局一律記為「我方單位總數」**(最嚴重一類,避免倖存者偏誤:輸得快的局不會因受傷少而顯得佳)。
- **Φ_avg**(僅操作檢查):每回合我方全體行動完畢後,以 `AffinityRules.bonus_for_at(id, pos, positions, links)` 逐我方單位計算並加總,整局取平均。⚠️ 該函式是否即 `design/quick-specs/unit-stats-provisional.md`「Φ 上限實機驗證」所用者,未查證,ai-programmer 須確認並在 README 註明。

### 2.3 判定(依序)
**步驟 A 基準有效性(前置,非通過條件)**:忽視臂通關變體數須在 **2~6** 之內(換算:20%×8=1.6 → 向上取整 2;80%×8=6.4 → 向下取整 6;取整皆向「更嚴」方向,即縮窄有效範圍)。
- 通關數 ≤1 或 ≥7 ⇒ 結果記「**基準無效**」:**不判過、不判不過、不計入停損判定**。處置:調整**關卡/名冊數值**後整組(兩臂 16 局)重測;**門檻本身不動**。每次嘗試的原始 log 全部保留、編號 attempt-1、attempt-2…,不得刪除。🔴 **上限 3 次**(attempt-1~3 皆基準無效 ⇒ 停止,三次結果全數交管理者裁決;不得自行開 attempt-4)。調整關卡數值的提交須在重測前完成並早於該次結果檔(同第 4 節規則)。

**步驟 B 通過條件**(A 有效時,以下 B1 且 B2 同時成立才算「通過」):
- **B1(兩者擇一)**
  - (a) **通關率**:運用臂通關數 − 忽視臂通關數 ≥ **2 個變體**。換算:20 個百分點×8=1.6,**向上取整為 2**(=25pt,偏保守);「差 1 個變體」(12.5pt)一律不過。
  - (b) **回合中位數**:兩臂通關局數**各 ≥4**才可評估本支(否則本支視為不成立,不得以較少局硬算)。中位數取通關局回合數排序後的中位;偶數個時取中間兩數平均。為避免小數,以「兩倍中位數」`2M`(=中間兩數之和,奇數時為中位數×2)比較:`10 * 2M_運用 <= 8 * 2M_忽視` **且** `2M_忽視 - 2M_運用 >= 2`(即至少少 1 回合)。
- **B2 不得以更多瀕死換速度**:運用臂 8 局「每局瀕死數」**總和 ≤ 忽視臂總和**(兩臂局數同為 8,故等價於平均)。
- **平手與差距不足**:B1 門檻為「≥」,剛好等於算過;但差距小於 1 個變體或小於 1 回合者算**未通過**(舉證責任在假說)。B1、B2 任一不成立 ⇒ **未通過**。

### 2.4 判讀限制(必須隨結果一併寫出)
- 結果稱「**電腦對照判定**」,不得寫成「玩家行為證實」:兩臂都是工程師寫的策略(提案第 4 節疑慮,管理者已知並裁決電腦為正式)。
- 8 個變體**不是獨立統計樣本**(同一套決定性程式的參數變體),20 個百分點與 20% 是決策規則,不是顯著性檢定。
- 運用臂依鎖定前裁決改為**主動追好感度**(3.1):在通過安全門檻的格子中**以好感度加成最大者為第一優先**。仍是工程師寫的策略;若未通過,可能反映「此種運用方式」無效,不代表所有運用方式無效。**H 之後不得為此修改運用臂重跑**,只能登記為限制並交管理者裁決是否另開新一輪。
- 結果檔須列出 Φ_avg:忽視臂 Φ_avg 不論高低**都不重新分組、不作廢結果**;若 > +4(提案原操作線),以紅字揭露,可能是站位巧合靠近,由管理者判讀。「結構上不讀好感度」靠程式碼審查證明(2.1 之外見 3.2 第 4 點),**不靠 Φ_avg 低來證明**(站位巧合也會產生 Φ)。

## 3. 變體產生規則(預先登記,無裁量空間)

### 3.1 骨架
兩臂共用同一支決策函式(複製自 `autoplay_v2.gd` 的 `_decide_cautious`,放新目錄,不改舊檔),集火永遠開啟(`_focus_pick` 的「可擊殺優先」排序不變)。兩臂**唯一差別**是旗標 `use_affinity`:
- 運用臂 `use_affinity = true`:**主動追好感度**(鎖定前裁決,取代現 C 的「平手鍵」用法)。站位選擇順序寫死為:①先套 K1 安全門檻得出候選池(池空時照舊退回「最低 threat」);②在池中取 `AffinityRules.bonus_for_at(id, t, positions, links)` **最大**的格子集合;③該集合內再照忽視臂完全相同的既有比較(可攻擊/集火/距離)決定;④仍平手依 K3 順序取第一個。忽視臂則略過步驟②,其餘①③④相同 —— 兩臂差別仍只有步驟②。`positions` 為該單位**移動前**的我方站位快照(同回合先動者的新位置計入,後動者不預測)。
- 忽視臂 `use_affinity = false`:`caff`、`aff` 恆為 0,**不呼叫** `AffinityRules.*`、`prov.links()`、`prov.positions()`、`prov.phi()`。
現腳本把「集火」綁在 `prov != null` 上,須拆成獨立旗標 `focus_on = true`(兩臂皆真),否則會重演混雜變因(見量測計畫 1.2)。引擎端 Φ(`phi_cb`)**兩臂皆開**,與提案「Φ 機制都開著」一致。

### 3.2 變體名單(3 個二元旋鈕 × 2 = 8,按編號固定)
| 旋鈕 | 值 0 | 值 1 |
|---|---|---|
| **K1 安全門檻** | 候選格留下條件 `threat[t] < unit.hp`(現行) | `threat[t] * 2 < unit.hp`(更保守;池為空時照舊退回「最低 threat」) |
| **K2 集火平手鍵** | 可擊殺優先 → `hp` 小者 → `id` 小者(現行) | 可擊殺優先 → `hp` 小者 → `id` **大**者 |
| **K3 候選格順序** | 池按 `(y, x)` 由小到大排序後再逐格比較 | 池按 `(y, x)` 由大到小 |

變體編號 `v = K1*4 + K2*2 + K3`,即 v0~v7,**全部 8 個都要跑,不得挑選、不得增減**。同編號的忽視/運用兩局只差 `use_affinity`。
1. 排序在**兩臂**都做,確保 K3 的作用不因臂而異。
2. 若某變體在忽視臂與運用臂產生**逐字相同**的整局 log,照實保留,不視為異常(說明好感度在該變體沒起作用)。
3. 旋鈕只能取上表值;任何新增旋鈕、改值、改 `_threat` 或 `_focus_pick` 其他邏輯 = H 之後改動,須走第 4 節重新登記。
4. 「結構上不讀好感度」的審查:忽視臂路徑上 `grep -n "AffinityRules\|prov\.\(links\|positions\|phi\)" <決策檔>` 的命中必須全部落在 `if use_affinity` 保護之內(審查者逐行看,不只看命中數),並貼原始輸出。

## 5. 給管理者的白話摘要
1. 電腦用同一個關卡、同一套打法跑 8 組,每組各打一次「不看好感度」和「看好感度」,兩邊只差這一點。
2. 8 組不是 8 個獨立玩家,是同一個程式的 8 種小調整;它是規則判定,不是統計證明。
3. 過關標準:「看好感度」那邊**至少多贏 2 組**(8 組裡),**或**贏的局回合數少 20% 且至少少 1 回合;而且被打到快死的次數不能比對方多。
4. 12 回合沒打贏就算輸。差距不足、剛好平手,一律算沒過。
5. 如果「不看好感度」那邊 8 組只贏 0~1 組或贏 7~8 組,這次比較沒意義,記為「基準無效」,要調關卡難度重測,不算失敗也不算成功。
6. 這份文件一提交,數字就鎖死;電腦跑完後只能調關卡,不能改標準。
7. 「看好感度」那邊已依你的裁決改成主動追好感度(在不會被打死的格子裡,先挑好感度加成最高的)。它仍是一種程式寫的打法,沒過時代表「這種用法」沒效,不等於所有用法。
7b. 比較無效時最多調關卡重測 3 次,第 3 次仍無效就停下交你裁決。
8. 你日後要決定:基準無效時要不要調關卡、以及未通過時要不要另開新一輪(含更會用好感度的打法)。
