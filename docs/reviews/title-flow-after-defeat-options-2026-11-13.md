# 戰敗後的標題流程:方案比較(2026-11-13,game-designer)

範圍:流程與規則。介面細節標「需 ux」。本檔不改任何既有檔。

## 1. 事實查證(原始輸出,今天讀的現值)

標題兩列的接線(`src/ui/shell/title_screen.gd`):

```
137:	_start_battle_row.pressed.connect(start_tutorial)
138:	_skip_tutorial_row.pressed.connect(start_battle)
177:func start_tutorial() -> void:
178:	TutorialProgress.begin()
179:	SceneRouter.enter_tutorial_battle(get_tree())
172:func start_battle() -> void:
173:	SceneRouter.enter_battle(get_tree())
```

標籤:`strings.csv:88 shell.title.start_battle,開始戰鬥` / `:165 shell.title.skip_tutorial,略過教學`。
=> 實測屬實:「開始戰鬥」進教學第 1 場,「略過教學」進戰役。

戰役戰敗(`battle_screen.gd` 約 5523-5524):

```
			else:
				CampaignProgress.rollback_on_defeat()
```

`rollback_on_defeat()` 只回滾好感度累積記錄,**場次編號不動**(`campaign_progress.gd`:`_current_mission` 是 static var,戰敗不呼叫 `advance_on_victory`)。
結果顯示結束後走 `_on_result_display_finished()`:戰役戰敗 `_proceed_to_next_mission == false` -> `return_to_title_screen()`。

教學戰敗(同檔 `_resolve_tutorial_outcome`):

```
5677	if outcome != BattleState.Outcome.VICTORY:
5678		_tutorial_next = TutorialNext.TUTORIAL_BATTLE
```
=> **教學戰敗直接重打同一場,不回標題。**

`TutorialProgress.begin()` 把教學歸 1 並 `_active = true`;`SceneRouter.enter_battle()` 一進戰役就 `TutorialProgress.end()`。

結論(查證後的事實):
1. 戰役場次在【本次執行期間】戰敗後確實保留(`_current_mission` 沒被動),所以資料沒丟。
2. 丟的是【入口】:標題沒有任何一列會把玩家送回「戰役第 N 場」。唯一進戰役的是「略過教學」,而且它不會重置場次(所以點它其實能回到第 N 場,但標籤講的是「略過教學」,玩家不會想到)。
3. 勝利路徑完全不回標題(直接下一場或對話),只有「戰役戰敗」會回標題。
4. 流程不對稱:教學戰敗重打同一場、戰役戰敗卻被丟回標題。
5. 我 11-13 定稿第 5 項「會進同一場」的推論錯在:`reset_campaign()` 註解寫的是「戰役完成後歸零」,我把它讀成「按開始進戰役」。入口根本沒接。更正:應以本檔為準。
6. 以上全為 static var,關掉遊戲即全部歸零(`campaign_progress.gd` 檔頭「跨啟動不持久化」)。

## 2. 方案

### 方案 A:戰役戰敗直接重打同一場,不回標題(與教學對稱)

- 玩家體驗:輸了 -> 看結果(約 3 秒)-> 直接重開同一場。和教學、和勝利路徑一致,標題只在「剛開遊戲」與「戰役打通」時出現。戰敗摩擦最低(符合「高頻失敗要快速恢復」)。
- 與存檔範圍:不依賴存檔。關掉遊戲照舊歸零,但因為玩家不會被丟到標題,「回來之後找不到進度」這個場景只剩「自己關遊戲」,而那本來就是已知限制。
- 要改(粗估):`_on_result_display_finished()` 在戰役戰敗分支改呼叫 `SceneRouter.enter_battle()`(約 5 行,`enter_battle` 內 `start_mission_affinity_ledger()` 會重新 begin,回滾後狀態乾淨);新增 1~2 條測試;改「下一步」文字 1 條(`strings.csv` 一列)。要核對戰敗後 ledger 與牌組「只記單輪」不外洩(測試涵蓋)。
- 結果畫面「下一步」行:可寫實話「稍後重打本場」(教學戰敗已是同一句型,可共用文案)。
- 優點:改動最小、不新增任何入口或標籤、玩家沒有「我進度去哪了」的疑問。
- 缺點:戰敗後沒有喘息或離開的點,想回標題只能走戰鬥選單的離開(離開確認語意現有,需 ux 確認選單能在結果期間之外順利取得;結果 3 秒內不可操作屬現況)。無法自然給玩家「改配置再來」的機會(但牌組只記單輪,本來就沒有場外配置)。

### 方案 B:標題在有戰役進度時顯示「繼續戰役(第 N 場)」

- 玩家體驗:戰敗回標題後,看見能直接回第 N 場的明確入口。
- 與存檔範圍:最容易出事。「繼續」兩字在玩家心智中等於「關遊戲再開也在」,而實際關掉就歸零。要加但書(例如「本次遊玩」)或接受誤導。這會把存檔缺口暴露在標題最顯眼處。
- 要改(粗估):標題多一列或條件式改標籤(需 ux:位置、焦點順序、手把;`focus_neighbor` 已手動接線,要重排)、3~4 條字串、`title_screen.gd` 條件判斷、測試;`CampaignProgress` 需對外提供「有進度」判斷(新增公開方法,如 `has_progress()`)。約 A 的 4~6 倍。
- 結果畫面「下一步」:可寫「稍後回到標題,按『繼續戰役』」,比現在好,但字更長。
- 優點:玩家有明確掌控感(自己決定何時回去);戰敗與離開之間有停頓。
- 缺點:成本高、「繼續」誤導風險、仍然多一次點擊的摩擦;標題在有進度與無進度時是兩種版面,測試面加倍。

### 方案 C:「開始戰鬥」改進戰役,教學另列

- 玩家體驗:第一次進遊戲就是戰役,教學變成可選。戰敗回標題後按「開始戰鬥」回到第 N 場(因為現有 `enter_battle` 本來就不重置場次)。
- 與存檔範圍:同 B,「開始」不會讓玩家預期有記憶,比「繼續」誤導小。
- 要改(粗估):兩列的接線與標籤對調(約 4 行 + 字串 2~3 條 + 測試),但需 ux 決定新手預設路徑與教學入口位置。
- 結果畫面「下一步」:可寫「稍後回到標題,再按『開始戰鬥』回到本場」,可靠。
- 優點:戰敗回流與標籤一致、改動小。
- 缺點:**預設新玩家跳過教學**。教學有 4 場、是目前唯一的規則教學,管理者把它放在「開始」位置是刻意的(story-008)。把它降為選項會推翻那個決定,屬新裁決。同時「戰役打通後再按開始戰鬥」會接續到已歸零的第 1 場,沒問題,但新手流失風險高。

## 3. 「開始戰鬥」標籤是否誤導

- 對新玩家:按它進教學第 1 場,是**好事**(這就是設計意圖,教學在前)。標籤沒有說謊 —— 教學也是戰鬥。旁邊「略過教學」那列讓配對語意成立:玩家看到「略過教學」就推得出上一列是帶教學的。
- 對回頭玩家:只有在「戰役戰敗被丟回標題」這個情境裡才誤導 —— 他會預期「開始戰鬥」回到剛輸的那場,實際進教學第 1 場。這個誤導其實是方案 A 要消除的**情境**,而不是標籤本身的錯。
- 標籤本身的小缺點:它像「立刻進戰役」,不像「從頭(含教學)開始」。若要改字,「開始遊戲」比「開始戰鬥」更準(需 ux / narrative 定稿,不阻擋任何方案)。

## 4. 推薦

**推薦方案 A**(戰役戰敗直接重打同一場)。一句話理由:它在根上讓「戰敗後入口接不上」不再發生,與教學、勝利路徑全部對稱,成本最小,且不碰標題版面與存檔缺口;標籤維持不動。

給管理者的選項:
1. 方案 A(推薦):戰敗直接重打同一場。改動小,不動標題。
2. 方案 B:標題加「繼續戰役(第 N 場)」。成本約 A 的數倍,且「繼續」會讓玩家誤以為關遊戲後還在。
3. 方案 C:「開始戰鬥」改進戰役、教學另列。小改動但推翻「新手預設進教學」,新手可能略過規則教學。
4. 另可在選 A 之外,順手把「開始戰鬥」改名「開始遊戲」(純文字,可之後再說)。

連動項:選 A 後,結果畫面「下一步」行應改寫為「稍後重打本場」(戰役戰敗)。我 11-13 定稿第 5 項需更正(該檔是既有檔,待你核准後我才改;story-046 實作者目前寫「回到標題」的版本在選 A 後也要改)。

未查證:戰役戰敗重打時戰鬥選單的離開路徑在結果計時器期間的行為(需 ux / 程式確認);重打是否殘留本場牌組/好感度(依賴 `enter_battle` 重新 begin,需測試鎖住)。
