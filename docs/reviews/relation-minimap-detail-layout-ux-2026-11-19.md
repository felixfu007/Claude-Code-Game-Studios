# 關係圖詳情區版面意見(ux-designer,2026-11-19)

依據:`design/ux/card-rework-ui-2026-11-17.md` 4.2/4.3、AC-11、AC-13;實作者量測表(派工單提供,**我未重跑量測**);`active.md` 10-28 裁決第 21 項。未讀 worktree 程式碼,`hud_layout.gd` 是否要動為依量測表推論。

## 一、詳情區與手牌列重疊

問題白話:關係圖面板加了 11 列文字後變長,在 960×540 與 1920×1080 的下緣會壓到畫面下方的手牌列。1280×720 沒事。960×540 在加詳情之前就已經有 4.6px 相交。

### 方案甲:整個面板(圖 + 詳情)往上移,下緣貼齊手牌列上緣(推薦)
- 白話:面板變高了,就讓它的底部停在手牌列上面一點點,頂端往上長。
- 算一下(依量測表,詳情 132px):960×540 面板原高約 220,加詳情約 352,手牌列頂 392,頂端落在約 40px,放得下;1920×1080 面板原高約 440,加詳情約 572,手牌列頂 784,頂端約 200px,放得下。1280×720 本來就不撞。
- 優點:玩家一次看到圖與文字;不用多學一個按鍵;符合「介面疊在棋盤上、不佔側邊」的硬性約束;順便把既有 4.6px 相交一起消掉。
- 缺點:面板會蓋住更多棋盤(960×540 最明顯,面板約蓋掉上方三分之二的高度)。補償是關係圖本來就是玩家主動開、可再按鍵關掉,蓋住棋盤是接受過的代價。
- 要動的檔:`hud_layout.gd`(`relation_minimap_rect` 的垂直定位規則由「從頂部固定位置往下長」改成「以手牌列頂為下界、往上長」,且須呼叫 `HandBar.slot_bar_rect` 取下界,不可抄座標);`relation_minimap.gd` 的內部排版視情況跟著調。
- 水平重疊(960 下 x 293~307)在垂直已分開後就無妨,不必再處理。

### 方案乙:詳情區改成再按一次鍵才展開的浮層
- 白話:關係圖照舊,另按一個鍵才跳出文字清單,清單可以蓋在手牌列上方。
- 優點:平時畫面最乾淨;面板本身不變高。
- 缺點:多一個按鍵與一層狀態,鍵盤與手把都要能到;冷淡與騎牆資訊(AC-11、AC-13 要玩家一眼分辨「沒線是冷淡還是漏畫」)被藏到第二層,與我 4.3 的設計意圖(詳情是為了解釋沒線)相反;手牌列被蓋住時手牌可操作性要另外定義。
- 要動的檔:`hud_layout.gd`(新增浮層矩形)、輸入對應、`battle_screen.gd`、無障礙走查項。工程量最大。

### 方案丙:縮減列數,只列非冷淡 + 騎牆
- 白話:冷淡的那幾組不列了,面板就比較矮。
- 優點:改動最小,可能不必動版面函式。
- 缺點:直接違反 AC-11(「冷淡也列」),且列數不固定,版面會跳動;冷淡組愈多縮得愈多,正好是最需要解釋的情境(沒線)反而沒字。**不推薦。**

### 既有 4.6px 相交要不要修
建議一起修。理由:這是同一個根因(面板下界沒有以手牌列為準),方案甲修了詳情區就自動修掉,不修反而要留一個特例。若管理者選乙或丙,則應另開一個小修,不要讓它繼續留著。

⚠️ 未驗證:方案甲在 960×540 下面板蓋住的棋盤區是否會遮到開場單位站位,需要實作後用截圖由人眼確認(AC-14 同一批)。

## 二、「目前效果」的原意

**結論:不是數字。** 我 4.3 的「目前效果」指的是三種語意詞:加成 / 懲罰 / 無(效果為 0)。依據同檔 135 行棋盤友敵線的定義:「形狀 = 關係,色 = 效果(加成、懲罰)」,效果 0 對應灰線與「站位沒效果」(11-12 裁決)。「效果」在本檔一律是方向,從未指強度。

與 10-28 裁決第 21 項「關係圖不顯示強度數字」**不衝突**:該項禁的是數字,詞不是數字。實作者省略整個「目前效果」欄,過度解讀了。

建議補回的形式:每列尾端加一個短詞(加成 / 懲罰 / 無),且不能只靠顏色(可及性清單「不得只靠色彩」)。冷淡列沒有效果概念,該欄留空或不顯示,不要寫「無」(「無」是 POS/NEG 但站位不到的意思,與冷淡不同,混用會讓玩家分不清)。詞表需走既有 `strings.csv` 單一鍵(AC-12),我未查現有鍵是否已含「加成/懲罰/無」。

⚠️ 未驗證:加了這個詞之後,11px 下單列是否仍不換行、不超出面板寬度,需實作者量測。
