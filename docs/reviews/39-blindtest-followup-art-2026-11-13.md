## 二、題 C:「很醜」的具體原因與第二階段修正

「醜」是管理者的感受,下面是我從圖上找得到的原因,不是替圖辯護。信心標在每條後面。

### 最可能的原因(依我認為的影響大小排序)
1. **臉讀不出來(信心:高)**。【看圖】丁:帽簷與頭髮蓋掉大半臉,臉只剩一塊暗斑;丙:槍管與瞄準鏡壓在臉上;甲、戊:臉約 4~5px 寬,看不到眼睛的位置。人物沒有臉,觀者的第一反應就是「怪」。這與「四個都沒有很像」是同一件事——**沒有臉就沒有「像不像」可言**。
2. **頭太小、身體太寫實(信心:中高)**。【看圖估計】頭(含髮)約 8~10px / 全身約 55px,約 1:6。48×60 的畫布上,6 頭身會把臉擠到無法畫五官。像素風在這個尺寸下通行的做法是 3.5~4.5 頭身(頭 12~14px)。**這是造型取捨,不是修瑕疵**,見下方路線討論。
3. **服裝上有零散單點雜訊(信心:中高)**。【看圖】丁的外套與腰帶、甲的胸口與褲管都有 1px 孤立亮點/暗點,不成形狀。這是 AI 圖縮小到 48 寬的典型副產品(把高光/紋理壓成孤點)。觀感是「髒」。
4. **描邊不一致(信心:中)**。【看圖】丁、甲的深藍衣服與深色描邊同暗,輪廓邊緣糊掉;戊、丙則輪廓清楚。四人輪廓清晰度不同,放在一起像不是同一人畫的。
5. **色彩整體悶、且兩人撞色(信心:中)**。【看圖】丁與甲都是深海軍藍,丙是單一棕色,只有戊有衣色對比。灰階圖裡丁、甲最暗、內部層次最少。第一階段審查已要求丁換色,但**沒有要求「每人至少三個明度階」**。
6. **姿勢僵硬(信心:低~中)**。【看圖】丁筆直站姿、腿近平行;戊手臂垂直下垂,像人偶。丙、甲有動勢,較好。
7. **地形雜訊蓋過人物(信心:中,但這題 C 只看棋子圖,所以只列為合成圖上的加重因素)**。【看圖】平地是高頻迷彩斑,水是高頻亮點,比棋子本身更「忙」,人物在上面失去焦點。第二階段已要求改重複圖樣,**另要降低高頻度**(見附錄 T1)。

### 第二階段可執行的修正(要求見附錄 C1~C6)
- C1 臉:每人臉部留 ≥ 4×4px 膚色區,兩個 1px 眼點不被帽簷/髮絲/槍遮住。
- C2 孤點清除:衣服內不得有孤立單像素(眼睛與高光 ≤ 3 處除外);色塊最小 3px。
- C3 每人除描邊外 ≤ 8 色,且衣服至少三個明度階(亮/中/暗)。
- C4 描邊只在**外輪廓**(沿用 10-12 裁決:內部接縫不描),且描邊色與相鄰衣色差一階以上;深色衣服的輪廓用比衣色略亮的邊緣光(1px)。
- C5 丁、戊至少各改一個姿勢要素(丁:重心微偏、一腿微彎;戊:一手離體)。
- C6 頭身比:**不強制**,見路線選項 B2。

## 三、題 B:倒木「比人矮卻擋視線」的美術方案

### 先承認:管理者說得對,而且部分是我的要求造成的
【看圖】合成圖裡倒木約 40×15px;跪姿的丙全高約 37px,站姿的丁約 55px。**倒木高度只有跪著的人的 0.4 倍、站著的人的 0.27 倍,約等於膝蓋高。** 我在第一階段給的「高 20~24px」(要求 #10)也只有站姿的一半,**這個數字我定低了**,即使外包照做,管理者還是會問同一個問題。

另兩個看得到的問題:
- 【看圖】合成圖的倒木格底色是**平的單色**,與平地格的斑紋地面不同——它像貼在格子上的貼紙,不像長在地上的東西(需確認這是合成圖的做法還是倒木磚本身不帶地面)。
- 【看圖】6×6 拼圖裡倒木靠左、置中偏上,整齊排成一列,體積感為零。

### 設計原則(我建議採用,不論規則怎麼定)
**「擋視線」與「剪影高度」要一對一綁定**:會擋視線的地形,畫出來的最高點必須 ≥ 站姿棋子眼睛高度(約 40px,即格高 48 的 5/6 以上),且是密實的暗色塊;不擋視線的地形最高點不得超過約 14px。這樣玩家不必學規則,看圖就知道。目前倒木同時違反兩邊(矮、卻擋),所以才會被質疑。

### 48×48 與 48×60 棋子站旁邊的比例
- 棋子 48×60:腳在格底,頭向上突出格頂約 12px(沿用規格)。站姿棋子身高約 43px 在格內、約 12px 在格外。
- 因此**格內塞滿 44px 高的物件 ≈ 與棋子等高**,畫得下;48×48 之內放「棋子等高」是可行的,代價是整格幾乎被物件占滿(也本來就是「這格被堵住」的意思)。
- 若想更高(超過格頂),必須做成像棋子一樣的「向上溢出格子的物件」(48×60、依 y 排序),**這牽涉渲染層是否支援地形溢出,我不判斷,交 technical-artist/godot-specialist 查**。

### 方案一:規則不改(可走成本 3、擋視線)——美術上最可信的做法
**把「一根倒木」改畫成「亂木堆/倒木糾結」**:2~3 根粗幹交疊(上層橫躺、下層斜壓)、數根枝椏與斷枝向上、高約 40~44px 填滿格高、顏色最暗最密、頂部有凌亂突起。
- 為什麼可信:**「爬得過去,但要繞很久(成本 3),也看不透(密實)」正是亂木堆的物理直覺**——單根倒木讓人想「跨過去就好、看得到對面」,糾結的堆則不會。
- 48×48 畫得出:是,疊 3 層幹 + 枝椏,在 64 色內可行;單張樹皮質感用現有 AI 路線,輪廓用我先前同意的「程式畫剪影」可控。
- 名稱建議連動:「倒木」改稱「亂木堆」會讓玩家預期一致。**改名是文案/規則面,由協調者與 game-designer 定**,我只說美術上這個名字比較配得上這張圖。
- 風險:成本 3 的「可走」,玩家看到 44px 高的密堆仍可能覺得「這怎麼走」。這是**這個方案的殘餘不可信度,無法靠圖消除**,只能靠移動預覽(顯示成本 3)輔助。

### 方案二:換成別的地形名稱——美術上的選擇
(是否換、換成什麼規則,**由 game-designer 定**;下面只講各名稱畫出來的可信度。)
| 名稱 | 畫法 | 擋視線可信度 | 備註 |
|---|---|---|---|
| **密林/灌木叢** | 高密暗綠團塊,高 40~44px | 最高 | **注意:39 號第二階段已有「灌木」要做。**若灌木規則不是擋視線,兩者長得相似規則不同,又會製造新衝突;若灌木規則就是擋視線,則倒木大概可併入或另立。**須 game-designer 先答灌木的視線規則。** |
| **岩堆/巨石** | 大塊岩石堆,高 44px | 高 | 一般直覺是「過不去」;若保留「可走成本 3」可叫「碎石坡」,但看不透就仍會被質疑,可信度略低於亂木堆 |
| **矮牆/柵欄** | 高 ≤ 24px | **低** | 矮牆擋視線與管理者直覺正面衝突,**不建議**用於擋視線 |
| **倒木(維持原名+單根)** | 現狀 | 低 | 不建議;需要同時改規則成「不擋視線」才成立 |

**若規則改成「倒木不擋視線」**:美術上就畫矮(≤14px、單根、貼地),現況只需微調,是**美術成本最小**的解;但全遊戲就**沒有任何擋視線地形**,是否影響戰術設計由 game-designer 評估。

### 追加要求(附錄 L1~L4)針對「規則不改」的路線;若規則改,L 條作廢,改發新要求。
**需要管理者決定**:規則面與地形名稱(見第四節),在決定前**不要推送 L1~L4**。

| 方案 | 內容 | 優點 | 缺點 | 對第三階段待機幀的影響 |
|---|---|---|---|---|
| **S1 站姿常駐,跪姿只在攻擊幀(推薦)** | 待機=站姿、長槍**斜背/斜扛**(槍管朝上斜過身體,不水平);攻擊幀才跪下架槍 | 移動與待機一致,將來加走路也成立;斜背長槍與丁的水平槍臂剪影不同,**仍可分辨**;跪姿不浪費,成為攻擊的戲劇性 | 要重畫丙一張;第一階段通過的丙剪影需重驗(盲測再做一次丙/丁);攻擊幀本來是第三階段才有,屆時才看得到跪姿 | 待機 2~3 幀做呼吸/重心微移即可;攻擊幀 = 跪射;無需走路幀(現行瞬移) |

**需要管理者決定**:是否改丙的常駐姿勢(S1/S2/S3)。若選 S1,附錄 A2 才推送;**與 B2 Q 版試做(第二節)的丙共用重畫,建議合併為同一張試做**,避免畫兩次。

## 七、管理者補述:「之後棋子移動時要做移動動畫,所以(腳設站資料)合理」

### 我讀到的幾種解讀(請協調者向管理者確認)
- **R1(協調者的讀法)**:之後會做移動動畫,所以常駐姿勢必須能自然接上走路。
- **R2**:「腳設站資料」指**腳的站位資料**——各幀腳底錨點/基準線要一致且合理,動畫才不會抖。
- **R3**:「你提醒她」的「她」若指外包或另一位專家,則是要我**把這個前提寫進給外包的要求**。

### 以 R1 為前提的結論
**跪姿不能當常駐姿勢**:走路幀必須從待機姿勢自然過渡,而跪姿→站起→走→再跪,等於每次移動要多兩個過渡幀(起身、跪下),每個單位移動都付這個代價。**前提成立時,方案 S1(站姿常駐、跪姿僅限攻擊幀)從「推薦」升為「幾乎必選」。** S2 只在「永遠不做走路幀、永遠瞬移」時才成立,與管理者的前提相反。

### 各階段要求
**第二階段(棋子,現在就要改嗎):要,但只有丙一人。**

## 八、依管理者「樹葉/迷霧」方向(2026-11-13)

管理者的直覺是對的,而且它修正了我第三節的設計原則:**「擋視線」要綁的不是「實心」而是「高 + 密」**。亂木堆是實心物,會讓人想「走不過去」;枝葉、高草、霧是**非實心但看不透**,正好同時說得通「走得過去(撥開就過)」「慢(成本 3)」「擋視線」。**第三節方案一(亂木堆)與 L1~L4 作廢**,由下方新 L 組取代;「高度綁視線」原則保留。標記:以下皆為美術設計推論,我沒有 Bash、沒開圖重驗,色盤只指階數,具體色碼由協調者/外包從色盤檔取。

### 1. 兩種畫法,怎樣讓人「一眼相信」

「走得過去」靠**邊緣是碎的、底部是空的**;「看不透」靠**中上段是密的、頭部高度被填滿**。

| | 茂密枝葉/高草叢 | 迷霧 |
|---|---|---|
| 高度 | 最高點 40~44px(約站姿棋子眼高以上,與 48×60 棋子差一個頭)。格頂外不溢出。 | 同:上緣 38~44px,但**上緣淡出**,不畫硬邊。 |
| 密度分佈 | 上 2/3 密(葉團或草尖交疊,幾乎不見背景);**底部 10~14px 疏**:可見草莖、地面、幾處縫隙,表示「底下是可以踩進去的」。 | 底部較濃、往上漸稀;整團無輪廓線。 |
| 輪廓 | **不描實線外框**(實線=實心物)。外緣用「葉尖/草尖」鋸齒,左右不對稱,頂部有 3~5 個高低不一的尖。 | 外緣用**抖色(dither)**過渡:2 階相鄰色棋盤格混排,寬 4~6px。 |
| 色(色盤內) | 綠系 3 階:暗綠(主體、佔 ~50%)、中綠、一小撮亮綠葉尖(≤10%);陰影處用深色而非黑。**整體比灌木暗一階。** | 偏冷灰藍白 2~3 階(色盤內最亮的冷灰+一階中灰藍);**不用純白**,以免與水面亮點、UI 搶。 |
| 質感 | 葉形/草葉以 3~5px 成簇的小形狀,**不是 1px 亂點**(沿用 C2 孤點規則)。 | 以 6~10px 的橫向雲團疊,不畫細節。 |

### 棋子站在裡面時的呈現

- **P0 最低成本(AI 可交件)**:棋子照常畫在地形**上方**,完全可見。優點:零程式、讀得出誰在哪;缺點:人像站在草叢「前面」而不是「裡面」,「走進去」的說服力最弱。
- **P1 前景遮擋層(推薦,需 godot-specialist 確認)**:地形交**兩張**——後景(整團)與**前景條**(只含最下 12~14px 的草尖/霧底,其餘透明)。棋子夾在兩層之間,結果是**腳與小腿被草尖蓋住、上半身可見**。這是像素遊戲處理高草的通行做法,「在裡面」感最強。
  - **需確認**:`render_pieces()` 目前每次重建 Sprite2D;前景條須在棋子圖層**之上**、且只蓋有棋子的那格或全部該地形格皆可。是否有 z 排序/圖層安排,我不判斷。
  - **可讀性風險**:被蓋的是腳不是臉,血量/武器仍可見;前景條 alpha 不得讓棋子「消失」(不得遮到膝以上)。
- **P2 整個棋子半透明化(不推薦)**:棋子變色會與「選取/受傷/行動完成」等狀態色衝突,且 AI 無關、全由程式做;我不建議為此占用狀態色語彙。

### 2. 與灌木拉開(玩家一眼分得出「擋/不擋」)

沿用並收緊「高度綁視線」原則,**四個維度同時拉開,不靠單一維度**:

| 維度 | 灌木(慢、不擋) | 新地形(慢、擋) |
|---|---|---|
| 高度 | **≤14px**,低矮圓團,後方(上方)天空/地面全看得見 | **40~44px**,高過棋子腰部 |
| 輪廓 | 圓、緊湊、邊緣有 1px 描邊(實心小物) | 鋸齒尖、無描邊、頂部不規則 |
| 明度 | 中綠為主,有亮點(果/花可選) | **最暗**,通體暗綠,幾乎沒有亮點 |
| 剪影 | 棋子站其上,上半身全可見 | 棋子站其中,下半被蓋 |

另請 UI 面(`ux-designer`/game-designer,非我網域)考慮:**移動/視線預覽時**對「擋視線」格加一個小符號,作為圖像之外的第二層保險。美術上我只保證四維度可分,**不保證**單憑色分辨(色覺差異玩家)——所以高度與輪廓兩項不得省。

### 3. 迷霧做成動態/半透明:AI 能不能出?

- **半透明:AI 不適合。** 本專案鎖 64 色,**沒有 alpha 漸層可用**,半透明只能用抖色模擬;AI 出圖經縮圖+量化後,霧會變成**一片髒灰斑**(正是題 C 第 3 點的孤點雜訊),且 AI 無法穩定畫出「透出背後」的效果。
- **動態:AI 不能,也不該。** 飄動需要多幀或程式滾動;AI 逐幀不連續。較合適的是**程式效果**:一張可無縫平鋪的靜態霧貼圖(AI 或手畫皆可,≤3 色抖色),由程式以慢速水平捲動/淡入淡出疊在格子上。**屬 technical-artist/godot-specialist 範圍,我標為「需確認」**:能否限定在特定地形格內、是否與 480×270 世界層整數縮放相容(棋子與地形在 SubViewport 內,疊層若在介面層會破壞像素對齊)。
- **成本風險**:(a)新增一套程式效果與測試;(b)依 `ui-code.md` 動畫須可跳過並尊重動態偏好設定,**必須有靜態備援圖**——也就是說**靜態版一定要先做**,動態只是加分;(c)霧會降低整個棋盤的清晰度,若多格相連,地形混排會比題 C 說的「忙」更糟;(d)冷灰藍白是新色相,可能與水面撞色。
- **結論**:迷霧可行但**是兩份工作**(靜態圖 + 程式效果),樹葉/高草是**一份工作**(靜態圖,可選 P1 前景條)。

### 4. 美術推薦

**推薦:茂密枝葉/高草叢**(名稱若可選,「密葉」或「高草」比「迷霧」更配得上「慢」;霧給人「無阻力」的聯想,與成本 3 較不合),先做靜態後景+前景條(P1,不通過則退 P0);迷霧列為日後選配、不納入第二階段。理由:AI 路線一張圖就能交、與灌木拉得開、不需程式也成立、「撥開才過得去」的直覺同時解釋成本與視線。**殘餘風險**:AI 出的草叢仍可能長成「一團實心灌木」——驗收必須看**底部疏、邊緣碎、無描邊**三點(見 L2、L3),這是我會盯的失敗形狀。
