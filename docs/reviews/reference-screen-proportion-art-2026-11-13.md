# 參考畫面比例分析:聖火降魔錄 風花雪月戰鬥畫面(2026-11-13)

> 依據:協調者的文字描述(目視、非量測),我沒看到圖。以下「該圖」的數字都是描述值,不是實測。
> 原則:只學原則,不照搬外觀、角色、介面樣式。
> 作者:art-director。UI 部分標「需 ux-designer 確認」。

## 1. 可學的原則拆解

| # | 原則 | 對我們 2D 像素 640×360 / 48 格的適用性 |
|---|---|---|
| a | 一畫面約 11~12 欄 × 7~8 列 | 可學,但該圖是透視,近處格大、遠處格小,「可見格數」被遠處小格灌水;近處實際只有約 8~9 欄。我們正俯視、格子等大,13.3×7.5 是真格數。見第 2 節 |
| b | 角色身高約 1.3~1.5 格 | 我們棋子 48×60 = 1.25 格高,已在範圍內。**比例本身不是問題**。問題是 48px 寬裡臉只有約 16~20px,而該圖用 3D 模型也沒靠模型臉認人(見 d) |
| c | 格線半透明疊在連續地面上 | 適用,但與比例無關,屬地面風格。我們若已是格狀貼圖,可考慮線更淡以減少雜訊,讓棋子突出。低成本 |

## 2. 可見格數算術

- 我們:640÷48 = 13.33 欄,360÷48 = 7.5 列。
- 該圖描述:11~12 欄 × 7~8 列,且含被裁邊格。
- 結論:**我們的欄數比它多,列數相當,已經不比它「小」**。畫面不是太擠,是單格內資訊太小。
- 若要更接近 12×7(真格數):
  - 640÷12 = 53.3,360÷7 = 51.4 → 格約 **52~54 px**(例:52 → 12.3×6.9;54 → 11.85×6.67)。
  - 若硬取整 11.5 欄、7.5 列:格 = 55.6 / 48 不一致,需 56 → 11.4×6.4。
  - 也就是格從 48 放大到 52~56(+8~17%),可見範圍縮小。
- 這會抵觸今天稍早「格 48、先看 Q 版試畫再決定放大」的裁決,且 +8% 的放大對臉的讀性幫助有限(臉 18px → 20px)。**不建議為了「對齊該圖格數」而放大**。

## 3. 頭像徽章

**能否直接解「臉讀不出」?** 能解「認人」,不解「棋子本身臉醜/武器讀不出」。兩個痛點要分開:
- 認人(誰是誰):徽章有效。把臉放到約 24~28 px 的專用小圖,比棋子上的 16~20 px 臉大約 1.4~1.6 倍,而且可以專門畫(特寫、高對比、無身體干擾)。
- 棋子本身好不好看、武器讀不讀得出:徽章不解。這仍要靠 Q 版試畫(董振豪、秦亦柔)驗證。

**在 48 格下的尺寸**:建議 24~28 px 方形或菱形,貼在棋子頭頂上方、與棋子頂端重疊少許。其高度約佔半格。
**會不會擋棋盤**:會。它佔棋子上方那一格的下半部,擋住:(1)上方相鄰單位的下半身、(2)上方格地形。11 個單位同時顯示時,縱向相鄰的單位會互相遮擋。緩解:
- 只在「選取 / 游標懸停 / 敵我回合切換時」顯示,平時隱藏;
- 或縮到 20 px、只畫臉不畫外框。
- (需 ux-designer 確認:常駐 vs 懸停、遮擋規則、與血量條位置。)

**與既有首字標記(story-039)的關係**:兩者功能重疊(都是「認人」)。選項:
- 徽章取代首字:美術成本新增,但認人最直觀;
- 首字保留、徽章只在選取時出現:成本低,風險最小;
- 首字併入徽章角落:避免畫面兩層標記。
我傾向第二種,先驗證有沒有效。

**美術成本警告**:徽章需要 5 人各一張專畫的 24~28 px 頭像,不能由 128×128 立繪直接縮小(縮小後 1px 描邊與色塊會糊,違反整數對齊與 64 色規範)。這是第二階段/修正單之外的新增資產,需 producer 認可範圍。

另:既有資訊卡(story-048)已有頭像,懸停即可看到;徽章的新增價值是「不需操作就看見」。

## 4. 斜俯視透視

**不建議改。** 理由:
1. 整個資產線(格 48×48、棋子 48×60、64 色、1px 描邊、整數縮放)都建立在正俯視等大格上;透視要每個單位多角度/多縮放,像素風會破壞整數對齊(Check 4 的前提)。
2. 近大遠小要求不同尺寸的棋子精靈,資產量至少翻倍,而且我們已確定是 AI 生圖路線,多尺寸一致性是最弱項。
3. 該圖是 3D 即時渲染,透視是免費的;2D 像素做同樣效果要手工重畫。
4. 它的可讀性好處(臉、徽章)來自徽章,不是來自透視。

## 5. 推薦與選項

**推薦一句**:不改比例、不改透視,畫面格數已不輸該圖;只學「頭像徽章」這一條,且先以「選取/懸停才顯示」的低成本版驗證,等 Q 版試畫結果出來再決定要不要常駐。

| 選項 | 內容 | 優點 | 缺點 |
|---|---|---|---|
| A(推薦) | 維持 48 格;Q 版試畫照進行;另做 5 張 24~28 px 徽章,選取/懸停才顯示 | 不動既有裁決與外包單;徽章解認人 | 新增 5 張小圖;需 ux-designer 定遮擋規則 |
| B | 只做 Q 版試畫,不做徽章,看結果再決定 | 零新增成本 | 若 Q 版仍讀不出臉,多等一輪 |
| C | 格放大到 52~56 以靠近該圖 | 臉略大 | 抵觸稍早裁決;效益小(+8~17%);第二階段/修正單需重規格 |
| D | 改斜俯視 | 最像該圖 | 資產線重做,不建議 |

**對已推給外包的影響**:
- A、B:對第二階段與修正單 1 **無影響**(棋子與格尺寸不變)。徽章若要做,另開新單,不併入已推的單。
- C:會影響已推的單(棋子/格尺寸全改),需撤回重寫。
- D:全面重做。

**待確認**:徽章顯示規則與位置(ux-designer);新增 5 張徽章資產的範圍(producer)。

## 6. 更正與追加(協調者來訊,同日)

### 6.1 更正:第 2、3 節的「臉 18px」

協調者指出矛盾,屬實。我在 `39-blindtest-followup-art-2026-11-13.md` 第八節寫 48×60 現況「頭 8~10px、臉約 4~5px 寬」,而本檔第 2 節與第 3 節寫「臉約 16~20px」「臉 18px → 20px」。**後者是我的錯**:當時我把整顆頭或整個棋子寬度當成臉,數字沒有依據,也與自己先前的數字不一致。以先前的數字為準重算:

| | 頭 | 臉(寬) |
|---|---|---|
| 現況 48×60 | 8~10px | 約 4~5px |
| 格放大到 52~56(棋子隨比例,約 +8~17%) | 約 9~11.7px | 約 4.3~5.9px,**實際仍約 4~6px**,眼點仍塞不進 |
| 徽章 24~28px(臉佔徽章約六到七成,估) | | 約 15~19px 臉(估),約為現況臉的 3~4 倍 |

更正後的結論:
- 第 2 節「放大 8~17% 幫助有限」**方向不變、論據更強**:臉從 4~5px 只增加約 0.5~1px,等於沒變,選項 C 更不值得。
- 第 3 節「徽章臉比棋子臉大約 1.4~1.6 倍」**低估了**,正確是約 3~4 倍(估值,未量測)。徽章對認人的價值因此比我先前寫的更大;它是在不改棋子的前提下,唯一能讓臉達到可辨識尺寸的手段。
- 上述徽章臉尺寸為依比例的估算,不是量測。

### 6.2 story-044 判斷:選牌時移動不可達標記的空白洞

**判:(a)。** 選牌時,不可達標記也補畫到那些格;排除集合改用「實際有畫出來的」攻擊/威脅集合(閘門之後)。

理由:
1. **排除的目的消失了。** `move_breakdown_excluded` 當初的規則是「一格一種標記,攻擊或威脅優先於不可達」,即「讓位」給攻擊標記。選牌時攻擊族標記依裁決已隱藏,沒有東西可讓位,排除就只剩副作用:那些格什麼都沒有。
2. **空白洞會被讀成資訊。** 周圍格有不可達外框與點,中間一塊乾淨格,玩家會讀成「這裡特別、可走、或有東西」。這與我們一直在防的「標記互相矛盾」是同一類錯。
3. **(b) 超出裁決範圍。** 管理者裁決隱藏的是攻擊族三種,沒有裁決隱藏移動族。(b) 是新增一項視覺裁決,而且連帶要決定選牌時可達格的填色要不要也隱藏,影響更大,不屬於修缺陷。
4. **(a) 改動最小**:排除改用閘門後的集合(選牌時為空集合),不動標記形狀、色、圖層。
5. **(c) 不可接受**:洞是真實的視覺矛盾,不是風格取捨。

兩點提醒給實作時注意:
- `threat_cells_final` 同樣要用閘門後的集合,否則威脅格會留下同樣的洞。
- 若日後管理者想讓選牌畫面更乾淨(即 b),那是另一個裁決,可把「選牌時移動族是否隱藏」做成選項請他看圖決定;我目前不建議,因為我沒看到實際畫面,判斷依據只有碼與規格。
