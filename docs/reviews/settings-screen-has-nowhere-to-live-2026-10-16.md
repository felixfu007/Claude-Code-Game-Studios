# 設定畫面「只做最小的」撞到的事:遊戲沒有「戰鬥以外」這個狀態(2026-10-16)

> **狀態**:登記事實 + 三條路的代價。**不裁決。**
> **起因**:管理者 2026-10-16 裁決「設定/選項畫面:**開,但只做最小的**」。
> 協調者在寫那張工作單之前做開工前查核,發現「最小」的形狀跟裁決當下假設的不一樣。

## 一、查核結果(當場可重跑)

```bash
$ grep -n "run/main_scene" project.godot

$ find src -name "*.tscn" | sort

src/ui/battle/BoardView.tscn

$ grep -rn "change_scene" src/ --include=*.gd
(零命中)
```

**七個場景全部是戰鬥相關,而且整個 `src/` 沒有任何場景切換。**
🔴 **遊戲開機直接進戰鬥,然後永遠待在那裡。沒有標題畫面、沒有主選單、沒有戰鬥外狀態。**

## 二、它為什麼讓「只做最小的」變形

猜測標記規格的 **AC13**(`design/quick-specs/battle-hud-prediction-marker.md`)逐字要求:

> 給定玩家在戰鬥中打開選項選單 → EGM 開關應顯示目前值但**不可互動變更**;
> **變更只在下一場戰鬥開始時生效**。

**這條預設了兩個狀態**:一個「戰鬥中」(顯示但鎖定),一個「戰鬥外」(可以改)。
**而第二個不存在。**

📌 **這不是 AC13 寫錯。** AC13 是依管理者 2026-10-16 的裁決
(「不行,整場固定」)寫出來的,而那次裁決沒有人提到遊戲沒有戰鬥外狀態 ——
**包含協調者在內。這是第三個「驗收對象是空集合」的實例,同一天抓到的第三個。**

## 三、三條路與各自的代價(交回裁決,本文件不選)

| | 做法 | 代價 |
|---|---|---|
| **甲** | **戰鬥選單加一列唯讀顯示**(`BattleMenu` 目前有三列,加第四列)。實際開關留給 story-002 的暫代品 | ✅ 最小、滿足 AC13 的字面。<br>🔴 **玩家永遠無法自己打開 EGM** —— 那個模式對玩家而言等於不存在,而它是「正式遊戲功能」(2026-07-29 裁決)。而且本專案登記過「暫代品沒有任何自動檢查會確認它日後被移除」 |
| **乙** | **允許在戰鬥選單裡直接改** | ✅ 玩家真的能用。<br>🔴 **與 AC13「不可互動變更」字面衝突**,而 AC13 的理由(避免同一場內統計資料半套)仍然成立。等於推翻今天的裁決之一 |
| **丙** | **做一個最小的標題/主選單**,讓「戰鬥外」這個狀態存在 | ✅ 一次把根因解掉;而且**遊戲遲早需要它**(存檔、關卡選擇、離開遊戲都要落腳處)。<br>🔴 **明顯超出「只做最小的」** —— 要新增場景、場景切換、以及「從戰鬥回到主選單」的生命週期(而 `BattleMenu` 的「離開確認」目前是直接退出遊戲) |

## 四、協調者的觀察(不是建議,是把牌攤開)

- **甲與乙都是在一個不存在的前提上補洞**,丙是把前提補上。
- **但丙不只是「比較大」** —— 它會碰到場景切換,而本專案目前
  **整個 `src/` 零場景切換**,等於引入一個全新的架構面向。
  🔴 **那很可能需要一次架構決策(ADR),而不只是一張工作單。**
- ⚠️ **協調者未查證**「做一個標題畫面」會不會與 ADR-0005(游標/高亮狀態系統)
  的 Autoload 生命週期假設衝突 —— `CursorStateHost` 掛在 `/root`,
  **跨場景切換時它的行為本專案從未量測過。**
