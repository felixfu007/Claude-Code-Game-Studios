## 一、新規則(要寫進規格的內容)

### 詞彙(修正「極性」混用)

| 新用詞 | 意思 | 會不會隨走位改變 | 資料欄位 |
|---|---|---|---|
| **關係**(好感 / 惡感) | 這兩人合不合 | 不會(只隨劇情/對話/卡牌) | `AffinityLineStatus.polarity` |
| **效果**(加成 / 懲罰 / 無) | 依現在距離,此刻這條線的數值正、負或零 | 會 | `AffinityLineStatus.state` / `delta` |

- 規格中「極性」一詞**只**保留給「關係」。凡原文把「極性」用在效果上的,一律改稱「效果」。
- 「中立」只能形容**效果**(0),**不得形容關係**(關係只有好感/惡感兩種)。

### 規則

- **R1 線形 = 關係。** 好感 = 實線;惡感 = 鋸齒線。(例子取自選項書,**具體畫法交 art-director**,見第三節。)
- **R2 線色 = 效果。** 效果為正 = 綠、為負 = 紅(沿用現有兩色,色值不動)。
- **R3 效果為 0(距離 2)時,棋盤上不畫線。**(管理者裁決。)
  🔴 後果:距離 2 時,玩家在棋盤上看不到這兩人有關係。我的處置建議:
  (a) 不新增任何灰線/淡線(尊重裁決);
  (b) 該對關係**仍可在關係圖查到**(見 R4);
  (c) 游標預覽/資訊列既有的「好感度 %+d→%+d」不變。
  ⚠️ 副作用要知道:一條線走一步從「無線」變成「綠實線」,玩家看到的是「線出現了」,而不是「線變色」。這對「往前走一步會變好還是變壞」的可預判性有利有弊:出現的線形(實/鋸齒)直接告訴你是好還是壞,但**出現之前**看不到。**往距離 2 外的格子預覽時(Mode A 假想站位)線是照假想位置畫的**(`affinity_line_dicts` 本來就吃假想位置),所以游標停在目標格就能預先看到,不必真的走。這點要靠 AC-5 鎖住。
- **R4 關係圖(迷你地圖):建議 — 十條關係一律畫出(形狀 = 關係),效果為 0 時不上色、不寫效果符號,線用圖面的中性前景色;效果非 0 時上色並標 `+`/`−`。【需協調者確認】**
  理由:
  - 管理者「沒效果就是什麼都沒有」是針對**棋盤太雜**說的;關係圖是專用的、收合的、疊在棋盤上的單一用途面板,它存在的理由就是「一眼看懂五人關係結構」(`relation-minimap.md` 第 1 節)。五邊形固定排列、至多 10 條線,不像棋盤會被地形與棋子切碎,「髒」的風險小得多。
  - `game-concept.md` 第 244 行本來就要求「全圖檢視模式僅顯示好感度極性與強度」——**全圖該畫的正是關係**。若關係圖也在距離 2 時把線拿掉,它就無法回答「誰跟誰是什麼關係」,失去存在理由。
  - 這確實**不是**「棋盤與關係圖同一套」的字面照辦(關係圖多畫了棋盤沒畫的線)。**兩種取捨,選一個:**
    - **R4-甲(我的建議)**:關係圖十條都畫;0 效果線無色、無符號。
    - **R4-乙(字面照辦)**:關係圖與棋盤同集合,0 效果就不畫。優點:規則只有一條;缺點:五邊形圖上常缺線,玩家無法用它查「這兩人到底合不合」,對測驗一不利。
  - ⚠️ R4-甲 的 0 效果線**不算灰線**(沒有「0」符號、不是「低對比灰」),但視覺上仍是一條線——這點請管理者確認是否可接受。
- **R5 效果的第二通道(非色彩)。【需協調者確認,見第三節問題 3】** 棋盤線必須另有一個**非顏色**通道表達效果的正/負。可選方向(長相交 art-director,不由我定):
  - 線寬(正粗/負細或相反);
  - 線中點的小符號 `+`/`−`(關係圖現已這樣做,詳見 `relation_minimap.gd` 的 `symbol_for`);
  - 端點標記。
  **約束**:不得與「形狀」(R1)混淆;1px 線在 480×270 下已偏細(現行線底襯 3px、線身 1px)。**我傾向中點符號**,因為關係圖已有同一套,「棋盤與關係圖同一套」的裁決最容易滿足,但字在 32×32 格上是否可讀要美術驗證。
- **R6 詳情區文字**:關係圖詳情區每列 = 對象名 + **關係文字(好感/惡感)** + **效果與強度數字**。這是文字,不在棋盤上(棋盤不寫「好感/惡感」,保護探針,見第四節)。
- **R7 色盲模式**:形狀(R1)與第二通道(R5)皆不隨色盲模式改變(非色彩通道);色盲模式只影響 R2 的色值。

### 新驗收條件(可測試)

> 取代/增補 `design/ux/relation-minimap.md` 第 8 節 AC-3、AC-5,並新增棋盤 AC。像素/視覺證據依專案規則須**人開圖確認**。

- **AC-P1(形狀只由關係決定)** Given 同一對角色,When 其距離依序為 1、2(R3 之外)、≥3,Then 該對線的**形狀**(若有畫)在所有距離下都相同(`polarity` 不變 → 形狀不變)。測法:對 `affinity_line_dicts` 輸出斷言形狀欄僅取決於 `polarity`。
- **AC-P2(顏色只由效果決定)** Given 同一對角色,When 距離改變使效果符號改變,Then 線色隨之改變、形狀不變;好感 + 太遠(−1)= 實線 + 紅,惡感 + 相鄰(−1)= 鋸齒 + 紅,**兩者形狀不同**。
- **AC-P3(0 效果不畫,棋盤)** Given 任一對效果為 0(含距離 2 的好感與惡感),When 棋盤繪製連線,Then 該對**不產生任何 Line2D**(`_affinity_line_layer` 子節點數 = 效果非 0 的對數 × 每條線的節點數),且**不存在 `MUTED` 灰色筆畫**。
- **AC-P4(關係圖對 0 效果)** 依管理者對 R4 的選擇:甲 → 關係圖十對全畫,0 效果對無色、無 `+/−/0` 符號;乙 → 與 AC-P3 同集合。
- **AC-P5(預覽一致)** Given 游標停在假想目標格(Mode A),Then 棋盤連線依假想站位的效果重算:距離變為 2 的線消失、離開距離 2 的線出現,形狀正確。
- **AC-P6(非色彩)** Given 灰階截圖,When 檢視棋盤連線,Then 可僅憑**形狀 + R5 第二通道**分辨「好感/惡感」與「正/負效果」四種組合,不靠顏色。
- **AC-P7(同一來源)** 「`AffinityLineStatus` → (形狀, 色調)」的轉換只有一處(沿用原 AC-3 的 `^static func` 錨定 grep),關係圖與棋盤共用,不得各寫一份。
- **AC-P8(棋盤無字)** Given 棋盤連線繪製,Then 不出現「好感」「惡感」等關係文字(保護教學探針)。
- **AC-P9(詞彙)** Given `design/ux/relation-minimap.md`,When 搜尋「極性」,Then 命中處皆指「關係」;搜尋「中立」,Then 無任何命中把它形容關係。

## 三、交 `art-director` 的問題(我不定畫法)

1. **鋸齒線具體長相**:在 480×270 世界層、32×32 格、現行底襯 3px/線身 1px、`antialiased = false` 的條件下,鋸齒線的**振幅(px)、週期(px)、是否需要加粗**到什麼程度才能與實線在 1× 世界層(放大 4~8 倍後)一眼分辨?實線與鋸齒線在**斜線(非水平/垂直)**上都不能糊成一樣——請實畫兩種線在四個方向與 45° 的樣張。
2. **關係圖(UI 層,原生解析度、非像素字級)同一套形狀**:世界層是 nearest 整數放大、關係圖是介面層原生像素,兩邊的鋸齒要「看起來是同一種語彙」,畫法是否同一組參數按比例換算?

## 四、對教學關「不講因果」探針的影響

- **有利**:形狀是**無文字**通道,棋盤不寫「好感/惡感」(AC-P8),玩家仍須自己把「鋸齒線的兩人」歸因為「合不來」。探針測的是「玩家會不會自發歸因」,而不是「玩家看不看得見關係」,丙保留了前者。
- **有風險**:
  1. 「看得見關係」本身會提高玩家歸因的機率,探針的**基線**變了。若探針(`vertical-slice-level-01.md` 驗收第 3 條)的通過門檻是在「畫面不顯示關係」的前提下訂的,**門檻要重議**。【未驗證:該探針是否仍要執行;我沒讀該檔】
  2. 教學關 S4 才首次出現連線(`tutorial-level.md` 第 49 行)。一次引入兩個軸(形狀 + 顏色)比現在只引入顏色多一個學習負擔。**建議**:S4 的教學提示維持一句、**不講因果**,例如只指出「線的樣子有兩種、顏色有兩種」之類的指認性提示,不講「所以怎麼站」。具體措辭交 narrative/game-designer。
  3. 「距離 2 無線」會讓 S4 的玩家在某些站位完全看不到線;教學關的出生佈陣是否落在距離 2,**未驗證**,需逐局面看。
- 不論如何,教學不得出現「好感/惡感」字樣在棋盤上(AC-P8);關係圖內的詳情區文字是玩家主動開啟,不計入。
