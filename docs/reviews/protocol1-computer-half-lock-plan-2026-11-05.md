## 0. 先講三個會影響設計的實測發現(都出自讀程式,不是推測)

1. **畫面上不顯示連線的極性(好感/惡感),只顯示「目前這一格的狀態」。**
   `RelationMinimap` 只畫 `+`(實線)、`-`(實線)、`0`(虛線),來自 `AffinityLineStatus.State`,
   而 State 由**當下 delta 的正負**決定(`AffinityLineStatus._classify`)。
   `AffinityRules.delta` 的對照表:好感連線 距離1=+3、距離2=0、距離3+=-1;惡感連線 距離1=-1、距離2=0、距離3+=+2。
   → **符號 `-` 可能是「好感連線拉太遠」也可能是「惡感連線靠太近」;符號 `0` 可能是任一極性在距離 2。**
   極性在畫面上只能靠「符號 + 距離」反推。這是本量測最有價值的標的(P2 要量的就是它)。
   (極性在 `battle_screen.gd` 唯一被直接讀取處是開場好感度記錄種入,不是顯示;棋盤上的線色是否另有極性提示:**未查證**。)
2. **EGM 的「猜測前」狀態,畫面刻意藏起了答案**:游標在候選格、尚未猜時,預覽數字與棋盤上的假設連線都不畫
   (`battle-hud-prediction-marker.md` 第 2 節步驟 3 及 2026-10-28 裁決)。所以「預判者能看到什麼」=
   **移動前的現況**(各連線現在的狀態、雙方位置),加上候選格的座標;**不包含**候選格的預覽值。
3. **每關只有 2 條連線**(`vs02`~`vs05`:1-2 好感、3-4 惡感;`tut04`:1-2 好感;`tut01`~`tut03` 無連線,`tutorial_no_links.txt`)。
   → 只有名冊 1~4 號有可猜的東西,5 號恆為「無效果」;局面空間小,**多數候選格的正解會是「無效果」**
   (距離 2 或不接觸連線)。這直接決定 P0 的分數,見第 4 節。

## 1. 三種預判者的精確定義

共同點:全部**決定性**(無 RNG、無種子;本專案禁戰鬥結算 RNG,且測試要求決定性)。
共同輸入單位:一個「決策」= (關卡, 局面, 一個我方單位 u, 一個候選格 c)。分類三態沿用
`EffectGuessTracker.EffectDirection`(POSITIVE/NEGATIVE/NEUTRAL;`classify_delta` 為正解分類,見第 3 節)。

### 預判者「能看到的資訊」(對應畫面上真的顯示的東西)

| 資訊 | 畫面上的來源(讀過) | P0 | P1 | P2 |
|---|---|---|---|---|
| 候選格 c 的座標、u 目前位置、各我方單位位置 | 棋盤(`BoardView`) | 否 | 是 | 是 |
| u 的每條連線的對象與**目前狀態**(+/-/0) | `RelationMinimap.set_lines()`(與棋盤線同一份 `AffinityLineStatus` 陣列) | 否 | 是 | 是 |
| 距離規則表(距離→加成) | 玩家教學/說明文字:**未查證**是否教過 | 否 | 否(只用符號直覺) | 是(假設已被教過,**上限**設定) |
| 連線真實極性、候選格預覽值 | 猜測前**不顯示**(第 0 節 2) | 否 | 否 | **否**(只能推論) |

### P0 底線(「不讀畫面也能拿到幾%」)
不看任何資訊。報告**四個**決定性猜法,各自一個分數,**取其中最高者為 P0**:
- P0-neutral:一律猜「無效果」
- P0-positive:一律猜「正」
- P0-negative:一律猜「負」
- P0-cycle:對該局面內該單位候選格,依**行優先(y 再 x)座標序**輪流猜 正→負→無→正…(固定序、不隨機,代表「亂猜」的期望,重現性靠固定走訪序)。
另報**正解類別分布**(正/負/無各佔幾 %),因 P0 取決於它。

### P1 天真讀者(只用畫面上直接看得到的符號與位置)
規則(寫死):對 u 的每條連線 L(對象 p,目前符號 s ∈ {+,-,0}):
- 令 d = 目前與 p 的曼哈頓距離,d' = u 站到 c 後與 p 的距離(距離一律呼叫 `AffinityRules.manhattan_distance`,不自己寫);
- 票 v(L) = sign(s) × sign(d − d')。「+」連線靠近得 +1、拉遠得 −1;「-」連線靠近得 −1、拉遠得 +1;「0」連線得 0。
- 總票 > 0 猜正,< 0 猜負,= 0 猜無效果。
這代表「把符號當成『這個人是朋友/敵人』然後走近朋友、遠離敵人」的直覺讀法;**它刻意不知道** `-` 可能是好感連線拉太遠。
- ⚠️ P1 的定義權在作者(我),代表的是「一種合理的天真讀法」,**不是新手實際會怎麼讀**;報告時必須如此標註。

### P2 完整讀者(上限:畫面資訊在邏輯上是否足以推出答案)
假設讀者**已知距離規則表**,但只能用畫面資訊:每條連線的目前符號 + 目前距離 d。
- 對每條連線枚舉**所有與畫面一致的極性**(用 `AffinityRules.delta` 驗證「該極性在距離 d 下算出的 delta 其符號 = 畫面符號」;
  實際上只有距離 2 的 `0` 線兩種極性皆一致,其餘唯一)。
- 對每一組極性假設,**建構真實的 `AffinityLink` 陣列,呼叫真實的 `AffinityRules.bonus_for_at` / `bonus_for`**(含夾限、含全部規則,
  不在腳本內重寫任何一條),得到該假設下的 delta,再 `classify_delta`。
- 所有假設得到**同一類別** → 猜該類別(「可決定」);否則 → 「**無法決定**」(abstain)。
- 回報兩種計分:**P2-strict**(無法決定算答錯)與 **P2-tie**(無法決定時決定性選擇:假設中出現最多次的類別;平手選「無效果」)。
- 預期並**事先寫死**:可決定的決策,P2 正確率在構造上應為 100%(因真實極性必為某個一致假設);
  **若可決定的決策出現任何一筆答錯 → 視為量測腳本或規則不一致的缺陷,停止、不得往下解讀,回報管理者**(第 4 節)。
  P2 真正的資訊量在「無法決定比例 U」。
