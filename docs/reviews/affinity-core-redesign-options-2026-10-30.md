## 1. 問題陳述(白話)

協議 2 的電腦對照判定未通過:不看好感度 8 組贏 4 組,看好感度 8 組全輸
(`production/qa/protocol2/computer-attempt-1-20261030T0120Z/VERDICT.md`「步驟 B」)。診斷說出為什麼
(`prototypes/protocol2-diagnosis-2026-10-30/README.md`):

1. **好感度的收益很小。** 每次攻擊多出的傷害只有 −1~3(F3,「各 EFFECT 行 `phi=`」);整局運用臂 ΣΦ 11、忽視臂 7,**只差約 4 點傷害**,卻因為站位少打 4 次攻擊(8 對 12),少輸出約 20 點。
2. **貼在一起有代價,而且代價大於收益。** 「甲乙留後、貼著不動」在 R1 就讓可攻擊格從 25 格剩 1 格(F2 `pool_before_step2: 25 -> pool_after_step2: 1`)。
3. **沒有關係線的戊被甩出陣型。** 戊 Φ 恆為 0、不受牽制,獨自前衝被集火:30→25→20→14→8→2→0(F2)。敵方總傷害兩臂差不多(65 對 71),差別只在「集中在誰身上」。
4. **「任一人倒即敗」把集中放大成致命。** 已查證 `BattleState.outcome()`:我方任一單位死亡即敗。忽視臂分散承傷(15~27)、無人倒;運用臂 戊 一人承受 30(F1、F2)。
5. 誠實限制:VERDICT「判讀限制 4(1)」指出電腦的運用臂把好感度排在「能不能攻擊」之前,比鎖定文字強硬;診斷 F4 也顯示「只當平手鍵」則與忽視臂完全相同。**兩者合看:好感度要嘛太貴(強硬)、要嘛沒作用(溫和),中間沒有一個划算的用法。** 這才是設計問題,不只是電腦策略問題。
6. 設計原則(推導自上): **「為好感度放棄一次攻擊」的代價必須小於它的收益。** 現況:一次攻擊基礎傷害約 10(甲 ATK16 − 敵 DEF 約 6,(推估) 讀自 `vs01_roster.txt`),Φ 最多 +3 = 約 +30%。放棄 1/3 的攻擊換 +30% 傷害,打平而且還擔風險,所以不划算。

## 2. 核心調整方案

### 方案 A:放寬有效距離(正向關係死區取消)

- **改什麼**:R3 正向關係距離 2 由 0 改為 **+3**(與距離 1 相同);距離 ≥3 仍 −1;負向關係不動。(`affinity-position-chain.md` Core Rules R3 表、R6)
- **影響(推估)**:乙丁射程 1~2、丙 2~4,可站「相隔一格」仍拿滿加成,同時從容攻擊;「貼身」的代價(可攻擊格剩 1 格)大幅下降。收益本身不變(仍 +3),所以只修「代價面」。ΣΦ 上限仍約 +10。
- **動到的文件**:`affinity-position-chain.md` 的 R3、R6(合作/對立 50% 差距須重新裁決)、「公式一」與「算例」、「交叉校準結果」、Tuning Knobs、AC 中釘住距離-數值表者;`affinity-data-pool.md` 與 UI 的預覽文字若引用「死區」。
- **既有測試**:約 20~30 條(推估;`affinity_rules_test.gd` 有 83 處相關引用,其中釘 R3 具體數值者需改)。
- **支柱檢查**:支柱四(`game-concept.md`「支柱四:羈絆是雙面刃」)要求任何狀態組合不得無代價純正向。正向「遠」(≥3)仍 −1,**仍有代價**,但「正近」的代價(站位受限)明顯變輕,**邊緣風險**:需 creative-director 確認。「距離 2 是刻意死區、靠近遠離必須是明確選擇」(R3 原文)的設計意圖被削弱。無 RNG,不違反零隨機。

### 方案 B:收益擴到防禦面(好感度也減傷)

- **改什麼**:除加成輸出外,單位若 Φ > 0,**被攻擊時傷害 −⌈Φ/2⌉**(最少 0)。這是 Φ 的第二個輸出通道,數值為提案起點。(涉及 `tactical-combat-system.md` 傷害公式,`max(0, ATK − DEF + Φ)` 旁加一項;`affinity-position-chain.md` Overview、公式一)
- **影響(推估)**:Φ = +3 的單位承傷 −2;敵方 ATK 13~14 打 DEF 6~8 現為每下 5~8,變 3~6,約少 25~40%,我方「被打幾下倒」由 4~6 下變約 6~9 下。**讓「靠近」的收益同時含存活,而存活正是一人倒即敗規則下最值錢的東西。** 也補上 GDD 自己承認的缺口:Overview 註記「Φ 只覆蓋輸出通道,敵方 ATK 虛高造成的承傷劣勢完全不覆蓋」(已查)。但戊 Φ=0,**仍然拿不到好處**,集火他的問題不變。
- **動到的文件**:`tactical-combat-system.md` 傷害公式、Core Rules #7 敵方優勢校準;`affinity-position-chain.md` Overview、公式一~三、交叉校準;`unit-stats-provisional.md` 的「被打幾下倒」表須重算;AI(`GreedyTacticalAI`)傷害預估;UI 傷害預覽。
- **既有測試**:約 30~50 條(推估;傷害預覽、AI、戰鬥結算皆讀 Φ)。**跨系統改動**(戰棋 + 好感度 + UI)。
- **支柱檢查**:無 RNG。支柱四:負向的對應(是否也「減傷減少」)需決定,否則負向關係的代價面不對稱;建議 Φ < 0 時不加傷(僅 Φ>0 減傷),但這讓負向路線相對更弱,R6 的 50% 差距又要重議。**風險中等。**

### 方案 C:放寬「一人倒即敗」(戰棋規則,跨系統)

- **改什麼**:敗北條件由「任一我方死亡」改為「我方 **2 人**以上死亡」(旋鈕 `defeat_death_count` = 2,可調 1~3)。(`BattleState.outcome()`;`tactical-combat-system.md` 敗北條件相關節;vs01 等關卡 AC)
- **影響(推估)**:不改 Φ。把「集火戊一人」從致命變成可承受,好感度的空間價值才有機會在結果上顯現。但它**同時也讓忽視臂更容易贏**,兩臂的通關率同步上升,**不保證好感度組相對更好**,只保證「比較有資訊」。
- **動到的文件**:`tactical-combat-system.md`(敗北條件、各關預期)、`vertical-slice-level-01.md`「預期回合數」、教學/各關的失敗畫面文字、`endings.md` 與好感度陣亡處理(`affinity-position-chain.md` 陣亡規則與「死亡權重」敘事:一旦戰鬥中死人不再等於結束,陣亡後續就要接得上)。**未查證** 敘事端是否預設「死人=失敗」。
- **既有測試**:約 13 處引用 `Outcome.DEFEAT`(已查,散在 10 個檔案);需改者約 8~15 條(推估)。
- **支柱檢查**:無 RNG;零隨機承諾不受影響。與「不會有靠機率造成的永久角色死亡」(`game-concept.md`「不是什麼」)相容。**⚠ 治標不治本且是戰棋核心規則,屬 `tactical-combat-system` 管轄,需 creative-director/該系統擁有者裁決。**

### 關於戊(三案共通的開放問題)

戊「沒有關係線、不選邊」是敘事設定(`unit-stats-provisional.md` 與診斷 F2 提到的 `vs01_affinity_links.txt` 只有 1-2、3-4 兩條)。若幫他加關係線,會動到敘事與結局(`endings.md`),屬 narrative-director 範疇,**本提案不做**。戊的問題在任何 A/B 方案下都剩下「他是前鋒,會被集火」;能解的方式是 C,或讓關卡/敵 AI 的集火規則不專挑他(戰棋/AI 範疇,不在本提案內)。

## 3. 優缺點與推薦

| | 優 | 缺 |
|---|---|---|
| A 放寬距離 | 改動最小;只修「代價面」;符合第 1 節原則(降低放棄攻擊的機率);無跨系統 | 不增加收益;削弱「死區=刻意選擇」;戊問題完全沒解 |
| B 加防禦面 | 同時加大收益與存活;補上 GDD 自承缺口;存活直接對應「一人倒即敗」 | 跨系統(戰鬥公式、AI、UI);對戊無效;R6 對稱性要重議 |
| C 放寬敗北 | 直接拆掉放大器;最能讓比較「有資訊」 | 戰棋核心規則;可能連忽視臂一起變強(相對差不變);敘事端未查;有「為了過測而改規則」的觀感 |

**推薦:A + B 兩案的最小組合不建議一次做,先做 B,再視需要補 A。** 理由:診斷的核心是「收益(+4 點)遠小於代價(−20 點)」,而且一人倒即敗讓存活價值遠高於輸出;B 直接把好感度的價值轉到存活上,A 只降代價。C 雖然最有效,但它改的是「問題的測量方式」而非好感度本身,與管理者裁決「重新設計好感度核心機制」的字面距離最遠,建議保留為最後手段。
**單一推薦:方案 B。** 注意這是推估,**未經任何引擎驗證**;B 對戊無效,所以仍可能不過。若要更保險,B 加 A(兩案獨立,改動面可相加)。

## 4. 防過擬合規則(硬性)

重測用的是**已鎖定門檻**(H `20e0854`)與**新的預先登記**。為了讓重測真的有證據價值:

1. **第 1 場保留為重測專用。** 任何方案的評估若需要電腦實測,**只能在第 2~5 場**跑。重測前**不得**用任何新數值(新 R3、新減傷、新敗北條件)跑第 1 場,包括「只看一眼」「確認有沒有壞」。
2. 第 2~5 場的結果**只用於判斷方案是否合理(沒爆表、沒全滅)**,**不得**用來微調到某個通關率;一旦開始「調到好看」就等於把它們也變成訓練集。
3. 方案裁決後、重測前,**把最終數值寫入一個進版控提交**(時間戳在先),再跑第 1 場;與先前門檻鎖定做法相同。
4. 重測時電腦對照的運用臂/忽視臂策略**必須先登記**,且運用臂須是 VERDICT「判讀限制 4(1)」兩種讀法(強硬/溫和)之外**事先說明哪一種**,不得看了結果再換。
5. 此條規則只靠紀律,**沒有自動檢查**;最強的保險是第 1 場在重測前完全不被執行。

## 5. 給管理者的白話摘要

1. 上次失敗的原因不是電腦太笨,而是「靠好感度站位」換到的好處太小,付出的代價太大。
2. 好處:每一擊多打 0~3 點傷害。代價:為了站位少打了幾次攻擊,而且沒有關係的戊一個人衝前被圍攻,死一人就輸。
3. 方案 A:放寬「要貼多近才有加成」,讓站位不必那麼擠。改動最小,但好處沒變大。
4. 方案 B(推薦):讓好感度除了多打傷害,還能**減少受到的傷害**,直接幫「不要死人」。要改戰鬥公式,動到的範圍較大。
5. 方案 C:改成「死 2 個人才輸」。最有效,但是改戰棋的核心規則,而且連不看好感度的玩法也變容易,比較像改考卷而不是改教學。
6. 三個方案都沒辦法幫到戊本人,那要改敘事或敵人 AI,另案。
7. 防作弊規則:第 1 場關卡在重測前完全不碰,新數值只在第 2~5 場看有沒有爆掉。
8. 以上都是推估,沒有實測。需要你裁決:選哪一案(推薦 B)、是否接受跨系統的改動範圍。
