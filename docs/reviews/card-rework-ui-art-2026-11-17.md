## 一、9 項決定

### 1. 三態徽記(POS / NEG / NONE)

- **決定**:徽記用介面層圖元,色 `ui_text_primary_01` #FFFFFF,外圍 1px `nature_void_shadow_01` #0E0F14 描邊;1 個源像素 ≥ 2 螢幕像素(最小視窗 N=2 下,須以 `HudLayout` 倍率整數放大、nearest,不補間;倍率數值未驗證)。
  - **POS 好感**:7×2 實心橫條(置中於 7×7 格)。
  - **NEG 惡感**:7×3 鋸齒,1px 筆畫,端點 (0,0)(1,1)(2,2)(3,1)(4,0)(5,1)(6,2)。
  - **NONE 冷淡**:5×5 空心點(四角缺一格的圓環,中空),**不得含任何橫線**。
- **理由**:形狀對應棋盤線(實線/鋸齒),冷淡是「沒有線」的對應物,用空心點避免被當成弱關係。白色避免與效果色(金/紅)混義。三者在灰階與色盲下僅靠形狀 + 旁邊兩字即可辨(三通道:字、形、位)。
- **混淆風險**:POS 橫條與減號 `−` 符號牌(5×5)形近。緩解:徽記只出現在資訊卡/手牌/面板文字旁、必與「好感」字並列,符號牌只在棋盤線中點、深色牌底,兩者不同畫面層。風險低但**須 N=2 截圖人眼確認(未驗證)**。
- **管理者裁決**:否。

### 2. 加成 / 懲罰色值

- **決定**:**懲罰 = `ui_state_negative_01` #FF5252(維持)**;**加成 = `ui_state_warning_01` #FFBF4D(既有色,暫用)**。符號牌 `+`/`−` 圖元用同線色,牌底維持深色不透明(現行 AFFINITY_PLAQUE,近 #0D0D12)。
- **理由**:你的約束是只用既有色;票上沒有比 #FFBF4D 更淡的暖金。#FFBF4D 與 #FF5252 手算亮度比 ≈ (0.5905+0.05)/(0.2791+0.05) ≈ **1.95:1(未驗證)**,灰階下仍可分,加上形狀與符號牌兩個非色彩通道,不違反「不得只靠顏色」。
- **混淆風險(中)**:**琥珀變成 4 用** —— 可攻擊環、card_target 合法框、HP 預覽字、加成線。緩解:①選牌/選敵期間攻擊環已隱藏(11-12 裁決),不同屏;②線是細線 + 7×7 牌,框是 2px 閉合外框(inset 3),形狀不同;③**我 11-12 自己寫的約束「加成金須明顯比 #FFBF4D 亮」在此被放寬** —— 這是為遵守「只用既有色」而放寬,**不是我認為更好**。紅仍是三用,本檔不新增第四用(見第 6 項刻意避開紅)。
- **管理者裁決**:**是(Q1)**。推薦 A:新增一色「淡金」(建議試畫值約 #F2DE8A,**未驗證**,屬建議),色票 48→49/64,並須重過 #FF00FF 檢查與和 `ui_state_warning_01` 並排辨識;B:維持現決定(既有 #FFBF4D)。**在管理者回覆前,以 B 為準,常數單點可換。**

### 3. 關係圖灰線(效果 0 的有關係線)

- **決定**:色 `metal_base_01` #6B7280,**不透明、不用 alpha**,形狀保留(好感實線 / 惡感鋸齒),**不放符號牌**;冷淡不畫線。
- **理由**:不用半透明是為了不產生色票外的混合色;手算 #6B7280 亮度 ≈ 0.167,對關係圖面板底 #1A1A1F(≈0.010)比值 ≈ 3.6:1(未驗證,過 3:1 的非文字門檻);與金(≈0.59)/紅(≈0.28)亮度分層,且**灰線無符號牌**,所以灰階下三通道:亮度、形狀、有無牌。「有灰線 = 有關係;完全沒線 = 冷淡」靠有無線區分,不靠灰階深淺(符合規格 4.3)。
- **混淆風險**:灰線對紅線亮度比僅 ≈ (0.329/0.217) ≈ 1.5:1(未驗證),灰階下偏弱;但紅線有牌、灰線無牌,可分。與棋盤上的 `#808080` 不合法 X 同屬灰,但不同畫面(關係圖 vs 棋盤),不混。
- **管理者裁決**:否。

### 4. 選敵:card_target 框 vs 一般攻擊環

- **決定**:**圖形不再新增**,靠「互斥 + 現有形狀差」:選敵期間攻擊環/移動/威脅層全隱藏(AC-5 驗);card_target 維持**閉合 2px 外框、inset 3、琥珀 #FFBF4D**;攻擊環是 2px 琥珀環**帶首字框缺口且省略 HP 文字條**(story-044)。不合法 = 同形外框改 `ui_divider_01` #808080 + inset 7 的 X。
- **理由**:兩者色同(皆 #FFBF4D)是既成事實,分界靠形狀(閉合無缺口 vs 有缺口環)與互斥;不再加第三種琥珀圖形。
- **混淆風險(低,前提是隱藏真的做了)**:**現行 `_card_selecting_target` 是否隱藏攻擊環未驗證**(規格 10-2 同)。若沒隱藏,兩個同色琥珀圖形並存,風險升為中,須補做隱藏而不是改色。
- **管理者裁決**:否。

### 5. 「被擋住」章與「框 + X」同格

- **決定**:**互斥,章取代 X**。敵人在射程內但視線被擋 → 該格只畫**灰框(#808080)+ 被擋章**,**不畫 X**;射程外/太近 → 灰框 + X,不畫章。繪製順序:框 < 章。
- **理由**:讀程式常數:章位於格內 (21,8)-(27,14),X 的對角線(inset 7)從 (25,7) 到 (7,25),**會經過約 (21,11) 穿過章的範圍** —— 疊畫會讓斜線與章斜線交錯糊成一團(手算座標,未驗證實繪)。兩種原因本就不同(規格 2.2 #3),各用自己的符號、不並存。
- **混淆風險**:低。須在樣張確認章不被框內緣擠壓(章右緣 x=27 恰貼框內緣 27,**零間隙,未驗證**;若貼死,章左移 1px,由 ui-programmer 以樣張定)。
- **管理者裁決**:否。

### 6. 代價圖示、`✕`、「無法出牌」鈕

- **決定**:
  - 圖示(面板代價列前,7×7,白 #FFFFFF + #0E0F14 描邊,**刻意不用紅**):**付血 = 水滴**;**折損 = 斷開的兩個環(中間缺口)**;**各付血 = 兩個並排小水滴**。
  - `✕`:字元 + 該列文字用 `ui_state_warning_01` #FFBF4D(沿用確認面板既有 `WARNING_COLOR` 語意 = 警示),不用紅。
  - 「無法出牌」鈕:沿用現行 HUD 停用樣式(透明底、灰框 (0.5,0.54,0.6)、灰字),**鈕面文字 `無法出牌`**,不加鎖、不壓暗整個面板。
- **理由**:與 S5「壓暗 + 鎖」區分的是**範圍與圖形**:S5 是整條手牌壓暗 + 掛鎖圖示(鎖是 Panel 圖元),本處只動一顆鈕、一列字、用 ✕ 不用鎖 —— 補救動作不同(S5 等敵方回合;這裡換人/換牌)。不用紅避免第四個紅用途。
- **混淆風險**:低;水滴與紅色血條是否被讀成「血條」—— 因為白色而非紅/綠,風險低(**玩家是否一眼懂水滴 = 血:未驗證**,屬人眼確認項)。
- **管理者裁決**:否。

### 7. c12 兩次傷害數字與受擊

- **決定**:
  - 數字:`−6` 文字,白 #FFFFFF + 1px #0E0F14 描邊(同棋子首字慣例),**不用紅**;出現在目標頭上,靜止、不上飄。
  - 受擊:目標水平位移 2px 一個來回(120ms),**不閃色、不閃爍**。
  - 時序(**調整旋鈕,起始值;未驗證**):數字停留 700ms、兩擊間隔 500ms;第二擊數字顯示在第一擊同位置上方一行(不重疊)。「減少動態」:取消位移,**間隔保留**(資訊),停留縮至 400ms。
  - 第二擊略過:不播動畫、無數字;回合訊息列顯示 `第二擊略過`,與其他回合訊息同樣式(白字,無色碼)。
- **理由**:無閃爍;兩個數字分開 = 看得出兩人各一手;不用紅是避免第四個紅用途。
- **混淆風險**:低。**時間數值須實機試畫,人眼確認節奏**(Check 5)。
- **管理者裁決**:否。

### 8. 騎牆有效 / 失效徽記

- **決定**:白 #FFFFFF + #0E0F14 描邊,7×7 盾形。**有效 = 實心盾**;**失效 = 空心盾輪廓 + 一條左下到右上的 1px 斜線穿過**。
  盾形參考(每列 7 格):`#######` ×4 列 → `.#####.` → `..###..` → `...#...`;失效版保留外輪廓、清空內部,再畫斜線。
- **理由**:實心 vs 空心 + 斜線是形狀通道,灰階下仍分;與資訊卡文字 `騎牆：有效/失效` 並列,三通道。白色不帶效果色。
- **混淆風險**:斜線與被擋章斜線(也是左下到右上)同方向,但章在棋盤格角、盾在資訊卡文字旁,不同畫面層,風險低(未驗證)。
- **管理者裁決**:否。

### 9. 手牌 Z2 卡面角落三態徽記

- **決定**:卡面(4.5×6 fpx,fpx = 字級單位,卡約 49×66 源像素,**換算未驗證**)**右下角**放 7×7 三態徽記 + 其左側 `好感/冷淡/惡感` 2 字(11px 字 ≈ 22px 寬),整組貼卡內緣 2px;**只用在雙人卡**。「永久」標示與類別圖示維持在卡面上半(左上),不動。
- **理由**:Z2 文字內容(`ATK+3`、`〔永久〕`)在上、中段;右下是目前唯一我不認為被占用的角(**我只讀到文件草圖,未讀實際 hand_bar.gd 版面,未驗證**)。若實作發現被占,退路:徽記改置左下,文字不動;不縮卡面字級。
- **混淆風險**:右下三態徽記與卡面「永久」邊框/◆ 圖示不同形;**未驗證 1280×720 下 2 字 + 徽記 ≈ 31 源像素是否塞得進卡寬而不換行** —— 須截圖。
- **管理者裁決**:否。
