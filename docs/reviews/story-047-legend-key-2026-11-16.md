## 2. 結論:鍵位

動作名:**`battle_open_legend`**(與既有 `battle_*` 一致;語意為「切換圖例」,同一鍵開/關)。

| 裝置 | 綁定 | 理由 |
|---|---|---|
| 鍵盤 | **L**(Key 76) | 記憶法 Legend;與現有 C/X/R/Q/M/H/Tab 全部不衝突;離方向鍵與 Enter/Esc 一段距離,不易誤觸;單鍵不需修飾鍵。 |
| 手把 | **LT(左扳機,軸 4,觸發門檻 0.5)** | 手把 11 顆常規鈕(A/B/X/Y/Back/Start/左右搖桿按下/LB/RB)**已被佔滿**;剩下的 Guide 鍵是平台系統保留(Xbox/Steam 會攔走),不可用。扳機是唯一還空的、且一般不會被誤碰的位置。 |
| 滑鼠 | 無專用鍵,走選單「圖例」列(story-046) | 滑鼠玩家本來就用選單;工單已定。 |

被否決的備選:
- 鍵盤 F1:慣例上是「說明」,但筆電常需 Fn,且手把無對應,不如 L 一致。
- 鍵盤 `?`:要 Shift,且各鍵盤配置不同。
- 手把「Start 兩次」/組合鍵:不可發現、與選單鍵語意衝突。
- 手把借用右搖桿按下(鈕 8)並讓關係圖改位:動到已上線綁定,風險大於收益。

**手把退路(若 LT 實測有問題)**:手把只保留選單入口(Start → 圖例列),並把此事寫回本檔第 7 節。這不需要重新請管理者裁決——管理者授權的是「專用鍵由 UX 挑」,退路屬同一授權範圍內的實作回報。

## 3. 動作的事件處理規格

- 回呼只在 `event.is_pressed()` 時切換;**鍵盤 echo 一律忽略**(比照 `battle_toggle_hud` 既有寫法,`InputEventKey.echo` 引擎不過濾)。
- 手把扳機是類比軸,**需過濾「持續按住」**:只在由放開跨過 0.5 進入按下的那一幀觸發一次(Godot 對動作用 `is_action_just_pressed` / `event.is_pressed()` 判斷即可,但實作者需用一條測試驗證按住不會連續切換——見第 7 節)。
- 既有 `_note_hint_device()` 對 `InputEventJoypadMotion` 已以 `axis_value > 0.5` 判為手把,扳機觸發不需改這段。

## 4. 圖例開啟時的其他鍵行為(與開選單同規格:棋盤輸入不誤觸)

圖例是**唯讀、有模態攔截的疊層**,不改任何遊戲狀態,不暫停敵方回合播放。

**何時可開**:除下列兩種外,任何時刻都可開(含敵方回合、手牌開啟、選目標、強制棄牌、攻擊確認面板):
1. 戰鬥已結束(`Phase.FINISHED`)——結果畫面沒有任何可按的鍵(story-045 定稿第 7 節),此時按 L 無反應。
2. 選單已開啟——選單是更上層的模態,且選單裡本來就有「圖例」列;此時 L 無反應(不疊兩層)。

理由:圖例只是資訊疊層,疊在強制棄牌或確認面板上看一眼再關閉,不會讓玩家丟失狀態;反過來若在這些時刻禁止,玩家最需要查「這個顏色什麼意思」的時候(選目標、確認攻擊)反而查不到。

**開啟期間輸入表**(實作位置:`battle_screen.gd` `_input` 的「鍵盤/手把/動作」區塊最頂端,**在 `battle_toggle_hud` / `battle_toggle_relation_map` 檢查之前**,因為這兩個鍵現在放在所有吞鍵分支之前):

| 輸入 | 圖例開啟時 |
|---|---|
| `battle_open_legend`(L / LT) | 關閉圖例 |
| `battle_cancel`(Esc / B) | 關閉圖例(並吞掉,不傳給下層的取消) |
| 滑鼠右鍵 | 關閉圖例 |
| 滑鼠左鍵點圖例面板外(遮罩) | 關閉圖例;**點擊不得穿透到棋盤** |
| 面板上的「關閉」按鈕(滑鼠左鍵) | 關閉圖例 |
| `battle_confirm`(Enter/Space/A) | 關閉圖例(與選單/多數對話框一致:確認鍵也能收) |
| 方向鍵/十字鍵/搖桿、Tab/LB/RB、C/X、R/H/Q、Back/Start/搖桿按下 | **一律吞掉,不執行**(AC3「游標移動不改變選取」) |
| `battle_menu`(M / Start) | 吞掉(不疊選單);玩家要選單需先關圖例 |
| 滑鼠移動 / 懸停 | 棋盤懸停高亮停止更新(吞掉);不得顯示依賴懸停的內容 |

**關閉後**:回到開啟前的畫面狀態,**不回到選單**(即使是從選單「圖例」列進來的:選單先關閉再開圖例;關圖例後落在棋盤,不重開選單)。理由:選單「圖例」列的意圖是「看一眼」,回棋盤即可繼續;回選單多一次按鍵且面板層疊更複雜。游標/選取/手牌狀態完全不變。

**焦點(手把/鍵盤)**:圖例開啟時預設焦點落在「關閉」按鈕,確保鍵盤/手把用戶在沒有專用鍵的路徑(例如從選單進入)也能用確認鍵收起。

**無障礙**:圖例面板內容是靜態文字(不依賴懸停、不閃爍);圖示以「顏色 + 形狀 + 一句話」三者並陳,不得只靠顏色(`technical-preferences.md` 無障礙檢核)。面板文字走 HUD 字級規則(`screen-architecture.md` 一之二節),在 960×540 必須完整可見(AC4)。

## 5. 提示列(story-045 `controls_hint_content.gd`)

**結論:要列,但只列在最需要的一格、放最後一段;另新增一個 `LEGEND_OPEN` 狀態。**

### 5.1 `NO_SELECTION`(未選取任何單位)——鍵盤與手把加最後一段 `legend`

```
鍵盤/手把: ["move", "select", "hand", "menu", "legend"]
滑鼠:      不變(["move", "select"])——滑鼠沒有專用鍵,走選單
```

- 放**最後**:`fit_text` 從右端丟棄,狹窄視窗時圖例提示最先消失,不犧牲「移動/選取/手牌/選單」。
- 只放 `NO_SELECTION` 這一格,理由:這是玩家「停下來看畫面、想知道標記是什麼」最自然的時刻,且該格目前只有 4 段,有餘裕;`UNIT_SELECTED` 鍵盤/手把已有 7 段,在 960×540 已經截斷,再加一段只會被丟掉而白做。
- **不**放其他狀態:該狀態的選單(M/Start)提示已在,圖例入口在選單裡;提示列是狀態相關的最小集合,不是鍵位總表。

文案(`strings.csv` 新增):
```
battle.hud.hint.legend.keyboard,圖例 L
battle.hud.hint.legend.gamepad,圖例 LT
```
(格式比照既有「選單 M」「選單 Start」:`名稱 鍵名`。手把鍵名沿用既有 Xbox 命名慣例,與 Back/Start/RB 一致。)

### 5.2 新狀態 `HintState.LEGEND_OPEN`

- `_current_hint_state()` 的優先序:**FINISHED 之後、ENEMY_PHASE 之前**加一條「圖例開啟 → `LEGEND_OPEN`」(圖例開啟時輸入被攔截,提示列必須說真話,即使敵方回合也是)。
- 段落:三個裝置各一段 `legend_close`:
```
battle.hud.hint.legend_close.mouse,關閉 右鍵
battle.hud.hint.legend_close.keyboard,關閉 L 或 Esc
battle.hud.hint.legend_close.gamepad,關閉 B 或 LT
```
- 圖例的開關需像選單那樣觸發提示列重新套用(選單用 `visibility_changed.connect(_refresh_controls_hint.bind(true))`,圖例面板比照)。

### 5.3 連帶

- `strings.csv` 列數斷言(`locale_data_integrity_test.gd`)隨新增 5 列同步:2 列(5.1)+ 3 列(5.2),另加圖例面板自身字串。列數現值**當場取**,不要抄本檔。
- `controls_hint_content` 既有測試中的「各格段落數/優先序」斷言需同步更新 `NO_SELECTION` 鍵盤/手把的預期。提示列段落順序以本檔 5.1 為新定稿;story-045 定稿檔原文不動。

## 6. 圖例每項「一句話」文案準則(實作者出草稿,UX 覆核)

1. **長度**:每句 **≤ 14 個全形字**(含標點),單行顯示、不換行。超過就改寫,不是縮字級。(理由:960×540 的圖例面板要同時列 8 種以上標記,每行 = 圖示 + 名稱 + 一句話;提示列既有句子約 8~12 字,同一量級。)
2. **結構**:`名稱(≤ 4 字)` + `一句話`。名稱是玩家在畫面上會「叫它什麼」的詞(例:移動範圍、攻擊範圍、威脅區),一句話回答「這代表我現在可以/該做什麼」,不是描述顏色或形狀(顏色與形狀由圖示自己示範)。
3. **語氣**:白話、陳述句、第二人稱省略(不寫「你」);用「可」「會」「無法」等結果語,不用評價詞。範例方向:「可以走到的格子」「敵人下回合可打到」「被擋住,攻不到」。
4. **不用代號**:不寫 `T5`、story 編號、`AC`、內部列舉名(`MOVE_RANGE`、`THREAT` 等)、檔案名;不寫任何程式術語。標記名稱以**畫面上其他地方已在用的詞**為準(如提示列、單位資訊卡、選單),同一概念全作品只用一個詞;若與既有詞不一致,先對齊既有詞,不另造新詞。
5. **不依賴顏色當唯一說明**:句子不得出現「紅色的」「綠色的」當定義(色盲玩家無法對應);形狀可描述(「方框」「叉」),但優先用功能描述。
6. **不放鍵名**:圖例講「標記是什麼」,不講「怎麼按」(鍵位在提示列與選單,且會隨裝置變);避免把會改版的資訊寫進兩處。
7. **在地化**:每句一把鍵,走 `strings.csv`(AC4);鍵名風格與既有 `battle.*` 一致;不拼接字串(整句一條)。
8. **覆核流程**:實作者出整張草稿表(圖示來源常數、名稱、一句話、字數),交給 UX 設計師一次覆核;覆核只看第 1~6 點,不審美術(圖示外觀屬 art-director,AC2 已規定同源)。
