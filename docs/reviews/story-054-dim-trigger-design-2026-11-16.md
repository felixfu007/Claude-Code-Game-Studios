# story-054 變暗觸發條件設計判斷(2026-11-16)

> 只讀諮詢,未改任何程式或工單。判定:**推薦選項甲(以 `is_done` 為準)**。

## 1. 查證結果(皆已讀原始碼,不採信工單轉述)

- `src/gameplay/battle/turn_order.gd` `is_done(id)`:未註冊或已移除的 id 回真;其餘回 `_done.get(id,false)`。`_done` 只有兩處會設真:`end_unit_turn()`(只要單位「可行動」,兩旗標皆不必用)與 `_finish_if_both_flags_spent()`(兩旗標都用)。工單轉述正確。
- `advance_faction()` 對結束中陣營的每個單位把兩旗標與 `_done` 全部清除,所以變暗在下個我方回合自動復原。
- `unit_action_state(id)`(同檔):`_done` 優先於旗標,「被結束」回 `DONE`,與「兩旗標都用」**同值**。
  🔴 **工單「若裁決為只算兩旗標都用,改用四態查詢」這條退路不成立**:四態 getter 分不出這兩種 DONE。選項乙需要新增查詢(例如直接看兩旗標),不是換呼叫。
- `src/gameplay/battle/battle_controller.gd` `_select_unit_internal`:依序拒絕 單位不存在、已陣亡、非當前陣營、`_order.is_done(id)`;其餘才選取。故:
  - `is_done` 的單位(含被結束者)**不能被選取**。工單預期的「DONE 被選取是否恢復亮度」這題自然消失,查證成立。
  - 已移動、未攻擊(`ATTACK_ONLY`)的單位 `is_done` 為假,**可以再被選取**。
- `end_unit_turn`(controller):被結束的單位若正被選取會清除選取;敵方 AI 無事可做時也呼叫同一個 `_order.end_unit_turn`(`battle_controller.gd` 約 1614 行),不影響我方顯示(敵方不畫、不變暗)。
- 未驗證:`render_pieces` 的輸入字典目前有沒有「做完」欄位(工單自己也寫「缺則先問」);ux 是否已對「變暗但無圖示」有看法。

## 2. 推薦:甲

玩家看盤面時真正要回答的問題是:**「這個人我還能不能點、還能不能下指令?」** 引擎對這題的答案就是 `is_done`(`_select_unit_internal` 用的正是它)。變暗直接對應這個答案,畫面才不會對玩家說謊。圖示回答的是另一題(「這個人這回合做過什麼」),本來就該忠實反映旗標,兩者各管各的,不必綁在一起。

## 3. 乙的代價

- 玩家主動按「結束角色行動」的單位會**保持明亮卻點不了**(選取被 `is_done` 拒絕)。「亮 = 可操作」這個最直覺的讀法被畫面自己打破,而且是玩家剛剛親手造成的狀態。
- 需要新增一個只看兩旗標的查詢,與引擎的 `is_done` 分成兩套「做完」定義,日後容易再度脫節(本專案已有同類登記案例)。
- AC4 與工單退路都要重寫。

## 4. 甲的副作用與是否需 art/ux 確認

副作用:被結束但沒移動沒攻擊的單位變暗、頭上無圖示。緩解:資訊卡狀態行本來就依 `unit_action_state` 顯示「已行動」(DONE),可補足語意;「變暗不是陣亡」本就在 AC8 盲測範圍。
**不需為此單獨再請 art/ux 開一輪**;只需在 AC8 盲測多擺一人「只被結束、沒動作」的案例,若管理者讀成「陣亡」再回頭處理(先調 c,不改規則)。若 ux 想補,屬觀感微調而非阻擋項。

## 5. 給管理者的說明

玩家按了「結束這個角色的行動」之後,這個角色就點不了了,所以我建議讓它也變暗,這樣「變暗 = 這個人這回合不會再動」永遠成立。代價是:如果玩家沒移動沒攻擊就直接結束某個角色,它會變暗但頭上沒有鞋或劍,看起來像「什麼都沒做就暗了」。這其實是準確的,因為那是玩家自己的決定;我們在試玩時多擺一個這樣的角色,確認你看了不會誤以為它陣亡即可。
