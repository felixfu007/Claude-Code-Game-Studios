# 原型:好感度—位置連鎖 v5(站位隨機化驗證批次)

## 假說

如果讓真正新手在教學後遊玩 2-3 場「站位隨機」的戰鬥,敵方含遠程單位、雙方攻擊距離皆 +1 格、卡牌池擴充
為 5 種,他們會發現固定陣型無法穩定通關(機制展現出真正的決定性),因而主動運用好感度佈局與卡牌因應
每次不同的站位——我們會知道這是真的,如果:(1) 同一位測試者在不同站位的戰鬥之間,實際採用的陣型明顯
不同(而非重複套用同一組解法);(2) 卡牌因為有更明確的加乘效果,測試者主動選擇使用它的比例提高;
(3) 預判準確率、探針關卡對照、陣型重複率等既有量測門檻,這次能收集到不被固定陣型污染的乾淨數據。

這是承接 v4 Track A(戰鬥端)PIVOT 判決的續驗,不是重新定義的新概念。v4 判定 PARTIALLY CONFIRMED,
核心機制方向全部保留,問題出在測試場景本身(敵我站位固定,導致最佳陣型也固定,機制決定性與卡牌必要性
完全沒被壓力測試到)。

## 與 v4 的差異

| 項目 | v4 | v5 |
| --- | --- | --- |
| 敵我初始站位 | 固定值 | 每次重開隨機(**僅測試用**,正式關卡仍手工設計) |
| 卡牌池 | 3 種(翻轉/新增正好感/新增負好感) | 5 種(新增:正好感加乘、負好感加乘,效果持續至本場戰鬥結束) |
| 敵方武器 | 全數近戰(射程1) | X 改為遠程(射程3),Y/Z 維持近戰(射程2) |
| 攻擊距離 | A/E射程3,B/C/D射程2,敵方射程1 | 全體 +1:A/E射程4,B/C/D射程3,X射程3,Y/Z射程2 |
| 預判標記、固定節奏發牌、非空間取捨機制、陣型重複率追蹤、遮蔽地形關卡、session 統計面板 | 已驗證,測試者反應正面 | 完全沿用,不變動 |

## 如何執行

直接用瀏覽器開啟 `prototype.html`(雙擊或拖進瀏覽器視窗,不需要伺服器)。操作方式與 v4 完全相同,見畫面
上方說明。**每次按「重新開始」或切換地形,敵我站位都會重新隨機分佈**(我方在棋盤上兩列、敵方在下兩列
範圍內隨機,避免落在障礙格或彼此重疊)。

**建議測試流程**:與 v4 相同(教學→ 2-3 場標準地形戰鬥 → 決定性探針關卡對照 → 遮蔽地形關卡),但這次
額外請測試者比較:「你這幾場用的陣型,是同一套解法套用在不同站位上,還是每次都因為站位不同而重新規劃?」
這是本輪要驗證的核心問題。

## 已知簡化(沿用 v4,未變動)

- 移動路徑不處理障礙物阻擋(只阻擋「站上」障礙格)
- 疊加規則的正式版本(相加/取極值/優先順序 + 同時生效對數上限)尚未在 `/design-system` 定案,本原型的
  「同時只有最近一對正好感生效」為驗證用的具體實作
- 陣型重複率統計僅在單次瀏覽器 session 內累積,無法產生具統計顯著性的樣本量

## 狀態

已結束 — PARTIALLY CONFIRMED,判決 PROCEED

## 發現

站位隨機化成功解決了 v4 的測試汙染問題:玩家在不同站位的戰鬥之間,陣型明顯不同,且主動運用卡牌
逆轉劣勢,爽快感明確(「原本打不贏的敵人,透過挪動陣型以及卡牌效果,成功在兩回合內擊殺」)。同時
暴露三個數值/內容層級的問題(非機制失敗):敵方強度不足(遠程比例過低+全體攻擊距離過遠導致敵方被
單方面壓制)、卡牌內容深度不足(負面效果卡用途不明、缺少牽制類卡牌、牌組/抽卡機制未定義)、角色
除能力值外缺乏識別度。另發現一個程式 bug(移動不消耗行動額度),不影響驗證結論。

完整報告見 [REPORT.md](REPORT.md)。
