# 模擬遊玩紀錄:好感度—位置連鎖 v4(Track B · 敘事軌跡系統)

> PROTOTYPE - NOT FOR PRODUCTION — 本檔案為設計者自行模擬的三段對照紀錄,用來在交給真人測試者之前,
> 先檢查 `story-map.md` 的分支規則是否內部自洽。三段紀錄分別代表三種典型的玩家行為模式。

---

## Session 1:「甲乙全押,只靠戰鬥」—— 測試「戰鬥端投入是否等於敘事端深交」

**玩家行為**:整個章節(3 場戰鬥,依 Track A 的 N=2 節奏抽到 5 張好感度對話卡牌)全部選擇作用在「甲乙」;
3 次支援對話名額完全沒有使用(玩家專注戰鬥,略過對話選項)。

**甲乙軌跡**:
```
[combat_card +] [combat_card +] [combat_card +] [combat_card +] [combat_card +]
```
5 筆,全部 `combat_card`,無反轉 → 分類:**戰場默契**

**甲丙軌跡**:0 筆 → 分類:**無**

**查表**:戰場默契 × 無/淺 → **E2a 選擇了乙(默契版)**

**讀出的結局片段**:「甲與乙從沒正經聊過幾句話,但每次並肩作戰,甲總是不必回頭確認,就知道乙會補上那一箭……」

**觀察**:這正是本輪最想驗證的情境——玩家對甲乙的戰術投入其實不比 Session 2 少(甚至次數更多),
但因為完全沒有 `support_conversation` 來源,系統把這條軌跡讀成「戰場默契」而非「推心置腹」。
是否要讓真人測試者也認同「這是不同的關係,不是比較差的關係」,是本次測試的核心待驗證問題。

---

## Session 2:「甲乙均衡投入(戰鬥+對話)」—— 對照 Session 1,驗證來源分布是否真的改變敘事性質

**玩家行為**:3 場戰鬥抽到的 5 張卡牌中,3 張作用在甲乙、2 張作用在甲丙;3 次支援對話名額全部用在甲乙。

**甲乙軌跡**:
```
[combat_card +] [combat_card +] [combat_card +] [support_conversation +] [support_conversation +] [support_conversation +]
```
6 筆,其中 3 筆 `support_conversation`(≥2),無反轉 → 分類:**推心置腹**

**甲丙軌跡**:
```
[combat_card +] [combat_card +]
```
2 筆 → 分類:**淺**

**查表**:推心置腹 × 無/淺 → **E1a 選擇了乙(深交版)**

**讀出的結局片段**:「乙從沒問過甲『你為什麼總是先算好每一步』,她只是在甲又一次徹夜推演棋盤時,默默放下一杯還溫著的茶……」

**觀察**:與 Session 1 對照,甲乙這條軌跡的戰鬥卡牌次數(3 張)其實比 Session 1(5 張)還少,但因為
補上了 3 次支援對話,結局的語氣與內容明顯不同——這證實了「來源分布」而非「總量」在驅動分類,
初步符合設計假說。真人測試時要問:這個差異讀起來自然嗎?還是感覺像在強迫玩家「必須去對話」才算數?

## Session 3:「嘗試兩邊都深交」—— 壓力測試資源預算是否真的形成取捨

**玩家行為**:玩家刻意想讓甲乙、甲丙都達到「推心置腹」。3 次支援對話名額拆成甲乙 2 次、甲丙 1 次
(無法拆成 2/2,因為總共只有 3 次);5 張戰鬥卡牌拆成甲乙 3 張、甲丙 2 張。

**甲乙軌跡**:
```
[combat_card +] [combat_card +] [combat_card +] [support_conversation +] [support_conversation +]
```
5 筆,2 筆 `support_conversation`(=2,達標),無反轉 → 分類:**推心置腹**

**甲丙軌跡**:
```
[combat_card +] [combat_card +] [support_conversation +]
```
3 筆,只有 1 筆 `support_conversation`(未達 ≥2 的門檻),無反轉 → **這個組合沒有落入 story-map.md 定義的
任何分類**:不是「淺」(超過 2 筆)、不是「戰場默契」(不是全部 combat_card)、不是「推心置腹」(support_conversation
不足 2 筆)、也不是「波折」(沒有反轉)。

### 發現:分類規則有缺口

`story-map.md` 原本只定義了 5 種乾淨的形狀(無/淺/戰場默契/推心置腹/波折),但 Session 3 顯示:
**真人玩家很可能大量落在「投入了、但沒投入到門檻」的中間地帶**,而不是集中在乾淨的極端案例。
這是本次紙上原型測試前,自我模擬就先發現的規則缺口,建議 `/design-system` 階段補上至少一個
「淡淡的交情」中間層級(例如:≥3 筆但不滿足任一乾淨分類時的預設歸類),否則正式系統上線時
會頻繁出現「查表查不到」的狀況。

**資源預算驗證結果**:即使玩家刻意想讓兩段關係都達到「推心置腹」,3 次支援對話名額也無法同時
支撐兩條軌跡各自達到 ≥2 筆的門檻(2+1,不是 2+2)——**本次資源預算確實成功阻止了「兩段關係同時
深交」這個組合**,初步驗證了取捨機制在敘事層有效。真人測試時應追問:玩家自己有沒有意識到
「我沒辦法兩邊都要」?這個限制感覺是合理的抉擇,還是感覺像被系統卡住?

## 給真人測試者的引導問題(對照 `/prototype` Phase 6 debrief 五問使用)

1. 讀完你這一輪選擇對應的結局片段,你覺得它符合你在遊戲中實際做的選擇嗎?
2. E1(深交版)和 E2(默契版)讀起來像是「同一段關係的兩種可能」,還是像是「一個做得好、一個做得差」?
3. 你有沒有在中途意識到「我沒辦法把甲乙、甲丙都經營到最好」?那個當下的感覺是什麼?
4. 卡牌打出時,介面告訴你「這會影響[某段]關係軌跡」但不告訴你會怎麼影響——這樣的揭露方式,
   讓你覺得選擇有意義,還是覺得資訊不夠、只能亂猜?
5. PROCEED / PIVOT / KILL,一句話說明原因。
