# 原型:好感度—位置連鎖 v4(Track B · 敘事軌跡系統)

## 假說

如果戰鬥中卡牌好感度變動與支援對話好感度變動共用同一條軌跡(依形狀特徵——方向反轉次數、來源分布、
時間分布——而非累積總量判讀),讀者會覺得自己的戰術選擇有意義地形塑了故事,而不是意外的刷好感——
我們會知道這是真的,如果:(1) 測試者回報分支差異感覺是刻意且可辨識的,不是分數高低;(2) 一個全程只靠
戰鬥卡牌刷高某角色好感度的測試者,得到的是「不同」而非單純「更好」的敘事結局(design-review 第五輪
creative-director 的設計測試);(3) 資源預算(3 次支援對話名額)確實阻止玩家讓兩段關係同時達到最深交情。

這是敘事端從未經過任何驗證的部分——三輪概念原型(v1-v3)皆刻意排除劇情分支。與 Track A(戰鬥端)不同,
Track A 已有方向性確認(v3 PROCEED),Track B 完全是空白,是本輪風險最高的驗證項目。

## 角色

甲、乙、丙——佔位代號,正式命名待角色設計階段。三人結構(而非兩人)是刻意設計,用來製造「該把有限的
戰鬥卡牌與支援對話名額投資在甲乙還是甲丙」的真實抉擇,對應戰鬥端的空間取捨在敘事端的等價物。

## 如何執行

1. 閱讀 `story-map.md`,理解資料結構(delta log + 來源標籤)、資源預算(3 次支援對話、4-5 張戰鬥卡牌)、
   軌跡形狀判讀規則、分支結局表。
2. 閱讀 `play-log.md` 的三段模擬紀錄,建立對整體邏輯的直覺。
3. 找一位沒看過這份設計的讀者,請他們自己「扮演」一輪(用紙筆或口頭決定每次卡牌打在哪段關係、
   每次支援對話選誰),你依 `story-map.md` 的規則現場判讀他們會落入哪個結局,唸出對應的結局片段給他們聽。
4. 用 `play-log.md` 最後的五個引導問題進行 debrief。

## 已知簡化

- 結局片段只寫了節錄,不是完整場景;正式敘事系統的實際文本量留待 `/design-system` 敘事系統階段。
- 分類規則目前只有 5 種乾淨形狀,`play-log.md` Session 3 已發現這無法涵蓋所有真實投入模式的中間地帶,
  是本輪原型測試前自我模擬就先發現的規則缺口,測試時應持續記錄類似的「查表查不到」情況。
- 卡牌對關係的指派(甲乙 vs 甲丙)在本測試中預設由玩家自由選擇每張卡牌的目標,對應 Track A 的卡牌系統設計。
