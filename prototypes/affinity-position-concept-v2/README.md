# 原型:好感度—位置連鎖 v2(HTML)

## 假說

如果好感度系統以「獎勵優先」為主軸設計,且好感度關係會隨劇情/戰鬥事件動態變化,玩家會主動、愉快地圍繞好感度佈局,並且不會因為找到單一最優陣型而停止思考。

**最風險的假設**:動態變化好感度本身,會不會反而讓玩家覺得規則在腳下移動、更困惑,而不是有趣的規劃。

延續自 `prototypes/affinity-position-concept/PIVOT-NOTE.md` 的轉向筆記(v1 為 Paper 路徑,判決 PIVOT)。

## 如何執行

直接用瀏覽器開啟 `prototype.html`(雙擊或拖進瀏覽器視窗,不需要伺服器)。

操作方式:
1. 點選我方角色(藍色),棋盤上會亮起可移動格子
2. 滑鼠移到候選格子上,即時查看好感度連結線預覽(綠=加成、紅=懲罰、灰=無效果)與淨效果數值
3. 點選格子確定移動,或直接點選相鄰敵人(橘色)發動攻擊
4. 若只想移動不攻擊,按「結束此單位行動」
5. 所有我方角色都行動後,按「進入敵方回合」
6. 每 2 回合會觸發一次隨機劇情事件,改變好感度關係(翻轉既有關係或新增一對)

## 狀態

已結束(PIVOT,第 2 次)

## 發現

假說判定 REFUTED。視覺化即時預覽本身沒有被證偽,但更根本的問題浮現:好感度佈局需要消耗跟戰鬥站位同一份移動力,兩者衝突時玩家必然放棄好感度;而且即使完全忽視好感度機制,靠角色基礎數值依然能通關,顯示機制目前不具決定性。完整報告見 [REPORT.md](REPORT.md)。下一輪需要把好感度效果改成不消耗額外資源的自動結算,並設計一場沒有好感度加成就打不贏的關卡來驗證決定性。
