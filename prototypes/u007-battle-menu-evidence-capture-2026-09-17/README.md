## 發現（不是單純「通過/失敗」，兩項機械門檻在本案例上需要說明）

1. **coding-standards.md 原始的 4×3 盲測網格,在本畫面下只量到 1 種相異色。**
   根因：該網格是為世界層滿版內容設計的，M1 面板刻意是安全區內一個精確置中的
   小區塊（1080p 下僅佔全螢幕約 8.9%），12 個均勻分布的點有很高機率全部落在
   面板之外。本驅動器額外加了取自 `BattleMenu.panel_rect()`（不重推座標，直接
   呼叫正式程式碼）的面板內取樣點，兩者合併後兩種解析度皆為 3 種相異色，
   達到門檻——但這是「加測」不是「重新定義門檻」，原始盲測網格的結果（1 種）
   也原樣印出、原樣保留，不隱藏。
2. **主色佔比兩種解析度皆超過 80% 門檻（91.6% / 92.7%）。** 這是模態選單「大面積
   暗色遮罩 + 一個小面板」這個設計形狀的直接後果，不是內容空白或渲染錯誤——
   已用人眼開圖確認畫面確實完整正確。**這條門檻是為了抓「全螢幕遊戲畫面主色
   佔比過高 = 可能是啟動畫面之類的空白幀」而設計的，套用到「模態選單本來就
   該以單一暗色遮罩為主」這種畫面形狀上，高佔比不具備同樣的判別力**——
   本探針如實記錄這個不匹配，不擅自調整規則本身，留給協調者/QA 判斷是否要為
   模態選單類畫面另訂門檻。
