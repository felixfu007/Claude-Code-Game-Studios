## 1. 它回答玩家什麼問題(為什麼棋盤連線不夠)

棋盤連線一次只畫「兩個單位之間的線」,而且線的兩端要看棋子在哪。玩家想問的是**跨棋子的比較**:
「這五個人裡,誰跟誰好、誰跟誰不合?我該把誰擺在一起?」——

- 棋子散在棋盤各處時,線被地形與其他棋子切碎、要逐條找,**看不到整張關係的全貌**。
- 棋子離得遠時,線的呈現與否取決於位置(**未驗證**:`NEUTRAL` 狀態是否等於「目前未生效」),玩家無從得知「這對本來是好是壞」。
- `affinity-position-chain.md` Player Fantasy 的目標感受是「我不是靠運氣贏的,是靠我把人擺對位置」;
  要擺對位置,得先**一眼看懂五人的關係結構**。本地圖就是為此,不是為了裝飾。

**它不回答**:「走到這格會多打幾點」——那是游標預覽(Mode A)的事。**不得與之重複或互相取代。**

## 2. 何時可見、怎麼開關

> ✅ **2026-10-28 管理者裁決取代本節的開啟條件**:我方階段隨時可開(含出牌、攻擊確認、強制棄牌、戰鬥選單期間),敵方回合自動收起;開著時棋盤操作照常。逐字見 `production/epics/relation-minimap/EPIC.md` 裁決 1、4。以下原文保留。

**可見時機(預設,見 Q2)**:戰鬥畫面的我方行動階段,且無模態/強制回應畫面開啟時可開啟。
敵方階段、戰鬥選單、手牌開啟中、強制回應覆蓋層(例:強制棄牌)**不可開啟**(按了無反應,且不得留下半開狀態)。
關閉是預設狀態:**不自動彈出**,避免擋住玩家正在看的棋盤。

**輸入(沿用既有動作名;新增一個動作,理由見下)**:

| 動作 | 鍵盤 | 滑鼠 | 手把 |
|---|---|---|---|
| 開/關關係圖 | 新動作 `battle_toggle_relation_map`,建議預設 `R` | 點畫面上**常駐的小按鈕**(關閉時也看得見,不靠懸停) | 建議預設右搖桿按下(`button_index` 8) |
| 在地圖內換下一個/上一個節點 | `battle_next_target`(Tab)/ `battle_prev_target`(Shift+Tab) | 直接點節點 | `battle_next_target` / `battle_prev_target`(肩鍵 RB / LB) |
| 離開地圖 | `battle_cancel`(Esc)或再按開關鍵 | 點關閉按鈕或點地圖外 | `battle_cancel`(B)或再按開關鍵 |

**為何要新動作而不借用既有的**:`project.godot` `[input]` 節目前的動作全是 `battle_*`:
`confirm / end_phase / cancel / open_hand / guess_cycle / next_target / prev_target / menu / end_unit_turn`;
手把的 A/B/X/Y、兩肩鍵、Back、Start 都已被占用(依該節 `button_index` 讀出)。借用任一個會讓「開地圖」與原功能打架。
⚠️ **未驗證**:`R` 鍵與右搖桿按下是否已被游標系統/他處使用(`[input]` 節沒有,但游標移動可能走內建 `ui_*` 動作,未讀);
預設鍵是**建議**,實作前須對照實際綁定查衝突。**可重新綁定**(Standard 無障礙承諾)。

**手把/鍵盤不得需要懸停**:地圖開啟時,節點是游標目標(第 6 節),用 `next/prev_target` 步進,不靠指標。

## 3. 版面

依 `design/art/screen-architecture.md`「由第 3 點導出的介面硬性約束」:**介面不得依賴棋盤旁邊有空位**
(1080p、4K 邊區為零),好感度關係圖**必須疊在棋盤上方、可收合、不得用側邊固定欄位**。

- **疊加面板**:半透明底,貼視窗一角(哪一角見 Q3),**收合時整個消失**(只剩常駐小按鈕)。
- **不得遮住關鍵資訊**:不得與 HUD 已有矩形(`HudLayout`)、手牌列(`HandBar.slot_bar_rect()`)重疊。
  驗收用**真實版面函式**取得矩形比對,不得另寫座標(Category 規則同 `coding-standards.md` 證據紀律)。
  ⚠️ **未驗證**:這些矩形目前各占哪一角,本檔未讀,故角落選擇交實作者依實際空位決定、人開圖確認。
- **尺寸與字級**:介面基準畫布 = 當下螢幕實際解析度;字級倍率 `N` 一律呼叫
  `src/ui/battle/world_layout.gd` 的 `compute_scale()` 取得(`technical-preferences.md` 硬性義務),**不得自算**。
  字級規則見 `design/art/screen-architecture.md`「一之二、HUD 字級規則」,本檔不複述。
- **節點排列**:五名我方角色(敵方不進好感度池,依 `AffinityRosterCharacterMapper` 只收我方 id)
  排成**固定的五邊形**,與棋盤位置**無關**。理由:位置會變、固定排列讓玩家形成空間記憶、五點兩兩連線(10 條)在五邊形上不會有三線共點。
  ⚠️ 若上場我方不足五人,缺席者**不畫節點**,版面不重排(位置固定)。
- **詳情區**:地圖開啟且游標在某節點上時,面板底部顯示該角色的**逐條關係列表**(對象名 + 極性文字 + 強度數字);
  不在節點上時顯示提示文字「選一個角色查看關係」。
- 動畫:開關最多一個短淡入淡出,**遵守玩家的減少動態偏好,且可略過**(`ui-code.md`)。

## 4. 節點與連線怎麼表示(不得只靠顏色)

| 資訊 | 表示法(三者缺一不可,顏色只是第三重) |
|---|---|
| 正向 | **實線** + 線中點符號 `+` + 綠色 |
| 負向 | **虛線** + 線中點符號 `−` + 紅色 |
| 中立/未生效 | **細點線** + 線中點符號 `0`(或無符號,見 Q4)+ 低對比灰(對應棋盤的 `MUTED`) |
| 強度 | 線寬分 3 級 **且**線中點附**數字**(數字是真值,線寬只是輔助);強度來源見第 5 節 |
| 節點 | 圓/方框 + **角色名文字**(名牌);不靠顏色、不靠立繪 |

- 色盲模式:沿用專案既有色盲模式,線型與符號**不隨模式改變**(它們本身就是非色彩通道)。
- 與棋盤線的對應:同一對角色的同一極性,**語彙一致**(棋盤用 `LineTone.POSITIVE/NEGATIVE/MUTED`)。
  若棋盤線目前只靠顏色區分,則棋盤也欠這條(`game-concept.md` 明訂連線不得僅靠色彩區分,**未驗證**棋盤已達標);
  本地圖不得因此降低自己的標準,但**棋盤補線型是另一張工作單**,不在本檔。
- 已陣亡角色:節點留著但標「陣亡」文字並降低對比,連線不畫(**未驗證** `links()` 是否已排除陣亡者;MVP 內陣亡即回滾,罕見)。
- 位置夾限:若某角色的總和被夾限壓回,詳情區必須明示「已達上限/下限」(`affinity-position-chain.md` UI Requirements 義務),
  否則逐條相加不等於總和,「線在騙人」。

## 5. 資訊一致性(單一來源,不得自算關係)

- 地圖**只讀、無狀態**,不得持有好感度、不得自行判定極性/強度/是否生效。
- 資料一律來自**好感度層的既有出口**:`AffinityPhiProvider.links()`(回傳 `Array[AffinityLink]`)與
  `AffinityLineStatus`(狀態 → 色調映射已存在於 `battle_screen.gd` 的 `line_tone_for()`);
  詳情區的逐條貢獻須與游標預覽**走同一個查詢函式**(`affinity-position-chain.md` UI Requirements)。
- **一次建立、兩處消費**:`battle_screen.gd` 現在於同一處把線狀態轉成字典餵給 `BoardView.set_affinity_lines()`。
  地圖應吃**同一份**中間資料,不得在 UI 內第二次呼叫 `links()` 再自己轉換(兩份轉換 = 兩份可能漂移的實作)。
  實作者若認為必須另算,須先停下來問。
- **更新時機**:與棋盤線**同一個觸發點**刷新(棋子移動、結算、陣亡之後);地圖開著時資料變了,必須當幀跟著變,不得顯示舊的。
- ⚠️ **未驗證/待查**:`AffinityLineStatus` / `AffinityLink` 是否已暴露「強度數值」。若只有極性與三態、沒有數值,
  則強度欄須由好感度層**新增唯讀出口**(交 `lead-programmer` 與 `game-designer`),**不得由 UI 反推**(見 Q1)。

## 6. 游標系統義務(`RELATION_MINIMAP_NODE`)

> ✅ **2026-10-28 管理者裁決:本節不實作**(EPIC 裁決 5「維持純顯示,不做地圖游標」)。關係圖為純顯示,不登記 `RELATION_MINIMAP_NODE`、不移動游標;本節原文保留,供日後若要加「切到地圖」模式時參考。

`CursorTypes.SurfaceType.RELATION_MINIMAP_NODE` 與 `relation_minimap_node_threshold_px`(`mouse_reclaim_threshold_config.gd`,

| 義務 | 本地圖如何滿足 |
|---|---|
| **OBL-011** | 節點高亮一律讀單一游標/高亮狀態系統;不自寫裝置權威判定;**不得使用引擎原生 focus/hover 繪製**(`interaction-patterns.md` P-N1 之註) |

## 8. 驗收條件(Given / When / Then)

- **AC-1(開關三裝置)** Given 我方行動階段無模態,When 分別只用鍵盤、只用滑鼠、只用手把,Then 三者都能完成「開、換節點、離開」,且無任何操作要求懸停。
- **AC-2(不可開的情境)** Given 敵方階段/戰鬥選單/手牌開啟/強制回應覆蓋層,When 按開關,Then 地圖不開,且無半開殘留。
- **AC-3(單一來源)** Given 任一時刻地圖開啟,When 比對每一對角色,Then 地圖上的極性與棋盤線的 `LineTone` 逐對一致;
  且原始碼中「`AffinityLink` → 色調」的轉換只有一處(以 `^static func` 錨定的 grep 或測試驗證)。
- **AC-4(同步刷新)** Given 地圖開著,When 一次移動或結算改變了某對關係,Then 同一幀地圖更新,不顯示舊值。
- **AC-5(非色彩)** Given 灰階截圖,When 檢視地圖,Then 仍可由**線型 + 符號 + 數字**分辨正/負/中立與強度。
- **AC-6(強度為真值)** Given 某一對的強度,When 比對線中點數字與好感度層回報值,Then 逐值相同(不是線寬推算)。
- **AC-7(不遮關鍵資訊)** Given 1920×1080、2560×1440、3440×1440、最小視窗 960×540,When 開啟地圖,
  Then 面板完整在視窗內、不與 `HudLayout` 矩形與手牌列矩形重疊(用真實版面函式比對),不依賴左右邊區。
  ⚠️ 像素/版面證據依專案規則須**人開圖確認**。
- **AC-8(字級)** Given 字級設為最大,When 顯示最長角色名與逐條列表,Then 無截斷、無溢出面板(換行或捲動)。
- **AC-9(游標交接)** Given 游標目標在節點上,When 關閉地圖,Then 關閉前已呼叫交接介面,關閉後目標回到開啟前的棋盤目標,
  且狀態不為「待重新解析且無人處理」。
- **AC-10(待重新解析)** Given 游標有效性旗標為待重新解析,When 詳情區要渲染,Then 顯示不確定佔位,不顯示確信樣式。
- **AC-11(進場焦點)** Given 剛開啟地圖,Then 第一幀已有節點被高亮(含手把玩家),無空白期。
- **AC-12(無狀態)** Given 地圖原始碼,When 搜尋寫入好感度池或持有關係副本的程式,Then 零命中。
- **AC-13(在地化)** Given 地圖原始碼與場景檔,When 搜尋任何固定文字或角色名字面值,Then 不得在程式碼或 `.tscn` 內出現。
- **AC-14(陣亡/不足五人)** Given 一名角色陣亡或不足五人,When 開啟地圖,Then 無報錯、無空洞、節點位置不重排。
- **AC-15(夾限明示)** Given 某角色原始和被夾限壓回,When 檢視詳情區,Then 明示「已達上限/下限」,逐條相加與總和之差有解釋。

## 9. 開放問題(交回管理者,後果用白話寫)

| # | 問題 | 若不決定的後果 |
|---|---|---|
| **Q1** | 地圖上要不要顯示每對的**強度數字**?(目前不確定好感度層有沒有把數值開放給畫面讀) | 若不決定,工程師會用線的粗細暗示強度,玩家只能看出「大概」,而且萬一和真實數值對不上,就是「線在騙人」 |
| **Q2** | 我方行動階段以外(敵方回合、戰鬥選單開著、出牌中)能不能開地圖? | 若不決定,工程師各處自行決定,可能出現「按了沒反應卻沒說原因」或「在敵人行動時多開一個畫面蓋住動畫」 |
| **Q3** | 面板貼視窗哪一角?(要看 HUD 與手牌列實際占哪裡,需要美術與實作一起看圖) | 若不決定,最糟會蓋到手牌或血量資訊;工程師只能先擺一個角落,上線前再被人眼抓到才改 |
| **Q4** | 「中立/未生效」的線要不要畫?(畫了資訊完整但圖變雜;不畫則玩家看不到「這對本來是好是壞」) | 若不決定,預設會畫成低對比細線;玩家可能把它誤讀成「兩人沒關係」,而實際只是目前離太遠 |
| **Q5** | 游標在地圖節點上時,棋盤上對應單位要不要加標記?(要的話,標記長相需不與游標高亮混淆) | 若不決定,玩家看得到「地圖上選了誰」卻找不到他在棋盤哪裡,地圖變成孤立圖表,失去「幫我擺位置」的用處 |
| **Q6** | 開關動作的預設鍵:鍵盤 `R`、手把右搖桿按下,可以嗎?(已查:現有九個動作與手把按鍵皆已占滿,必須新增) | 若不決定,工程師可能借用已有按鍵(例如跟出牌鍵共用),玩家在戰鬥中誤開誤關 |
| **Q7** | 地圖開啟時,是否允許同時操作棋盤(例如繼續移動單位),還是開啟期間只能看? | 若不決定,工程師會做成「半專屬」:游標卡在地圖裡但棋子又能動,手把玩家最容易困惑「我現在控制的是哪一邊」 |
| **Q8** | 好感度之外,地圖是否要附帶顯示每人 HP/狀態?(本檔預設**不附**,只畫關係) | 若不決定,預設不附;玩家想「看誰快倒了再決定誰要靠近誰」時,仍得切回棋盤找血量 |
