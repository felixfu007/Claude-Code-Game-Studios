## 1. 畫面分區(960×540 為準,比例固定,更大解析度等比放大)

| 區 | 內容 | 備註 |
|---|---|---|
| Z1 頂列 | 畫面標題、`本輪剩 N 次`(次數規則未定,見 7 #2)、當前步驟提示一行 | 步驟提示是「現在該做什麼」的唯一文字處 |
| Z2 左欄:五人 | 五位角色逐列(姓名 + 立繪小圖)。選第二人時,每列右側顯示**該人與第一人的目前關係**(詞 + 徽記) | 麥子健列另顯示 `騎牆：有效/失效`(同詞表) |
| Z3 中欄:動作 | `關心` / `質問` 兩個大按鈕,各附一句白話(關心:兩人更親近;質問:兩人更疏遠) | 第一、二人都選定前,兩鈕停用且寫明原因 |
| Z4 右欄:預覽 | 兩人姓名 → `目前：[詞+徽記]` → `寫入後：[詞+徽記]`;不變時寫 `關係不變`。麥子健預告列(見 2.3) | 預覽只讀,不可操作 |
| Z5 底列 | `返回`(退一步)、`確認`、`結束營火` | 確認鈕在步驟未完成時停用且鈕面換字 |
| 結果層 | 確認後 Z3/Z4 換成:產出的卡(沿用既有卡面樣板,**不另組字**)、該組寫入後關係、`繼續` | 見 2.4 |

- 列高/按鈕高 ≥ 2 × HUD 字高(960×540 為 44px,**提案值,未驗證**,依 Fitts 定律讓滑鼠點擊目標不小於手牌列既有尺寸)。
- 立繪、徽記只是輔助,**文字永遠在**;不得只靠顏色、不得只靠圖(沿用 v1.0 6.3 第 4 項)。

## 2. 操作流程

### 2.1 步驟狀態機

`選第一人 → 選第二人 → 選動作 → 預覽確認 → 結果 →(還有次數?回到選第一人:離開)`

| 步驟 | 滑鼠 | 鍵盤 | 手把 |
|---|---|---|---|
| 移動焦點 | 點選(hover 只做高亮,不觸發任何事) | 方向鍵 / `Tab` `Shift+Tab` | 十字鍵 / 左搖桿 |
| 選定 / 確認 | 左鍵點列或按鈕 | `Enter` / `Space` | 確認鍵(A) |
| 退一步 | 點 `返回` | `Esc` | 取消鍵(B) |
| 離開營火 | 點 `結束營火` | 焦點移到該鈕 + `Enter`(另綁快捷鍵待定) | 同左 |

- **動作名稱(InputMap)未驗證**:戰鬥用 `battle_confirm`/`battle_cancel`(見 `support-conversation-screen.md`),營火是否共用或另建,交 `ui-programmer` 查 `project.godot`。**不得自寫裝置切換邏輯**,焦點/高亮一律讀單一游標/高亮狀態系統(ADR-0005,同支援對話畫面 OBL-011 做法)。
- 進場初始焦點:Z2 第一列(手把玩家一進場就知道焦點在哪)。
- 取消鍵每次只退一步,不跳多步;在「選第一人」按取消 = 開啟離開確認(2.5)。
- **選第一人後,第二人列表排除第一人**(不可選同一人);已選的第一人在 Z2 持續標示(文字 `已選`,不只高亮)。
- 選第二人時顯示每列目前關係,是**資訊揭露**:玩家挑對象時就看得到「關心這組會從哪個狀態出發」。

### 2.2 預覽(寫入前)

- 「目前」與「寫入後」**兩者都來自唯一判定 `AffinityRelation.state_of()`**,寫入後那一格對**預覽池**(假想寫入 `±m` 後)呼叫;**UI 不得讀池值自己比大小、不得自帶 `k`、不得快取**(story-007 AC1/AC6;契約 `affinity_relation_state_single_judgment`)。
- 預覽池怎麼取得(複製池?純函式?):**未驗證**,交 `lead-programmer`(story-002)。
- 目前 = 寫入後時,顯示 `關係不變` 而不是兩個相同的詞,避免玩家以為畫面沒更新。
- 三態只有詞 + 徽記,**不顯示池值數字**(玩家詞表只有三態)。⚠️ 後果見 7 #3。

### 2.3 麥子健預告

- 條件:寫入**前**他與其餘四人 4 組全為冷淡(騎牆有效),且本次寫入使其中一組寫入後非冷淡 → Z4 與確認鈕之間顯示一行 `麥子健將失去騎牆`(鍵 `battle.relation.straddle.will_lose_format` 已存在,帶姓名;位置在確認前)。
- 判定「會不會失去」**讀同一個判定**(對預覽池算騎牆),UI 不自己數四組(story-007 AC2 兩側各一條)。
- 預告列有形狀通道:盾形加斜線徽記(與 `card-rework-ui` 4.4 同一個,畫法交美術)+ 文字。
- 只提示,**不加二次確認**(確認鈕本身就是確認步)。是否要更強的阻擋,見 7 #6。
- 營火是目前唯一會觸發它的地方(戰鬥中丙類卡版本暫緩,因麥子健無關係線,**採信來源:委託人訊息,本檔未查**)。

### 2.4 確認後與結果層

- 確認後鎖住輸入直到寫入與產卡完成(同步完成則無此態,**未驗證**);期間確認鍵給拒絕回饋。
- 結果層顯示:該組寫入後關係(詞 + 徽記)、產出的卡、`繼續`。卡出現不播閃爍,動畫可跳過;**卡面強度數字直接顯示**(產卡當下已固定,v1.0 4.4)。
- 若寫入使麥子健騎牆失效,結果層再顯示一次 `騎牆：失效`(事後確認,與預告同詞表)。
- 次數用完 → `繼續` 變成 `前往編輯牌組`(強制進入牌組編輯,見 `deck-edit-screen.md`);還有次數 → `繼續` 回到選第一人。

### 2.5 離開

- `結束營火` 或在步驟 1 按取消 → 一個確認框(`確認離開 / 返回`,預設焦點在 `返回`)。若本輪**一次都沒做**,框內多一句 `本次還沒有做任何選擇`。是否允許一次都不做就離開:見 7 #2。
- 離開 → 一律接牌組編輯(不得跳過,story-006 AC2)。

## 3. 狀態與邊界

| 情況 | 處理 |
|---|---|
| 次數用完 | 兩個動作鈕停用 + 原因行 `本輪次數已用完`,只剩 `前往編輯牌組` |
| 同一組本輪已做過 | 規格沉默,**未決**(7 #7);暫行:允許,Z2 該列顯示 `已做 N 次` |
| 寫入失敗(002 回拒絕) | 面板不關閉、零寫入、顯示失敗原因行;不進結果層 |
| 麥子健已非騎牆 | 不顯示預告;Z2 顯示 `騎牆：失效` |
| 視窗縮放 / 手把與滑鼠切換 | 焦點不丟失(由游標系統管);縮放後版面等比,不換行截斷 |
| 戰敗後重打 | 是否回到營火:依 story-006 管理者第 1 題,本畫面不處理 |
| 生命週期 | 向 `CursorStateHost` 註冊的表面,**必須接 `tree_exited → unregister_surface`**(game-shell EPIC 全域義務) |

## 6. 需要美術的清單(本檔不決定視覺風格,交 `art-director`)

## 7. 需要管理者決定的事(白話)

1. **最小視窗到底是多大?** 目前文件互相打架:畫面架構文件寫最小 960×540,你 11-12 的裁決與卡牌 UI 文件寫 1280×720。**我先照你這次的訊息以 960×540 設計(比較擠、較保險)**。若實際是 1280×720,版面會更鬆,不會需要重做。
2. **一輪營火能做幾次?一次都不做可以離開嗎?** 規格還沒定(每輪 2~3 次是二手說法)。「可以一次都不做就離開」最自由,但玩家可能完全不碰營火、營火系統就白做了。建議允許,但離開時提醒一句。**由你(或交遊戲設計師)決定。**
3. **玩家要看得到「還差多少」嗎?** 關心一次,不一定能讓「冷淡」變成「好感」(要跨出冷淡區)。畫面只顯示三個詞時,玩家可能做了選擇卻看到「關係不變」,會覺得營火沒用。選項:(甲)維持只有三態(最簡單,但容易挫折);(乙)多顯示一格粗略進度(例如「差一次」)——需要判定函式額外提供資料,**這會牽動好感度系統,未驗證可行**;(丙)甲 + 第一次出現「關係不變」時給一句說明。我推薦丙。**這題直接影響你要的體驗題「看得懂為什麼嗎」。**
4. **確認前要不要先看到「會產生什麼強度的卡」?** 規格只要求寫入後才定強度。先預告更好懂,但等於告訴玩家「這個選擇換到多強的卡」,可能讓玩家變成算卡面而非選關係。我推薦先不顯示,只在結果層揭曉。
5. **騎牆「恢復」要預告嗎?** 規格只要求「失去」要預告。若某次質問讓關係回到冷淡、騎牆恢復,畫面目前只在結果層事後顯示。我推薦維持(只預告失去)。
6. **麥子健預告要不要加強阻擋?** 目前只是一行字,不另加二次確認。因為關心他的代價(失去減傷)是規格明說的「刻意取捨」。若你擔心玩家漏看,可改成要多按一次。我推薦維持一行字。
7. **同一組本輪能不能重複做?** 規格沒說。允許 = 可連續關心同一組把關係推高;不允許 = 每輪最多每組一次。**屬遊戲設計師的規則題,我只是要在畫面上有個答案。**
