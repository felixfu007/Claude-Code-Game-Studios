### 🔴 阻擋項 1:規格要求呼叫的那兩個函式,程式裡不存在

規格在**三個地方**要求開選單時呼叫「暫停游標裁定」、關閉時恢復
(Interaction Map ①、Data Requirements、**AC-M3 阻擋級**)。

**實測**:

```bash
grep -rn "^func suspend_arbitration\|^func resume_arbitration" src/   # 零命中
grep -rn "suspend_arbitration\|resume_arbitration" src/               # 5 命中,全在註解
```

五處命中分別在 `src/ui/cursor/cursor_state.gd`(2 處)與
`src/ui/cursor/cursor_state_host.gd`(3 處),**全部是文件註解,沒有一行是函式定義**。

**後果**:**AC-M3 今天不可能通過** —— 無法對一個不存在的介面斷言「裁定已暫停」。

🔴 **這與本專案 2026-09-10 誠實登記的限制 #2 是同一個形狀**
(`authoritative_write_in_progress` 在 `src/` 只是一句註解,故 AC-14 驗的是
「閘門有接」不是「旗標會變真」)。**差別在揭露**:

> 本規格的 Data Requirements **把另一個未實作的依賴標了「尚未實作」**
> (「打牌流程是否進行中」),**卻沒標這一個**。同一張表,兩個同樣不存在的依賴,
> 一個標了一個沒標。而 Open Questions 登記了 7 項未量測的事(BM-1~BM-7),
> **這一項不在其中。**

**修法**:在 Data Requirements 標記為尚未實作,並新增一列 Open Question 指名擁有者
(游標系統 #3 / ADR-0005 機制九)。**規則本身不必改** —— 它是對的,只是它的前提不存在。

### 🔴 阻擋項 2:游標會不會停在那個灰掉的項目上,沒說

管理者 2026-09-09 裁決:打牌流程進行中,「結束回合」**灰掉並說明原因**。
而 Interaction Map 的上下導覽那一列寫的是「**✅ 既有內建 `ui_*`**」。

**實測規格對此零規定**:

```bash
grep -n "跳過\|循環\|wrap\|繞回\|停留\|焦點順序" design/ux/battle-menu.md   # 零命中
```

**後果**:**若導覽跳過不可選項目,玩家永遠看不到那行原因文字。** 連帶三件事一起落空:

1. 管理者裁決的「說明原因」那一半
2. `P-F5` 要求的**第二個非色彩通道** —— 只剩「灰掉」這一個對比度通道,而
   `P-F3` 明文無例外
3. **AC-M4** 驗的正是「畫面上出現原因文字」,而它會驗不到

⚠️ **本項刻意不斷言引擎的預設行為。** 「灰掉的項目還能不能被選到」取決於節點的
`focus_mode` 與 `disabled` 如何設定,**而這在本專案從未量測過**。
本專案已為「憑記憶寫引擎行為」付過代價(18 處錯誤呼叫寫法),
故正確說法是:**規格把它交給了引擎預設,而那個預設沒人量過。**

### 🔴 阻擋項 3:上下導覽會不會繞回,沒說

同一次搜尋,同樣零命中。而本畫面的版面讓這件事有具體後果:

**預設焦點在第一列「回到遊戲」,而「離開遊戲」排在最後一列。**
→ **若導覽會繞回,按一下「↑」就直接停在「離開遊戲」上。**

🔴 **這與本規格的存在理由直接衝突。** 版面刻意把「離開遊戲」排到最下面、加一條明顯分隔線,
`P-M4` 明文「破壞性項目不得與高頻項目相鄰」。**繞回會讓這段刻意拉開的距離變成一個按鍵**
—— 而規格用了整整一節論證為什麼那一項必須離得遠、必須攔一道。

📌 **M4 的預設焦點在「取消」這道防線仍在**,所以最壞情況不是「按一下就關掉遊戲」,
而是「按一下就進到離開確認」。**但那正是本規格要防的誤觸的上游一步。**

### 🔴 阻擋項 4:這個選單到底有沒有把遊戲暫停,沒說

規格明文禁止用引擎的暫停機制**當作游標的裁定閘門**,並逐字引用登記表:

> `docs/registry/architecture.yaml` 的 `cursor_arbitration_suspension_gate`,
> `not:` 欄為 `"SceneTree.paused; process_mode as the arbitration gate"`

**這段引用是對的,登記表確實這樣寫,理由也充分**(游標 GDD 的 AC-60 自己用了
「一個不會讓 `SceneTree.paused` 變成 true 的未登記表面」當測試情境,
故以它當閘門等於建立在一個已知不完整的判斷上)。

**問題在另一件事:規格從未說本畫面自己會不會設 `SceneTree.paused`。**
實測 `grep -n "paused" design/ux/battle-menu.md` 三處命中**全部是禁令或引用**,
沒有一處是本畫面自身機制的宣告。而它引用的那份游標 GDD:

- **AC-59 的 WHEN 子句逐字寫著** `遊戲進入暫停選單/模態 UI(SceneTree.paused = true)`
- Edge Cases 的「具體讓路手段」**提議** `SceneTree.paused` 搭配 Autoload 的 `process_mode`

**亦即:同一個機制,登記表禁止它當閘門,而游標 GDD 拿它當讓路手段與驗收前提。**
規格同時引用兩邊,**卻沒說本畫面採哪一種**。

**後果(兩個方向都壞)**:

| 實作者的讀法 | 會發生什麼 |
|---|---|
| 「不能用暫停」→ 完全不設 `SceneTree.paused` | **游標 GDD 的 AC-59 情境在本專案唯一的暫停選單上永遠不成立** —— 該 AC 只會對測試替身通過。⚠️ 而 AC-60 自己的說明就記載過同形狀的教訓:兩條 AC 共用同一情境時,「登記制判準實質上從未被驗證」 |
| 「只是不能當閘門,暫停還是要做」→ 設 `SceneTree.paused = true` | 出現**兩套獨立的暫停機制**(引擎暫停 + 顯式旗標),而規格只要求後者成對呼叫。⚠️ 登記表的 SCOPE 另明文:旗標**只**閘門被動裁定路徑,`set_target()` / `mark_pending_reresolve()` **絕不得**檢查它 —— 這條約束沒有出現在本規格的資料表裡 |

**兩種讀法都完全符合本規格的字面。** 而這件事決定的是場景樹的 `process_mode` 設定,
**事後改動的代價遠高於現在寫一句話。**

### 建議項(6 項,皆不阻擋)

| # | 項目 | 說明 |
|---|---|---|
| **A1** | **檔頭缺 `Platform Target`,且沒有連結任何 GDD** | 輸入裝置寫在 Interaction Map 裡,資訊不缺、只是不在檔頭。**但「沒連結 GDD」有實質後果**:本畫面依賴三個系統(游標 #3、戰棋 #4、卡牌 #6),檔頭一個都沒列,**跨文件核對因此沒有宣告範圍**。<br>✅ **本輪代為查了一次,結果乾淨**:`grep -n "結束回合\|暫停\|選單" design/gdd/tactical-combat-system.md` **零命中** —— 沒有被違反的上游介面要求 |
| **A2** | **資料表缺「多久更新一次」與「查不到時顯示什麼」兩欄** | 檢查表對即時資料要求前者、對全部資料元素要求後者。與 `skill-card-play.md` 第一輪同一項 |
| **A3** | **「打牌流程是否進行中」的「尚未實作」已只對一半** | 卡牌系統已於 2026-09-10 完成(8 張工作單、554 條測試)。**但這個查詢確實還不存在**:`BattleController` 有 7 個打牌動作與 `has_pending_discard()`,**沒有「流程進行中嗎」的查詢**。<br>📌 **精確說法**:系統存在了,**這個畫面需要的那個查詢沒有**。擁有者 = 卡牌系統(#6),成本很低 |
| **A4** | **模式庫的雙向登記只做了一半** | 這份規格生出的兩個新模式**已經進庫**(`P-M4` 破壞性動作確認、`P-F5` 不可選項目,兩者的「來源」欄都指名本檔),**但本檔還指著舊的**:M3 那一列引用 `P-F3`,而 `P-F5` 就是為它而生的模式;M4 那一列寫「新模式」,而它已經在庫裡。<br>⚠️ 另:**三個選單列都標「新模式」但沒有編號、庫裡也沒有對應條目**,而模式庫自己的維護規則是「**先在此登記為新模式再實作**」。<br>📌 附帶觀察:模式庫的缺口表當天關閉三項,**其中兩項各鑄了一個編號(`P-M3`/`P-F4`),「暫停/模態選單」這一項是指向本檔關閉的** —— 故「選單列導覽」至今沒有模式 |
| **A5** | **沒有效能驗收條件** | 檢查表要求「畫面在 X 毫秒內開啟」。🔴 **值得注意的是配對的那份規格有**(`skill-card-play.md` 的 AC-U2:`≤ 200ms`)。**兩份是同批交付義務,一份有一份沒有** |
| **A6** | **載入中/空狀態未明文標示不適用** | 本畫面三個項目恆存在、全部讀取皆同步,兩種狀態確實不適用 —— **但規格沒說**,而檢查表要求兩者有著落。一句話即可 |

📌 **另有一項已有擁有者,故不計入建議項**:Standard 層級要求標明文字對比度,
而本檔全部視覺樣式已由 **BM-7** 登記給 `art-director`。**不是缺漏,是已分派。**
