## 1. 這份規格是什麼 / 不是什麼

**處理的機制**:`game-concept.md:446` 裁決的「預判標記」——玩家在移動棋子前,先標記
自己預期的效果方向(正/負/無),系統記錄標記與實際結算的一致率,作為新手測試驗收協議
(80% 門檻,暫定值)的量測工具;並依 `game-concept.md:248` 裁決升格為**正式玩家可選
功能**,不只是測量用的臨時介面。

### 🔴 命名衝突澄清(本規格刻意不沿用「預判模式」四字)

本專案「預判」一詞目前指兩個不同的東西,必須先分清楚:

| 名稱 | 出處 | 意思 |
|---|---|---|
| P-M2 預判模式 | `design/ux/interaction-patterns.md` | 游標停在候選格時,遊戲**主動顯示** what-if 預覽(現值→預覽值);離開候選格即消失,不寫入常駐 HUD |
| **效果猜測標記**(本規格,以下簡稱 EGM) | `game-concept.md:446` / `:248` | **玩家自己**標記他預期的效果方向,系統事後揭曉真實數值並記錄一致率 |

**本機制定名為「效果猜測標記」(Effect-Guess Marker,縮寫 EGM)**。UI 文案一律用
「猜測」而非「預判」,避免與 P-M2 混淆。EGM 開啟時,**取代**(非疊加)P-M2 原本在候選格
顯示的好感度預覽文字——兩者互斥於同一畫面位置,見第 2 節。

**不是什麼**:不重新設計 P-M2 本身、不重新設計好感度數值的計算方式(沿用既有
`AffinityRules.bonus_for()` / `bonus_for_at()`)、不處理存檔系統(見第 7 節)。

## 2. 「先下注再揭曉」完整流程(2026-10-16 管理者裁決的實作化;一格一次規則見步驟 5)

前提:玩家已在選項/輔助設定選單開啟 EGM 模式。🔴 **2026-10-16 管理者裁決(結案)**:
EGM 模式**不支援戰鬥中途熱切換**——整場戰鬥開始前就固定,開戰後開關鎖定為唯讀
(見 AC13)。

逐步:

1. 玩家選取棋子、進入移動模式(既有行為,不變)——**此刻開啟一次新的「移動選取
   過程」**,本枚棋子這次選取過程中,所有候選格的 EGM 猜測狀態重置為「尚未猜測」。
2. 游標依現有輸入方式(鍵盤方向鍵/滑鼠懸停/手把 d-pad 或類比搖桿)在候選格間移動
   (既有行為,不變)。
3. 游標停在候選格時,依該格在本次選取過程中是否已被猜測過,分兩種情況:
   - 🔴 **尚未猜測過**:原本的好感度預覽文字(`battle.hud.affinity_preview_format`)
     暫時隱藏,改為顯示「猜測選擇器」(正/負/無三選項,可互動,見第 4 節)。
   - **已經猜測過**(含曾經移出又移回):直接顯示該格當初的猜測與「符合/不符合」
     結果(唯讀),**不**重新隱藏好感度預覽、**不**提供可互動的選擇器(見步驟 5)。
     🔴 **2026-10-28 管理者裁決**:「尚未猜測過」狀態下,棋盤上隨游標變化的**好感度關係線
     預覽也一併維持現況**(不畫假設位置的線)—— 線色會洩漏 delta 的正負,等於把答案畫在
     棋盤上。揭曉(步驟 4)或跳過(步驟 6)後才畫。EGM 關閉時不受影響。
     逐字選項:「接受,猜前連線也不變(推薦)」;被跳過:「照規格字面,只藏數字」。
     (由 story-002 實作者交件時提出;實作見 `battle_screen.gd` 的 `GuessCellState.PENDING` 分支。)
4. 🔴 玩家對一個尚未猜測過的候選格做出**第一次標記** → **同一瞬間觸發兩件事**:
   a) 被隱藏的好感度預覽文字立即顯示(現值→預覽值),並同步顯示「符合/不符合」回饋
      (圖形+文字,不得只靠顏色,見 AC10)。
   b) **該格的猜測在本次選取過程中永久鎖定為唯讀**,直到本次選取過程結束(確認
      移動或取消選取)。
   這是防灌水的核心:**一旦真實數值被揭曉,該格這次選取過程的猜測就不可能再被改成
   「更對」的值**(見 AC8)。
5. 🔴 **「一格一次」**(2026-10-16 協調者提案,採用):每格在同一次選取過程中只接受
   一次猜測。移出已鎖定的格子再移回 → 不解鎖、不接受第二次猜測(回到步驟 3「已猜測
   過」分支)。要重新取得「可以猜」的狀態,須**取消本次移動選取、重新選取同一棋子**
   (既有操作,免新增輸入)——開啟全新選取過程,所有候選格的鎖定猜測一併重置。
   ⚠️ **刻意保留的殘餘路徑**:「移出移回」這條近乎免費的記憶作弊路徑已被擋住;
   「取消重選」仍是更高成本但依然存在的路徑,其成本已足以嚇阻隨手作弊,且正是誤觸
   的合理救濟,**刻意保留,不視為待修缺陷**。
6. 🔴 **跳過**(2026-10-16 管理者裁決:標記可跳過,不強制):若玩家在步驟 3「尚未
   猜測過」狀態下,未操作猜測選擇器就直接送出移動確認(既有 `battle_confirm`)→
   視為「跳過」。跳過時,好感度預覽**比照 EGM 關閉時的行為立即顯示**——本規格判斷:
   繼續隱藏等於懲罰玩家「不想猜」這個正當選擇,會讓跳過比直接關掉整個 EGM 模式還差,
   違背把跳過設計成低成本退路的本意(見 AC12)。
7. **計分規則**:一筆記錄要計入一致率統計,須同時滿足 (i) 該格已鎖定猜測(非跳過)
   且 (ii) 玩家對該格送出移動確認;只滿足其中之一(鎖定後移到別格確認、或跳過後
   確認)都不計入分母與分子(見 AC7)。

**EGM 關閉時**:行為與現狀完全相同——好感度預覽文字立即顯示,無選擇器、不記錄一致率。

## 3. 「正/負/無」判定定義(可程式判定)

沿用既有好感度預覽的兩個整數(`battle_screen.gd:3500-3504`:`AffinityRules.bonus_for()`
取得 `current`,`AffinityRules.bonus_for_at()` 取得 `preview`):

```
delta = preview - current
正效果 (POSITIVE) ⟺ delta > 0
負效果 (NEGATIVE) ⟺ delta < 0
無效果 (NEUTRAL)  ⟺ delta == 0
```

**比對**:`guess == 實際分類` 為「符合」,否則為「不符合」。此為純函式(輸入 `delta: int`,
輸出三態 enum),可直接單元測試(見 AC5)。

🔴 **2026-10-16 管理者裁決(結案):判定範圍限定於好感度,不做可擴充設計。**
EGM 判定只對應好感度預覽的 `delta`,不預留其他效果類型欄位;未來若有其他效果預覽
(如戰鬥傷害)要不要涵蓋,屬於全新規格與裁決,不是本規格的延伸——範圍收斂非疏漏。

## 4. 輸入映射(鍵盤/滑鼠/手把平權)

### 🔴 已核對:實際輸入綁定(2026-10-16,`Grep` 直讀 `project.godot` 的 `[input]` 節)

專案目前僅有以下 8 個自訂輸入動作(逐一核對,非轉述):`battle_confirm`=Enter/
KP Enter/Space,手把鈕 0;`battle_end_phase`=無綁定;`battle_cancel`=Esc,手把鈕 1;
`battle_open_hand`=C,手把鈕 2;`battle_next_target`=Tab,手把鈕 10;
`battle_prev_target`=Shift+Tab,手把鈕 9;`battle_menu`=M,手把鈕 6;
`battle_end_unit_turn`=Q,手把鈕 4。

**上一版建議的 `Tab`/`Q`/手把鈕 9/10 全部與既有綁定衝突,已撤回。**

### 設計選擇:不共用 `battle_next_target`/`battle_prev_target`,新增獨立動作

這兩個動作語意上就是「在一組選項間循環」,技術上可以借用(攻擊目標情境與移動候選格
猜測情境不會同時出現)。**但本規格判斷不共用**:`interaction-patterns.md` 的 P-M2
已明文警告過同一手法的風險——同一顆鍵在不同情境做不同事,玩家會把舊情境學到的意義
當成事實帶進新情境,而本機制鎖定的受眾正是**首次接觸本作核心機制的新手測試者**,
心智模型最脆弱。為省一個綁定而讓最容易混淆的那群人混淆,不划算。

**新增獨立動作 `battle_guess_cycle`**(循環正→負→無→正…),確認沿用既有
`battle_confirm`,不新增確認鍵。鍵盤建議 `X`(未被上表任何動作佔用,已核對);
滑鼠為點擊選擇器左右箭頭圖示或滾輪(不佔用 `[input]` 動作);手把建議未被佔用的
按鈕序號 3(序號未衝突,但對應哪顆實體按鈕未驗證,見第 7 節第 6 項)。

**跳過**(第 2 節步驟 6):選擇器仍為初始狀態時直接按 `battle_confirm` 即可,不需要
額外的「跳過」鍵,三種裝置自動平權。

**平權**:三種裝置皆能在不碰滑鼠的情況下完成「循環到想要的選項 + 確認」,符合
「所有 UI 必須同時支援滑鼠與 d-pad/類比搖桿,不得有只能用滑鼠的互動」的硬性要求。

## 5. 一致率記錄與呈現

**記錄粒度**:每一筆「已鎖定猜測 + 已確認移動的格子」記 `(guess, actual_category, match: bool)`。

**呈現**:EGM 開啟時,HUD 疊加小型計數器(例如「猜中 6/8」),位置疊在棋盤上方角落、
可收合,不佔用側邊固定欄位;字級依 `src/ui/battle/world_layout.gd` 的
`compute_scale()` 取得的倍率 `N` 換算,不自行計算公式。

🔴 **2026-10-16 管理者裁決(結案):不持久化,只留記憶體,關閉遊戲即歸零。**
**本規格不得碰存檔系統**——理由(轉述自派工):存檔系統已降級為垂直切片階段、程式
尚未落筆,不該為此量測工具牽動它。統計變數生命週期與單次執行期間相同,**不得**出現
在存檔讀寫路徑或新增存檔欄位(見 AC14)。跨「前 2-3 場戰鬥」的累積僅於不關遊戲的
單次執行期間內有效;中途關閉則測試視窗歸零——這是裁決接受的代價,非本規格缺陷。

## 6. 驗收條件(可測)

- **AC1(迴歸安全)**:給定 EGM 關閉、游標停在候選格 → 應看到好感度預覽文字立即顯示,
  不出現猜測選擇器,行為與現狀逐字相同。
- **AC2(選擇器出現)**:給定 EGM 開啟、游標停在候選格 → 好感度預覽文字應被隱藏,
  猜測選擇器(正/負/無)取而代之顯示在同一區域。
- **AC3(輸入平權)**:給定選擇器已顯示 → 分別以鍵盤(`battle_guess_cycle`+
  `battle_confirm`)、滑鼠點擊、手把(`battle_guess_cycle`+`battle_confirm`)三種
  模擬輸入 → 三者皆應能獨立完成一次完整標記,不得有任一裝置無法完成。
- **AC4(揭曉與鎖定同時發生)**:給定玩家在某候選格做出第一次標記 → 應立即看到
  (a)好感度預覽文字顯示真實數值(現值→預覽值),且同時(b)該格的猜測在本次選取
  過程中永久鎖定為唯讀;真實數值不得早於標記完成就出現。
- **AC5(判定純函式)**:給定 `delta=+3` → 應回傳 POSITIVE;`delta=-2` → 應回傳
  NEGATIVE;`delta=0` → 應回傳 NEUTRAL。無副作用純函式,可覆蓋三分支。
- **AC6(一格一次 —— 鎖定後不因移出移回而重新開放)**:給定玩家在格 A 完成第一次
  標記並已進入鎖定狀態 → 玩家將遊標移出格 A 再移回格 A(未取消本次選取)→ 格 A
  應仍顯示原本的鎖定猜測與符合/不符合結果,**不得**出現新的可互動選擇器、**不得**
  重新隱藏好感度預覽;只有當玩家取消本次移動選取並重新選取同一枚棋子,格 A 才
  重新回到「未猜測」狀態。
- **AC7(只有「已鎖定猜測 + 已確認移動」才計分)**:
  (a) 給定玩家在格 A 完成鎖定標記後,對格 B(而非 A)送出移動確認 → 格 A 的鎖定
      猜測不計入一致率統計的分母與分子。
  (b) 給定玩家對格 A 送出移動確認,但格 A 從未被標記過(跳過)→ 格 A 同樣不計入
      一致率統計的分母與分子。
  共同規則:一筆記錄要計入統計,必須同時滿足「該格已鎖定猜測」與「玩家對該格送出
  移動確認」,缺一都不計入。
- 🔴 **AC8(不可灌水 —— 本規格最重要的驗收條件)**:(a) 給定玩家在格 A 標記「正」、
  系統隨即揭曉實際為「負」(鎖定)→ 在未取消本次選取下無法改猜;對格 A 送出移動
  確認,記錄應為「不符合」,不得因看到答案而變「符合」。(b) 給定上述情形已揭曉 →
  玩家移出格 A 再移回(未取消選取)→ 格 A 仍顯示原猜測與「不符合」,不得出現新的
  選擇器;此時確認移動,記錄仍為「不符合」。此條與 AC4/AC6/AC7 共同成立,缺一則
  一致率可被灌水到恆為 100%。⚠️ 「取消選取重新選取」仍可取得新猜測機會(第 2 節
  步驟 5)——刻意保留的誤觸救濟,非本條要擋的對象。
- **AC9(一致率計算)**:給定 N 筆已確認記錄、其中 M 筆 `match=true` → 呈現值應等於
  `M/N`(供新手測試驗收協議 80% 門檻判定使用)。
- **AC10(非純色區分)**:給定一筆「不符合」結果 → 除顏色外必須同時存在可判讀的圖形或
  文字差異(例如 ✓/「符合」、✕/「不符合」),不得僅以顏色區分。
- **AC11(本地化)**:給定選擇器與一致率呈現的所有玩家可見文字 → 應全部透過
  `assets/data/locales/strings.csv` 的鍵取得,原始碼中不得出現寫死的中文字面值。
- **AC12(跳過不隱藏資訊)**:給定玩家在候選格未操作選擇器就送出移動確認(跳過)
  → 好感度預覽應比照 EGM 關閉時的行為立即顯示,不得因跳過而繼續隱藏。
- **AC13(整場戰鬥固定,不可中途熱切換)**:給定玩家在戰鬥中打開選項選單 → EGM
  開關應顯示目前值但**不可互動變更**;變更只在下一場戰鬥開始時生效。
- **AC14(不持久化)**:給定玩家關閉遊戲並重新啟動 → 一致率統計應重置為 0/0;存檔
  讀寫路徑(序列化/反序列化程式碼)**不得**參照任何 EGM 統計變數。
