# 戰鬥 HUD 預判標記 —— 輕量規格

> 文件類型:`design/quick-specs/` 輕量規格,依 `design/gdd/systems-index.md`
> 2026-09-07 管理者裁決 ——「是把已經存在的數字畫出來,弄錯了重畫就好」,
> 不適用 GDD 8 節格式與兩輪 `/design-review`,**但驗收標準不豁免**。
> 狀態:草案。待裁決項見第 7 節「開放問題」,未裁決前不得視為可直接實作的定案。

## 1. 這份規格是什麼 / 不是什麼

**處理的機制**:`game-concept.md:446` 裁決的「預判標記」——玩家在移動棋子前,先標記
自己預期的效果方向(正/負/無),系統記錄標記與實際結算的一致率,作為新手測試驗收協議
(80% 門檻,暫定值)的量測工具;並依 `game-concept.md:248` 裁決升格為**正式玩家可選
功能**,不只是測量用的臨時介面。

### 🔴 命名衝突澄清(本規格刻意不沿用「預判模式」四字)

本專案「預判」一詞目前指兩個不同的東西,必須先分清楚:

| 名稱 | 出處 | 意思 |
|---|---|---|
| P-M2 預判模式 | `design/ux/interaction-patterns.md` | 游標停在候選格時,遊戲**主動顯示** what-if 預覽(現值→預覽值);離開候選格即消失,不寫入常駐 HUD |
| **效果猜測標記**(本規格,以下簡稱 EGM) | `game-concept.md:446` / `:248` | **玩家自己**標記他預期的效果方向,系統事後揭曉真實數值並記錄一致率 |

**本機制定名為「效果猜測標記」(Effect-Guess Marker,縮寫 EGM)**。UI 文案一律用
「猜測」而非「預判」,避免與 P-M2 混淆。EGM 開啟時,**取代**(非疊加)P-M2 原本在候選格
顯示的好感度預覽文字——兩者互斥於同一畫面位置,見第 2 節。

**不是什麼**:不重新設計 P-M2 本身、不重新設計好感度數值的計算方式(沿用既有
`AffinityRules.bonus_for()` / `bonus_for_at()`)、不處理存檔系統(見第 7 節)。

## 2. 「先下注再揭曉」完整流程(2026-10-16 管理者裁決的實作化;一格一次規則見步驟 5)

前提:玩家已在選項/輔助設定選單開啟 EGM 模式。(EGM 模式是否支援戰鬥中途熱切換——
本規格的建議與理由移至第 7 節開放問題 5,待管理者確認,不在此假設為定案。)

逐步:

1. 玩家選取棋子、進入移動模式(既有行為,不變)——**此刻開啟一次新的「移動選取
   過程」**,本枚棋子這次選取過程中,所有候選格的 EGM 猜測狀態重置為「尚未猜測」。
2. 游標依現有輸入方式(鍵盤方向鍵/滑鼠懸停/手把 d-pad 或類比搖桿)在候選格間移動
   (既有行為,不變)。
3. 游標停在候選格時,依該格在本次選取過程中是否已被猜測過,分兩種情況:
   - 🔴 **尚未猜測過**:原本的好感度預覽文字(`battle.hud.affinity_preview_format`)
     暫時隱藏,改為顯示「猜測選擇器」(正/負/無三選項,可互動,見第 4 節)。
   - **已經猜測過**(含曾經移出又移回):直接顯示該格當初的猜測與「符合/不符合」
     結果(唯讀),**不**重新隱藏好感度預覽、**不**提供可互動的選擇器(見步驟 5)。
4. 🔴 玩家對一個尚未猜測過的候選格做出**第一次標記** → **同一瞬間觸發兩件事**:
   a) 被隱藏的好感度預覽文字立即顯示(現值→預覽值),並同步顯示「符合/不符合」回饋
      (圖形+文字,不得只靠顏色,見 AC10)。
   b) **該格的猜測在本次選取過程中永久鎖定為唯讀**,直到本次選取過程結束(確認
      移動或取消選取)。
   這是防灌水的核心:**一旦真實數值被揭曉,該格這次選取過程的猜測就不可能再被改成
   「更對」的值**(見 AC8)。
5. 🔴 **「一格一次」**(2026-10-16 協調者提案,採用):每一格在同一次選取過程中只
   接受一次猜測。玩家移出已鎖定的格子、再移回 → 不重新解鎖、不接受第二次猜測
   (回到步驟 3「已猜測過」分支)。要重新取得「可以猜」的狀態,玩家必須**取消本次
   移動選取、重新選取同一枚棋子**(既有操作,不需新增輸入綁定)——這會開啟全新的
   選取過程,本枚棋子所有候選格的鎖定猜測一併重置。
   ⚠️ **刻意保留的殘餘路徑**:「移出再移回」這條近乎免費的記憶作弊路徑已被結構性
   擋住;「取消選取、重新選取同一棋子」仍是一條更高成本、但依然存在的路徑。本規格
   判斷它的成本已足以嚇阻隨手作弊,且它正是誤觸的合理救濟手段,**刻意保留,不視為
   待修缺陷**。
6. 玩家對目前這一格送出移動確認(既有 P-M1 流程,P-M1 本身不變)——**只有此時**該格
   「本次選取過程中鎖定的那個猜測」才正式計入一致率統計分母。
7. 未被確認移動的猜測一律不計分——玩家在格 A 鎖定標記後,對格 B(而非 A)送出移動
   確認,格 A 的鎖定猜測不計入統計(避免跨格灌水)。

**EGM 關閉時**:行為與現狀完全相同——好感度預覽文字立即顯示,無選擇器、不記錄一致率。

## 3. 「正/負/無」判定定義(可程式判定)

沿用既有好感度預覽的兩個整數(`battle_screen.gd:3500-3504`:`AffinityRules.bonus_for()`
取得 `current`,`AffinityRules.bonus_for_at()` 取得 `preview`):

```
delta = preview - current
正效果 (POSITIVE) ⟺ delta > 0
負效果 (NEGATIVE) ⟺ delta < 0
無效果 (NEUTRAL)  ⟺ delta == 0
```

**比對**:`guess == 實際分類` 為「符合」,否則為「不符合」。此為純函式(輸入 `delta: int`,
輸出三態 enum),可直接單元測試(見 AC5)。

🔴 **範圍限定,列為開放問題**:目前畫面上唯一的數值化效果預覽是好感度。未來若出現其他
效果預覽(例如戰鬥傷害預覽),EGM 判定要不要涵蓋,見第 7 節。

## 4. 輸入映射(鍵盤/滑鼠/手把平權)

**設計選擇:三態循環選擇器,而非三個各自獨立的按鍵。**

理由:三個選項各自綁一顆實體鍵/鈕,在三種裝置上要各自找三個不衝突的輸入點,且
Fitts's Law 上三顆分散按鍵在手把搖桿的可達性不易做到對等。改用**單一「循環」動作
+ 既有「確認」動作**:

| 裝置 | 循環(正→負→無→正…) | 確認標記 |
|---|---|---|
| 鍵盤 | 一個循環鍵(建議 `Tab` 或 `Q`/`E`,待核對) | 既有「確認」鍵 |
| 滑鼠 | 點擊選擇器左右箭頭圖示,或滾輪 | 左鍵點擊中央選項區 / 既有「確認」鍵 |
| 手把 | 肩鍵(`L1`/`R1` 類) | 既有「確認」鈕 |

**平權**:三種裝置皆能在不碰滑鼠的情況下完成「循環到想要的選項 + 確認」,符合
「所有 UI 必須同時支援滑鼠與 d-pad/類比搖桿,不得有只能用滑鼠的互動」的硬性要求。

⚠️ **未驗證**:上表鍵盤/手把按鍵代號為依慣例建議,**未對照專案既有輸入映射表
(control manifest)核對是否衝突**,送實作前必須核對(見第 7 節)。

## 5. 一致率記錄與呈現

**記錄粒度**:每一筆「已確認移動的格子的最終猜測」記 `(guess, actual_category, match: bool)`。

**呈現**:EGM 開啟時,HUD 疊加小型計數器(例如「猜中 6/8」),位置疊在棋盤上方角落、
可收合,不佔用側邊固定欄位;字級依 `src/ui/battle/world_layout.gd` 的
`compute_scale()` 取得的倍率 `N` 換算,不自行計算公式。

🔴 **開放問題(牽涉存檔系統,本規格不自行決定)**:驗收協議要求「新手測試者在教學關卡後
前 2-3 場戰鬥一致率達 80%」,代表統計至少要**跨戰鬥**保留。跨戰鬥是否等於**跨 session
存檔**(需經 ADR-0003/0004 序列化契約),或僅限**單次執行期間的記憶體內統計**(關閉
遊戲即歸零)?兩者代價差異大,**交回存檔系統擁有者與 `analytics-engineer` 裁決。**

## 6. 驗收條件(可測)

- **AC1(迴歸安全)**:給定 EGM 關閉、游標停在候選格 → 應看到好感度預覽文字立即顯示,
  不出現猜測選擇器,行為與現狀逐字相同。
- **AC2(選擇器出現)**:給定 EGM 開啟、游標停在候選格 → 好感度預覽文字應被隱藏,
  猜測選擇器(正/負/無)取而代之顯示在同一區域。
- **AC3(輸入平權)**:給定選擇器已顯示 → 分別以鍵盤循環+確認、滑鼠點擊、手把肩鍵+
  確認鈕三種模擬輸入 → 三者皆應能獨立完成一次完整標記,不得有任一裝置無法完成。
- **AC4(揭曉與鎖定同時發生)**:給定玩家在某候選格做出第一次標記 → 應立即看到
  (a)好感度預覽文字顯示真實數值(現值→預覽值),且同時(b)該格的猜測在本次選取
  過程中永久鎖定為唯讀;真實數值不得早於標記完成就出現。
- **AC5(判定純函式)**:給定 `delta=+3` → 應回傳 POSITIVE;`delta=-2` → 應回傳
  NEGATIVE;`delta=0` → 應回傳 NEUTRAL。無副作用純函式,可覆蓋三分支。
- **AC6(一格一次 —— 鎖定後不因移出移回而重新開放)**:給定玩家在格 A 完成第一次
  標記並已進入鎖定狀態 → 玩家將遊標移出格 A 再移回格 A(未取消本次選取)→ 格 A
  應仍顯示原本的鎖定猜測與符合/不符合結果,**不得**出現新的可互動選擇器、**不得**
  重新隱藏好感度預覽;只有當玩家取消本次移動選取並重新選取同一枚棋子,格 A 才
  重新回到「未猜測」狀態。
- **AC7(未確認不計分)**:給定玩家在格 A 完成鎖定標記後,對格 B(而非 A)送出移動
  確認 → 格 A 的鎖定猜測不計入一致率統計的分母與分子。
- 🔴 **AC8(不可灌水 —— 本規格最重要的驗收條件)**:
  (a) 給定玩家在格 A 標記「正」、系統隨即揭曉實際為「負」(鎖定)→ 玩家在**未取消
      本次選取**的情況下,無法將猜測改為「負」;若對格 A 送出移動確認,該筆記錄
      應為「不符合」,**不得因為看到答案而變成「符合」**。
  (b) 給定玩家在格 A 做出上述錯誤猜測並已揭曉 → 玩家將遊標**移出格 A 再移回格 A**
      (未取消本次選取)→ 格 A 仍應顯示原本的猜測與「不符合」,**不得**出現新的
      猜測選擇器;此時若對格 A 送出移動確認,記錄仍應為「不符合」。
  此條與 AC4/AC6/AC7 共同成立,缺一則一致率統計可被「先隨便猜、看答案、改成對的」
  (不論同一次選取內覆寫,或移出再移回)灌水到恆為 100%。
  ⚠️ 玩家仍可透過「取消本次選取、重新選取同一棋子」取得全新猜測機會(見第 2 節
  步驟 5)——這是刻意保留的誤觸救濟,不是本條要擋的對象;本條只擋「不取消選取」
  就能達成的灌水路徑。
- **AC9(一致率計算)**:給定 N 筆已確認記錄、其中 M 筆 `match=true` → 呈現值應等於
  `M/N`(供新手測試驗收協議 80% 門檻判定使用)。
- **AC10(非純色區分)**:給定一筆「不符合」結果 → 除顏色外必須同時存在可判讀的圖形或
  文字差異(例如 ✓/「符合」、✕/「不符合」),不得僅以顏色區分。
- **AC11(本地化)**:給定選擇器與一致率呈現的所有玩家可見文字 → 應全部透過
  `assets/data/locales/strings.csv` 的鍵取得,原始碼中不得出現寫死的中文字面值。

## 7. 開放問題清單(交回裁決,本規格未自行決定)

1. **一致率統計是否跨 session 存檔**(第 5 節)——牽涉存檔系統契約,需存檔系統擁有者
   與 `analytics-engineer` 共同裁決。
2. **判定範圍是否僅限好感度預覽**(第 3 節)——未來出現其他效果預覽(如戰鬥傷害)時,
   EGM 判定要不要涵蓋,需 `game-designer` 裁決。
3. **鍵盤/手把具體按鍵代號未核對**(第 4 節)——需對照既有輸入映射表(control manifest)
   確認無衝突,目前為未驗證的建議值。
4. **標記是否強制**——本規格假設「游標停在候選格就必須標記才能繼續移動」,未定義
   「跳過/不猜測」路徑,也未定義跳過是否影響統計分母。是否需要此路徑、以及它是否符合
   驗收協議的新手測試量測意圖,需 `game-designer` 確認。
5. **EGM 模式是否支援戰鬥中途熱切換**——本規格原在第 2 節內文直接假設「不支援,只在
   每場戰鬥開始前生效」(理由:避免同一場內一致率統計資料半套)。這會影響玩家能不能
   在一場仗進行到一半時關掉/開啟此模式,不純屬 UX 範疇,故移到此處,標為**本規格的
   建議,待管理者確認**,而非定案。
