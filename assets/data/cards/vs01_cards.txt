# vs01 技能卡牌表(好感度對話卡牌)— 固定欄位順序:
# id,category,delta_atk,delta_def,duration_rounds,affinity_character_a,affinity_character_b,affinity_magnitude,named_unit_id,named_mode
#
# 本檔是「先求能驗證流程,不求最終平衡」的第一批可用卡(2026-09-15 管理者裁決:
# 「先出一小批可用的牌,讓畫面跑得起來」)。數值皆為起始值,之後可隨時改動,
# 不代表最終平衡結果。
#
# 🔴 本檔只管機制數值,不含牌面顯示文字。顯示文字另在
# assets/data/cards/vs01_card_text.txt,以同一個 id 對應——2026-09-15 管理者
# 裁決分離,理由見該檔檔頭。本檔每一列新增/刪除都必須同步那張表的對應列。
#
# ── 欄位定義,逐一對應 src/gameplay/cards/card.gd 的實際欄位 ──────────────
#
# id                      Card.id(String)。本表內任選,不得重複,尚未綁定任何正式
#                         卡表格式(design/gdd/skill-card-system.md OQ-6 仍未定案)。
#
# category                Card.Category 的字面字串,必須逐字等於下列兩者之一
#                         (對應 card.gd 的 enum 名稱):
#                           TEMPORARY_STAT_MODIFIER   = 甲類(暫時性戰鬥數值)
#                           PERMANENT_AFFINITY_WRITE  = 丙類(永久好感度寫入)
#                         乙類(暫時性關係極性覆蓋)不在本表 —— GDD 定案 MVP 不實作。
#
# delta_atk / delta_def   甲類專用,對應 Card.delta_atk / Card.delta_def。帶號整數。
#                         單卡 |Δ| 落在 1~3(design/quick-specs/unit-stats-provisional.md
#                         §7-4 尺度錨點:上限 = Φ 單線最強貢獻 +3)。
#                         這裡的 0 代表「這張牌不動這個軸」(例:純 ATK 卡的
#                         delta_def=0),是合法的正常值,不是任何 sentinel。
#                         丙類卡此兩欄一律填 0(card.gd 該情況下的預設值;card.gd
#                         doc comment 明文:非本類別的欄位群「must be ignored by
#                         readers」)。
#
# duration_rounds         甲類專用,對應 Card.duration_rounds,r ∈ {1,2}
#                         (GDD 公式二)。丙類卡填 0(丙類沒有存續狀態,
#                         「single fire-and-forget write」,card.gd 類別文件註明)。
#
# affinity_character_a/b  丙類專用,對應 Card.affinity_character_a /
#                         affinity_character_b。與 vs01_affinity_links.txt 同一套
#                         id(1=甲 2=乙 3=丙 4=丁 5=戊)。
#                         🔴 2026-09-10 管理者裁決後,這兩欄「僅供牌面敘事」——
#                         機制上實際作用的配對由玩家在棋盤上兩步選定(S2p/S2q),
#                         PermanentAffinityWriteRules.play() 不讀這兩欄
#                         (見 card.gd 這兩個欄位各自的 doc comment、
#                         design/gdd/skill-card-system.md 一之三、
#                         design/ux/skill-card-play.md「確認面板欄位」節)。
#                         甲類卡此兩欄一律填 -1(card.gd 明文的 unset sentinel)。
#
# affinity_magnitude      丙類專用,對應 Card.affinity_magnitude,GDD 公式三的
#                         m。值域固定為 {-3,-2,-1,1,2,3},絕不可為 0——0 會在
#                         寫入埠被拒絕並拋驗證錯誤(GDD AC-9)。
#                         甲類卡此欄填 0,這是 card.gd 明文的 unset sentinel。
#                         ⚠️ 注意這是兩件不同的事:0 在甲類卡是合法的「未使用」,
#                         在丙類卡是被拒絕的非法值 —— 不要把兩者混為一談。
#
# named_unit_id           【選填第 9 欄】甲類專用,對應 Card.named_unit_id(story-009,
#                         管理者 2026-11-03 裁決「限定只能給點名者」)。牌面點名的我方
#                         單位 id(1=甲 2=乙 3=丙 4=丁 5=戊),這張牌只能打在該單位身上;
#                         該單位陣亡或不在本場 → 這張牌打不出(廢牌,管理者知情選擇)。
#                         -1 = 不限定(丙類一律填 -1)。省略此欄 = 不限定。
#
# named_mode              【選填第 10 欄】字面字串 ONLY 或 EXCLUDE(其他字串 → 整張表
#                         載入失敗)。ONLY = 只能打給 named_unit_id(牌面點名者是承受者,
#                         例:「丙壓低身形」)。EXCLUDE = 只能打給「存活我方減去點名者」
#                         (牌面點名者是出手鼓勵的人,承受者是隊友,例:「乙在耳邊喊了聲
#                         我挺你」;管理者 2026-11-03 裁決「給乙以外的任何人」)。
#                         省略此欄 = ONLY。丙類填 ONLY(無作用)。
#
# ── 丙類的合法配對(2026-09-15 撰寫時逐一查證) ─────────────────────────
# 只有 vs01_affinity_links.txt 已登記的兩對是合法的:(1,2) 甲乙、(3,4) 丙丁。
# 戊(5)沒有任何關係線,任何以 5 為 affinity_character_a/b 的丙類卡都無法通過
# 寫入埠驗證(design/gdd/skill-card-system.md AC-8a/AC-8c)——本表沒有這樣的卡。
#
# ── 本批的設計裁量(供之後檢視,非機制規則) ─────────────────────────────
# 兩張丙類卡的 magnitude 方向刻意與 vs01_affinity_links.txt 的既有 polarity 同向
# (甲乙用正值、丙丁用負值)。這是刻意迴避,不是驗證過安全——「丙類不得翻轉任何
# 角色設定的正負號」這條界線在「往相反方向寫」時會不會被拒絕、拒絕的判準是什麼,
# 目前沒有任何驗收條件可查證。已登記為已知缺口,見
# design/gdd/skill-card-system.md Core Rules 一之三界線 1(2026-09-15 補述)。
#
