#
# ── 這張表為什麼獨立於 vs01_cards.txt 存在(2026-09-15 管理者裁決) ──────────
#
# 本檔原本是 vs01_cards.txt 的第 9 欄(flavor_text),2026-09-15 管理者裁決分離:
# 	1. card.gd 的 Card 類別沒有任何欄位儲存牌面顯示文字 —— 數值欄位(delta_atk、
# 	   duration_rounds、affinity_magnitude…)全部對應 Card 的實際欄位,而顯示文字
# 	   從來就不是 Card 要管的事。混在同一張表,會讓人誤以為 flavor_text 也是
# 	   Card 的欄位。
# 	2. design/ux/skill-card-play.md 的 Localization Considerations 節已經指出:
# 	   中文翻成其他語言常膨脹 2~3 倍字元數,卡面正文是本介面最緊的版面
# 	   (該檔明文列為 HIGH 風險)。數值與文字分離,將來要換字級、排版、或加翻譯,
# 	   只需要動這一張表,不必碰任何會影響機制的欄位。
# 	3. 「不動已提交的資料」——本檔獨立以後,日後修牌面用詞不需要重新提交
# 	   vs01_cards.txt,兩者的修改歷史各自乾淨。
#
# 🔴 不要因為看起來像多此一舉就把它併回 vs01_cards.txt —— 以上三點是分離的理由,
# 不是隨手拆分。
#
# ── 欄位定義 ──────────────────────────────────────────────────────
#
# id           對應 vs01_cards.txt 同一欄的 Card.id,兩表以此欄位對應同一張卡。
#              本檔沒有任何一列可以脫離 vs01_cards.txt 存在 —— 若 vs01_cards.txt
#              新增或刪除一張卡,本檔須同步新增或刪除對應列。
# flavor_text  卡面顯示文字(繁體中文)。角色以代號表示(1=甲…5=戊,同
#              vs01_roster.txt 的 code_name 欄),正式姓名對照見
#              design/narrative/characters.md 第一節 —— 該檔第八節已裁決
#              「這一批不做」姓名欄位,本檔沿用同一裁決,不在此提前對應真名。
#              ⚠️ 內容避免使用逗號(改用「、」或破折號),本表沿用專案既有簡單
#              CSV 慣例,沒有引號跳脫機制。
#
# ── 兩份資料在哪裡會合(解析端的建議介面,非本檔決定) ────────────────────
#
# 建議由呼叫端(可能是 CardDeck,或載入階段的某個 loader)分別解析兩張表,
# 各自產生 id → 資料 的對照(Card 物件的字典 + flavor_text 的字典),再以 id
# 為鍵各自查找 —— 不建議在解析時就把 flavor_text 塞進 Card 物件本身(那樣
# 會回到「Card 該不該有顯示文字欄位」這個已經裁決分離的問題,且 Card 目前的
# 類別文件明文自稱是 pure data holder,只管機制數值)。
# 顯示層(手牌介面、確認面板)在需要呈現牌面文字時,用同一個 id 分別查
# 「這張卡的機制資料」與「這張卡的顯示文字」,兩者各自更新互不影響。
# 這個建議還沒有實作,詳見 vs01_cards.txt 檔頭與本次報告「兩份資料在哪裡會合」一節。
#
